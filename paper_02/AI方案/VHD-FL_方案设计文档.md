# VHD-FL：无人机簇结构的可验证 DKG 层次联邦学习

> **完整方案设计文档**（独立成文，自包含）
> 全称：Verifiable Hierarchical DKG-based Federated Learning for UAV Swarms
> 定位：在「终端 UAV（弱）→ 簇头 UAV（强）→ 云服务器」三层簇结构内，一次性统一 **外包加密 + DKG + 签名认证 + 同态哈希验证 + 抗共谋**（可验证性只用签名 + 同态哈希两个轻量原语，不用 NIZK）。

---

## 0. 一句话定位

终端 UAV 只做一次 OTP 盲化，簇头 UAV 完成外包加密并共同持有解密密钥份额，云服务器负责聚合与验证协调；用「簇头层 DKG + 三盲外包加密 + 签名认证 + 同态哈希验证」同时拿到 **可验证 + 隐私 + 抗共谋 + 去 TTP + 掉线容忍**，且**不新增任何可信实体**（复用相邻簇头充当第三掩码持有方）。

## 1. 背景与动机

### 1.1 场景

$N$ 架**终端无人机（worker）** 分属 $M$ 个簇，每簇由一架**簇头无人机（cluster-head，算力强）** 管辖，所有簇头上连一台**云服务器**。

- **终端 UAV**：算力极弱（MCU 级，无 NTT），只能做 OTP 盲化与线性哈希；
- **簇头 UAV**：算力强，可做 CKKS 加密、签名验证与 Feldman VSS；
- **云服务器**：聚合 + 验证协调。

### 1.2 要解决的四个痛点

| # | 痛点 | 说明 |
|---|------|------|
| 1 | **终端算力不足** | 终端无法做 CKKS 加密（最贵一步），需把加密**外包给簇头**，但簇头与服务器均不可信 |
| 2 | **无可信机构** | 无 KGC/TA，群体密钥需 **DKG** 分布式生成 |
| 3 | **可验证性缺失** | 簇头可能篡改盲化明文后加密（投毒）、服务器可能伪造聚合结果或伪造客户端 |
| 4 | **抗共谋** | 簇头（见盲化明文）+ 服务器（见掩码）共谋会还原终端明文，需利用**多簇头结构**抗住 |

### 1.3 方案对比：VHD-FL 有什么，别的方案没有什么

**VHD-FL 独有的 / 相对更强的能力**（相对本报告其余 5 个方案与已有文献）：

| 能力 | VHD-FL | 别人的短板 |
|------|--------|-----------|
| **簇头层 DKG（终端零参与、服务器零份额）** | ✅ 终端不碰密钥材料，服务器单独无法解密 | 5-A/5-E 的 DKG 需客户端参与；FedOut 依赖 KDC；ESAFL 依赖 KGC；SKHE 依赖 TA+TEE |
| **三盲外包加密，复用相邻簇头作第三掩码持有方** | ✅ 3-out-of-3 抗共谋，**不新增实体** | DynFL 需另设独立掩码服务器 MS；FedOut 单 Proxy 且"AS⊥Proxy"不抗共谋 |
| **签名认证 + 同态哈希验证** | ✅ 身份可认证 + 聚合可验（**无 NIZK，轻量**） | ESAFL、FedOut 无验证；VeSAFL 无包含性证明 |
| **抗恶意服务器 + 抗共谋** | ✅ 服务器恶意可验，≤2 掩码方共谋不可还原 | 5-A/5-C/5-D/5-E 服务器均 semi-honest；FedOut 抗不了共谋 |
| **去 TTP** | ✅ 实质无 TA | FedOut(KDC)、ESAFL(KGC)、SKHE(TA+TEE)、VLSFL(TA) 均有可信锚 |

**VHD-FL 相对别人的明确短板**（诚实声明，作为后续工作的对照）：

| 能力 | VHD-FL 现状 | 拥有该能力的方案 |
|------|-------------|------------------|
| 密文域拜占庭鲁棒（裁剪均值） | ✘ 无投毒鲁棒性（§7.3 需补） | 5-D RBH-FL |
| 前向 / 后向安全 | ✘ 静态密钥 | 5-E DynFL（epoch 密钥演化） |
| 两级阈值 + 后量子乘法 | ✘ 纯加法（218 模数链） | 5-C HETRA-FL |
| 多密钥（客户端间不可互解密） | ✘ 单密钥（群体） | 5-B MV-FL |

> **结论**：VHD-FL 的不可替代价值在于「**在微型终端算力约束下，不新增实体地同时拿到外包加密、去 TTP、签名认证 + 同态哈希验证、抗共谋**」——这是其余方案各自只占其一二、且均需额外信任锚或额外实体的组合。

**演进定位**（沿"问题—解决"链补齐的一环）：

## 2. 实体与架构

### 2.1 实体角色

| 实体 | 数量 | 算力 | 角色 |
|------|------|------|------|
| **终端 UAV $i$** | $N$ | 极弱（MCU 级，无 NTT） | 训练 + OTP 盲化 + 采样三份掩码 + 线性哈希 + EdDSA 签名 |
| **簇头 UAV $c$** | $M$ | 强 | 外包加密 + 持解密密钥份额 + 簇内预聚合 + 部分解密 |
| **相邻簇头 $c'$** | $M$ | 强 | 持第三份掩码（环形相邻） |
| **云服务器 S** | 1 | 强 | 聚合 + 验证协调 + 阈值解密插值 |

**角色归属**（对照 §4.8 四种角色）：**R1（终端 UAV-as-Client）+ R3（簇头 UAV-as-Relay/边缘代理）**。

### 2.2 实体—可见性矩阵

| 实体 | 可见 | 不可见 |
|------|------|--------|
| 本簇头 $c$ | 簇内 $m_i'$、$r_i^{(c)}$、加密结果 | $r_i^{(s)},r_i^{(c')}$（另两份掩码）；$s$（只有份额） |
| 服务器 S | $r_i^{(s)}$、簇级密文、$h_i$ | $m_i'$、$r_i^{(c)},r_i^{(c')}$；$s$ |
| 相邻簇头 $c'$ | $r_i^{(c')}$ | $m_i'$、$r_i^{(c)},r_i^{(s)}$ |
| 终端 UAV $i$ | 自身 $m_i,r_i^{(\cdot)},h_i$ | 他人数据、$s$ |
| 被动窃听者 | 公开信道 | 各掩码份（走独立信道） |

## 3. 威胁模型

### 3.1 基本威胁模型

- **实体**：$N$ 终端 UAV、$M$ 簇头、1 服务器。
- **服务器 S**：**恶意（malicious）**——可伪造聚合、选择性丢弃、篡改下行模型。
- **簇头**：**半诚实但好奇**，可被腐化；**任意 $\le t-1$ 个簇头合谋**（含与服务器合谋）无法重建 $s$。
- **终端 UAV**：诚实但好奇；**任意掉线**（阈值 + 补零容忍）。
- **三盲掩码持有方**（本簇头 / 服务器 / 相邻簇头）：**任意两方共谋**无法还原 $m_i$（3-out-of-3）。
- **无可信机构**；公开信道 + 独立安全信道承载掩码份。

### 3.2 扩展威胁模型（恶意终端 / 被截获终端）

- **恶意终端**：可上传任意更新（投毒），见 §5.4 与 §7.3；
- **被截获终端**：攻击者完全控制该终端，见 §5.4。

### 3.3 敌手能力 CAN / CANNOT

| 敌手 | CAN（能做什么） | CANNOT（做不到） |
|------|----------------|------------------|
| 恶意服务器 | 伪造聚合结果、选择性丢弃、篡改下行模型、选择性请求解密 | 伪造"带合法终端签名"的更新（无 $sk_i^{sig}$）；单独还原个体 $m_i$（零份额 + 只有一份掩码） |
| 恶意簇头（≤t−1 合谋） | 篡改 $m_i'$ 后加密（被同态哈希聚合验证发现）；提交错误解密份额（去 NIZK 后需半诚实假设） | 重建 $s$（份额不足 t）；伪造终端身份（无终端签名私钥） |
| 恶意终端 | 上传任意投毒更新 | 解密他人更新（零密钥）；伪造"已注册其他终端"的身份 |
| 被截获终端 | 泄露自己数据、冒用自己的签名身份投毒 | 泄露他人数据、解密密钥 $s$（终端零份额） |
| 被动窃听者 | 观察公开信道 | 看到各掩码份（走独立信道） |

## 4. 方案设计：符号、公式与交互

### 4.1 符号系统

| 符号 | 含义 |
|------|------|
| $N,M,t$ | 终端数、簇头数、阈值 |
| $G_c,N_c$ | 簇 $c$ 终端集合与规模 |
| $s_c,b_c=-as_c+e_c$ | 簇头 $c$ 密钥分量与公钥 |
| $s=\sum_c s_c,\ \bar b=\sum_c b_c$ | 群体密钥与公钥 |
| $[s]_c,\ pk_c^*=-a[s]_c+e_c^*$ | 簇头 $c$ 密钥份额与份额公钥 |
| $r_i^{(c)},r_i^{(s)},r_i^{(c')}$ | 三份掩码；$r_i=r_i^{(c)}+r_i^{(s)}+r_i^{(c')}$ |
| $m_i,m_i'=[m_i-r_i]_q$ | 终端明文与盲化明文 |
| $h_i=H(m_i)$ | 同态哈希 |
| $ct_i',ct^{(c)},ct_{\mathrm{glob}}$ | 个体 / 簇级 / 全局密文 |
| $\sigma_i,sk_i^{sig},D_c,\lambda_c$ | 终端签名、终端签名私钥、簇头部分解密、Lagrange 系数 |

### 4.2 阶段 0：簇头层 DKG（无 TTP）

簇头 $c$ 采样 $s_c\leftarrow\chi$、$e_c\leftarrow\psi$，公开 $b_c=-as_c+e_c$；全体得群体公钥

$$
\bar b=\sum_c b_c=-as+\bar e .
$$

簇头用 **Feldman VSS** 把 $s$ 做 $(t,M)$-共享：簇头 $c$ 持 $[s]_c$ 与份额公钥 $pk_c^*=-a[s]_c+e_c^*$。**终端、服务器均不持份额**。

> **设计要点**：终端零参与（保持"一次模减"极轻量）；服务器零份额（单独无法解密）。

### 4.3 阶段 1：终端盲化 + 三份掩码分发

终端 $i\in G_c$ 训练得 $m_i$，采样 $r_i^{(c)},r_i^{(s)},r_i^{(c')}\leftarrow U(R_q)$，$r_i=r_i^{(c)}+r_i^{(s)}+r_i^{(c')}$，盲化 $m_i'=[m_i-r_i]_q$，计算同态哈希 $h_i=H(m_i)=\sum_j m_{i,j}\,g_j$。分发：

$$
m_i',r_i^{(c)}\to \text{本簇头 }c;\qquad r_i^{(s)}\to \text{服务器 S};\qquad r_i^{(c')}\to \text{相邻簇头 }c'; \qquad h_i\to \text{S（公开）}.
$$

### 4.4 阶段 2：簇头验证签名 + 外包加密 + 部分去盲 + 簇内聚合

终端 $i$ 对盲化更新签名 $\sigma_i=Sign(sk_i^{sig},\ m_i'\|\mathrm{round})$ 随 $m_i'$ 发给簇头；簇头 $c$ 验证签名后，用**群体公钥**加密：

$$
ct_i'=(v_i\bar b+m_i'+e_{i,0},\,v_i a+e_{i,1}),\qquad \sigma_i=Sign(sk_i^{sig},m_i'\|\mathrm{round}).
$$

随后簇内聚合并做**自己的**那份去盲：

$$
ct^{(c)}=\Big(\sum_{i\in G_c}c_{i,0}'+\sum_{i\in G_c}r_i^{(c)},\ \sum_{i\in G_c}c_{i,1}'\Big)=\Big(\sum_{i\in G_c}\big(v_i\bar b+m_i-r_i^{(s)}-r_i^{(c')}+e_{i,0}\big),\ \sum_{i\in G_c}v_i a+e_{i,1}\Big).
$$

### 4.5 阶段 3：服务器 + 相邻簇头完成去盲 + 全局聚合

服务器加 $r_i^{(s)}$、相邻簇头加 $r_i^{(c')}$，得全局密文：

$$
ct_{\mathrm{glob}}=\Big(\sum_{c}C_0^{(c)}+\sum_i r_i^{(s)}+\sum_i r_i^{(c')},\ \sum_c C_1^{(c)}\Big)=\Big(\sum_i\big(v_i\bar b+m_i+e_{i,0}\big),\ \sum_i\big(v_i a+e_{i,1}\big)\Big).
$$

### 4.6 阶段 4：阈值解密 + 签名/同态哈希验证

服务器广播 $C_1$；簇头 $c$ 提交 $D_c=C_1[s]_c+e_c^*$；服务器取 $t$ 份插值 $M\approx C_0+\sum_{c\in T}\lambda_c D_c$。随后全体验证：

$$
H(M)\ \stackrel{?}{=}\ \sum_i h_i .
$$

### 4.7 闭环正确性推导

$$
\begin{aligned}
C_0+\sum_{c\in T}\lambda_c D_c
&=\sum_i\big(v_i\bar b+m_i+e_{i,0}\big)+C_1\,s+\text{噪声}\\
&=\sum_i m_i+\sum_i v_i\bar e+\sum_i e_{i,1}\,s_i+\sum_i e_{i,0}+\sum_{c\in T}\lambda_c e_c^*\ \approx\ \sum_i m_i=M .
\end{aligned}
$$

三份掩码在去盲中精确抵消（$r_i^{(c)}+r_i^{(s)}+r_i^{(c')}=r_i$）；$\pm(\sum v_i)a s$ 项由 $\bar b=-as+\bar e$ 与 $C_1s$ 精确对消。哈希线性同态保证 $H(M)=\sum_i H(m_i)=\sum_i h_i$ 当且仅当聚合诚实。

## 5. 安全性分析

### 5.1 四个定理

**定理 1（终端隐私 / 抗共谋）** 设 $m_i$ 被拆成 3 块加法共享 $m_i=(m_i'+r_i^{(c)})+r_i^{(s)}+r_i^{(c')}$，分别由本簇头、服务器、相邻簇头持有。则任意 $\le 2$ 个持有方共谋，无法还原 $m_i$。
*证明*：3 块构成 $m_i$ 的 3-out-of-3 加法共享；任意两方之和 = $m_i-$（第三方块），第三方块均匀 → 后验 = 先验（信息论）。∎

**定理 2（解密密钥抗合谋）** 任意 $\le t-1$ 个簇头（可与服务器合谋）无法重建 $s$，故无法解密任何密文。
*证明*：$s$ 的 $(t,M)$-Feldman VSS 份额，任意 $t-1$ 份对 $s$ 信息论独立；服务器零份额。故合谋方视图不含 $s$ 信息；密文在 $s$ 下 IND-CPA（RLWE）。∎

**定理 3（可验证性：签名 + 同态哈希）**
- (i) **身份认证**：服务器 / 恶意簇头无法伪造"带合法终端签名 $\sigma_i$"的更新（签名不可伪造，$1-\mathrm{negl}(\lambda)$）→ 无法伪造客户端（IFGIA 被挡）。
- (ii) **聚合 / 内容正确性**：恶意服务器提交 $M'\ne\sum m_i$，或簇头把 $m_i'$ 篡改成 $m_i''$，都会破坏 $H(M)=\sum_i h_i$——需哈希碰撞，在 SIS/LWE 难度下不可行；选择性丢弃由参与集合 Merkle 根检测。
- (iii) **解密正确性**：去 NIZK 后**假设簇头半诚实**（正确计算 $D_c$），不再防"主动提交错误份额"（代价见 §5.7）。

**定理 4（掉线容忍）** 任意终端掉线（簇头补零密文）与任意 $M-t$ 个簇头掉线，解密仍成功。
*证明*：$(t,M)$ 阈值保证 $t$ 份份额可重建；补零密文保证聚合分母完整。∎

### 5.2 抗共谋矩阵

实体：$N$ 终端、$M$ 簇头、$1$ 服务器。两套**正交**的抗性：

| 共谋集合 | 攻击目标 | 是否抗住 | 依赖 |
|----------|----------|----------|------|
| 服务器 + 任意终端 | 推断他人 $m_j$ | ✅ | 服务器只见密文+聚合，终端只见自己数据 |
| 服务器 + $\le t-1$ 个簇头 | 重建 $s$ 解密个体 | ✅ | $(t,M)$ 阈值，份额不足 |
| $\le t-1$ 个簇头（不带服务器） | 重建 $s$ | ✅ | 同上 |
| 任意 $\le 2$ 个掩码持有方 | 还原个体 $m_i$ | ✅ | 三盲 3-out-of-3 |
| 被动窃听者 | 窃取明文 | ✅ | 掩码走独立信道 + RLWE |
| **≥ t 个簇头**（含服务器配合） | 重建 $s$，解出全体 $m_i'$（盲化明文） | ❌（解密层） | $(t,M)$ 阈值固有上界；还原 $m_i$ 仍受盲化层拦 |
| **三个掩码持有方全腐化** | 还原 $m_i$ | ❌（盲化层） | 3-out-of-3 固有上界 |
| **服务器伪造客户端**（IFGIA） | 注入假更新 / 选择性解密 | ❌（需 V1′ 终端签名修补） | 缺身份认证 |

> **两条正交防线**：**解密层**（$(t,M)$，抗 ≤t−1 簇头，失守只解出**盲化** $m_i'$）与**盲化层**（3-out-of-3，抗 ≤2 掩码方，失守才还原**原始** $m_i$）。二者可独立调参：$t>\lceil M/2\rceil$ 抗"多数簇头合谋"；3-out-of-3 升到 $(k{+}1)$-out-of-$(k{+}1)$ 抗任意 $\le k$ 掩码方。

### 5.3 关键澄清（易误解点）

**(1) 加密用"群体公钥"，份额只用于解密。** VHD-FL 不存在"用份额加密"——加密阶段用公开的 $\bar b$（谁都能做），份额 $[s]_c$ 只在解密阶段贡献 $D_c=C_1[s]_c$。因此"服务器 + t−1 簇头"合谋 = t−1 份份额 < t，**重建不出 $s$**（Shamir 信息论），故解不出个体。

**(2) 若真重建出 $s$（≥t 簇头）——确实能解密个体**，标准 CKKS 解密：

$$
c_{i,0}'+c_{i,1}'\cdot s=(v_i\bar b+m_i'+e_{i,0})+(v_i a+e_{i,1})s=m_i'+v_i\bar e+e_{i,0}+e_{i,1}s\approx m_i',
$$

但解出的是**盲化明文** $m_i'$，还原 $m_i$ 仍受 3-out-of-3 拦。

**(3) 身份认证必须"终端签名"，而非簇头签名。** IFGIA 攻击者是服务器，服务器持公钥能自加密假更新，缺的是"终端身份凭证"；簇头签名证不了"终端 $i$ 提交过"，且在簇头可腐化下形同虚设。故 V1′ = **终端签名 + 注册**（终端签 $\sigma_i=Sign(sk_i^{sig}, m_i'\|\mathrm{round})$，簇头验证后加密；"密文加密的就是被签名的 $m_i'$"由**同态哈希聚合验证**兜底——篡改会破坏 $H(M)=\sum h_i$）。终端弱算力不成问题：EdDSA 签名（数十微秒、无 NTT）远轻于 CKKS 加密（NTT 毫秒级）。

### 5.4 泄露面与边界清单（诚实声明）

| 泄露面 / 边界 | 说明 | 缓解 |
|--------------|------|------|
| **公开哈希 $h_i=H(m_i)$ 泄露线性泛函** | 服务器拿到 $m_i$ 的 $\ell$ 维投影，可做部分梯度反演（推断攻击的真入口，非 $m_i'$） | 缩小 $\ell$ + PRG 派生 $g_j$；轻量 DP；盲化哈希 |
| **无投毒鲁棒性** | 恶意终端可任意投毒（同态哈希只验聚合不验诚实性） | 范数承诺筛选；叠 RBH-FL；轻量 DP 审计 |
| **≥t 簇头合谋解出盲化明文** | 解密层被破（还原 $m_i$ 仍受 3-out-of-3 拦） | 调大 $t$；升级盲化到 $(k{+}1)$-out-of-$(k{+}1)$ |
| **固定邻居同管理域** | 相邻簇头同域则 3-out-of-3 退化 2-out-of-2 | 随机/门限掩码分配 |
| **补零密文暴露掉线集合** | 公开事实，非额外泄露；但簇头可借补零投毒 | 补零改由服务器生成（已被同态哈希覆盖） |
| **终端被截获时签名私钥可冒用** | 冒用身份投毒（不泄他人/不泄 $s$） | 签名轮换 + HSM + 异常检测 |
| **新注册假终端注入** | 超出密码学范围 | 注册环节可信性（UAV 物理身份 / 证书链） |

### 5.5 3-out-of-3 的动机澄清 + 每个实体的信息账本

**3-out-of-3 是不是"为了防合谋而硬凑"？** —— 动机确实是抗共谋，但不是硬凑，而是两个前提的**必然推论**：

| 前提 | 内容 | 推导出的约束 |
| ---- | ---- | ------------ |
| 前提 A | 终端**不信任簇头**（簇头半诚实但好奇、可腐化） | 终端不能把 $m_i$ 明文给簇头 → 必须盲化 $m_i'=m_i-r_i$ |
| 前提 B | 掩码 $r_i$ **不能给"见明文方"** | 簇头见 $m_i'$，若再持 $r_i$ 则 $m_i'+r_i=m_i$，簇头**单独**还原 → 掩码只能给"不见 $m_i'$"的服务器 |
| 前提 C | 要抗"**服务器 + 簇头**"共谋（模型明确允许） | 若掩码只给服务器一份，则服务器+簇头共谋 $=m_i'+r_i=m_i$ → 必须拆成 **≥3 块** |
| **结论** | **块数 = 抗共谋的方数 + 1** | 抗 2 方共谋 → 3 块；抗 $k$ 方 → $k{+}1$ 块 |

**精确块结构（是 3 块，不是"3 掩码 + $m_i'$ = 4 块"）**：

$$
m_i = \underbrace{(m_i' + r_i^{(c)})}_{\text{块 1：本簇头 }c} + \underbrace{r_i^{(s)}}_{\text{块 2：服务器 }S} + \underbrace{r_i^{(c')}}_{\text{块 3：相邻簇头 }c'}
$$

- $r_i^{(c)}$ **不是独立的第 4 块**：它与 $m_i'$ 落在同一个持有方（本簇头），合并成块 1（阶段 2 的去盲等价于"把 $m_i'$ 就地调整成 $m_i'+r_i^{(c)}$ 再加密"）。
- VHD-FL 相对 DynFL-v2 的唯一实质差异：第 3 块持有方从"独立 MS"换成"复用相邻簇头"，不新增实体。

**逐实体信息账本**：

| 实体 | 类型 | 能获得 | 无法获得 | 关键推论 |
|------|------|--------|----------|----------|
| **终端 $i$** | 诚实但好奇（扩展：恶意/被截获） | 自身 $m_i$、$r_i^{(\cdot)}$、$m_i'$、$h_i$、$\bar b$、全局 $M$ | 他人 $m_j,r_j$；任何 $s_c,[s]_c$；$s$ | **零密钥份额**→被截获也拿不到解密密钥 |
| **本簇头 $c$** | 半诚实但好奇、可腐化 | 簇内 $m_i'$、$r_i^{(c)}$、自身 $s_c,[s]_c$、$ct^{(c)}$、$C_1$、$M$ | $m_i$（只到 $m_i-r_i^{(s)}-r_i^{(c')}$）；$r_i^{(s)},r_i^{(c')}$；$s$ | 持块 1，**仍缺 2 块**，共谋也还原不了 $m_i$ |
| **相邻簇头 $c'$** | 同簇头 | $r_i^{(c')}$、自身 $s_{c'},[s]_{c'}$、公开参数、$M$ | $m_i'$、$m_i$、$r_i^{(c)},r_i^{(s)}$；$s$ | 只持 1 块，对 $m_i$ **信息论零信息** |
| **服务器 S** | 恶意 | 全部 $r_i^{(s)}$、$h_i$、密文、$M$、$\{D_c\}$ | $m_i'$、$r_i^{(c)},r_i^{(c')}$、$s$、个体 $m_i$ | 零份额；即便选择性解密也只到盲化 $m_i'$ |
| **簇头集合** | $(t,M)$ 阈值份额持有者 | 各自 $[s]_c$、$D_c$ | $s$（<t 份独立） | 独立于掩码层的**第二道防线** |

### 5.6 环形拓扑的掩码持有全景（5 簇头为例）+ 去盲/解密角色分工

**5 个簇头的掩码持有情况**（环形邻居 $c'=(c+1)\bmod 5$，每个簇头同时是"本簇头"和"相邻簇头"）：

| 簇头 | 作为"本簇头"持有（块1） | 作为"相邻簇头"持有（块3） |
| ---- | ----------------------- | ------------------------- |
| CH0  | $G_0$ 的 $m_i'+r_i^{(0)}$ | $G_4$ 的 $r_j^{(0)}$ |
| CH1  | $G_1$ 的 $m_i'+r_i^{(1)}$ | $G_0$ 的 $r_j^{(1)}$ |
| CH2  | $G_2$ 的 $m_i'+r_i^{(2)}$ | $G_1$ 的 $r_j^{(2)}$ |
| CH3  | $G_3$ 的 $m_i'+r_i^{(3)}$ | $G_2$ 的 $r_j^{(3)}$ |
| CH4  | $G_4$ 的 $m_i'+r_i^{(4)}$ | $G_3$ 的 $r_j^{(4)}$ |

服务器持所有簇的块2（$r_i^{(s)}$）。

**安全性结论**：3-out-of-3 层面**无额外漏洞**——还原 $G_c$ 终端的 $m_i$ 仍需"CHc + S + CH(c+1)"三方，任意 2 方共谋在任何组合下都缺一块。**但环形固定邻居有两个弱点**：① 固定邻居可预测（攻击者可精确定位最小还原组合）；② 相邻簇头同域则 3-out-of-3 退化 2-out-of-2。

**去盲 vs 解密（别混）**：

| 阶段 | 目的 | 需要谁 |
| ---- | ---- | ------ |
| 去盲（阶段 2–3） | 消除掩码 $r_i=r_i^{(c)}+r_i^{(s)}+r_i^{(c')}$ | 本簇头（$r_i^{(c)}$）+ 服务器（$r_i^{(s)}$）+ 相邻簇头（$r_i^{(c')}$）= **2 簇头 + 1 服务器** |
| 解密（阶段 4） | 阈值解密得 $M$ | **任意 t 个簇头**提交 $D_c=C_1[s]_c$，与掩码/邻居无关 |

环形是**单向**的（$c'=c+1$），每个簇头只有**一个**相邻簇头，不存在"左右两个邻居"。

### 5.7 去 NIZK 的代价：威胁模型收紧（诚实声明）

本方案可验证性**只用签名 + 同态哈希，去掉了 NIZK**，代价有两个：

| 代价 | 说明 | 是否可接受 |
|------|------|-----------|
| **失去"逐密文定位"** | 原 V1 NIZK 能**逐密文**定位是哪个簇头篡改了 $m_i'$；去 NIZK 后，篡改只能由聚合级 $H(M)=\sum_i h_i$ **整体发现**（知道"聚合被破坏"，不知道"是谁"） | ✅ 可接受——只要"发现即中止/重来"，无需定位 |
| **解密正确性退化为半诚实假设** | 原 V3 NIZK 能防"恶意簇头提交错误 $D_c$ 破坏解密"；去 NIZK 后**防不住**，需把簇头假设收紧为**半诚实**（正确执行、不主动破坏解密） | ⚠ 需在威胁模型明确：簇头 = 半诚实，不防"主动提交错误份额" |

**结论**：去 NIZK 后，威胁模型从"簇头可主动恶意破坏"收紧为"**簇头半诚实（正确执行但好奇）**"；服务器仍是恶意的（由签名 + 同态哈希防）。这是"用 NIZK 换轻量"的**等价交换**：省掉 NIZK 的昂贵证明开销（每密文、每部分解密都要证明），代价是簇头假设收紧 + 失去逐密文定位。

### 5.8 3-out-of-3 架构的问题（架构性缺陷清单）

| # | 问题 | 严重度 | 说明 | 缓解 |
|---|------|--------|------|------|
| 1 | **去盲是 all-or-nothing，无阈值容错** | 🔴 高 | 掩码去盲需"本簇头+服务器+相邻簇头"三方**全在线**；任何一方掉线即去盲失败。且**簇头掉线有跨簇级联影响**：簇头 c 掉线，既让本簇 $G_c$ 无法加密（块1），又让前簇 $G_{c-1}$ 无法去盲（块3） | 用 $(t,n)$-Shamir 门限替代加法共享（掩码份门限分发，容忍掉线）；或冗余备份掩码份 |
| 2 | **通信开销翻倍** | 🟡 中 | 终端要发 4 份 $O(n)$（$m_i'$ + 3 掩码），比标准 FL 多 4 倍 | PRG 压缩掩码（$O(n)\to O(\lambda)$），见 §7.2 |
| 3 | **固定邻居可预测 + 同域退化** | 🟡 中 | 块3 固定在相邻簇头，攻击者可定位最小还原组合；相邻簇头同域则退化 2-out-of-2 | 随机/门限掩码分配 |
| 4 | **本簇头信息最强** | 🟢 低 | 本簇头持块1，离 $m_i$ 只差 2 块（服务器/相邻簇头各只差 3 块） | 结构性固有，无法消除 |

> **最关键的是问题 1**：3-out-of-3 的"去盲"和 $(t,M)$ 的"解密"在**掉线容忍上不匹配**——前者 all-or-nothing、后者有阈值。方案声称"掉线容忍"时，**只对了解密层，没对去盲层**（簇头掉线虽不破坏解密，但会因缺块3 破坏前簇的聚合）。这是 3-out-of-3 架构最需要正视的缺陷。

## 7. 实验设计

### 7.1 实验总矩阵（七块）

1. **精度**：MNIST / CIFAR-10 / FEMNIST，IID + Non-IID（Dirichlet $\alpha\in\{0.1,0.5,5\}$），vs 明文 FedAvg（证明 HE 零精度损失）；
2. **效率**：终端单轮开销（应 ≈ 一次模减 + 采样 + 签名，$\mu$s 级）、簇头/服务器开销、端到端每轮时延；
3. **掉线容忍**：掉线率 $\alpha\in\{0.1,0.2,0.3\}$ 下解密成功率 + 收敛曲线；
4. **通信**：见 §7.2，对标 $\mathcal{B}_{\max}\approx 25$ MB/轮；
5. **鲁棒性**：见 §7.3 六类攻击 × 防御；
6. **安全开销**：DKG 时间、签名 / 验证开销（终端签名 + 簇头验证）、同态哈希开销；
7. **消融**：三盲 vs 双盲、有/无验证、有/无 DKG、有/无身份认证，逐项看收益。

### 7.2 通信开销优化

**先定位 3-out-of-3 架构的通信开销来源**：终端每轮要发 **4 份 $O(n)$ 数据**（到 3 个方向）：

| 方向 | 内容 | 体积 |
|------|------|------|
| 终端 → 本簇头 | $m_i'$（盲化明文）+ $r_i^{(c)}$（掩码份） | $2\times O(n)$ |
| 终端 → 服务器 | $r_i^{(s)}$（掩码份） | $O(n)$ |
| 终端 → 相邻簇头 | $r_i^{(c')}$（掩码份） | $O(n)$ |

这是**标准 FL 的 4 倍**（标准 FL 终端只发 1 份 $m_i$）。

**核心优化：掩码 PRG 压缩（最关键，直接消掉 3 份掩码的开销）**：

三份掩码 $r_i^{(c)},r_i^{(s)},r_i^{(c')}$ 由终端用 PRG 从 3 个种子生成，**终端只发种子（$O(\lambda)$），接收方用种子重新扩展出掩码**。这样终端上行从"4 份 $O(n)$"降到"1 份 $O(n)$ + 3 份 $O(\lambda)$"。

**量化对比**（$10^6$ 参数，$n=16384$，$\log q\approx 218$）：

| 方案 | 终端上行 | 降幅 |
|------|----------|------|
| 优化前（掩码全量传输） | $m_i'$ 3.65 MB + 3×3.65 MB ≈ **14.6 MB** | — |
| 优化后（掩码 PRG 压缩） | $m_i'$ 3.65 MB + 3×32 B ≈ **3.65 MB** | **降 4 倍** |

> **关键洞察**：$m_i'=m_i-r_i$ 是**均匀随机**（减了均匀掩码），**无法熵编码压缩**（均匀随机=最大熵），所以 $m_i'$ 的 $O(n)$ 传输是刚性的，只能靠稀疏化/量化；但 3 份掩码是"可再生的随机数"，用 PRG 种子即可**几乎零成本**传输。优化后 VHD-FL 的终端上行 ≈ 标准 FL（都是 1 份 $O(n)$），3-out-of-3 的额外通信开销被 PRG 基本消除。

**其余优化（通用）**：

| 优化 | 做法 | 与带宽约束的关系 |
|------|------|------------------|
| **打包（SIMD）** | 终端/簇头把多个槽打包进单密文 | 密文体量降 $\sim n/2$ 倍，直接贴 $10^6$ 参数上限 |
| **稀疏化 + top-k** | 只传梯度幅值最大的 $k$ 坐标（注意索引隐私） | $10^7$ 模型降到可行区 |
| **量化** | 梯度量化到 8/4-bit 再编码 | 密文与明文体量双降 |
| **残差压缩** | 传"预测残差"而非全量更新 | 上下行同时降 |
| **簇内预聚合** | 簇头把 $N_c$ 份密文压成 1 份簇级密文 | 回传降 $N_c$ 倍 |

**必做实验**：在模型 $10^5/10^6/10^7$ 参数 × 不同稀疏率 $\rho$ 下，画「通信量 vs 精度」曲线，与 FedOut / CDKS-LSS / ESAFL / 明文 FedAvg 并列对比，证明 VHD-FL 在 $\mathcal{B}_{\max}\approx 25$ MB/轮内可达目标精度。

### 7.3 鲁棒性（攻击）实验

| 攻击 | 具体方法 | 应验证的防御 |
|------|----------|--------------|
| **标签翻转** | 拜占庭终端翻转标签后训练 | 范数裁剪（RBH-FL 裁剪均值可移植） |
| **符号翻转** | 梯度整体取反放大 | 裁剪 + 中位数 |
| **梯度放大（boosting）** | 范数放大 $k$ 倍 | $\ell_2$ 范数裁剪 |
| **后门攻击** | 植入触发器的投毒 | 裁剪 + 差分隐私审计 |
| **IFGIA（核心）** | 服务器伪造客户端 + 选择性隔离 | **V1′ 终端签名 + 完整聚合解密校验**，测"隔离成功率" |
| **梯度反演** | DLG / iDLG / Inverting Gradients 在 $M$ 上 | 轻量 DP，测反演 PSNR/MSE |

**实验指标**：攻击下全局准确率（应 ≥ 无攻击的 90%+）；IFGIA 隔离成功率（应从 ~99.5% 降到接近 0）；梯度反演 PSNR（加 DP 后应显著下降）。

## 8. 已知局限与后续工作

1. **3-out-of-3 去盲 all-or-nothing、无阈值容错**（最需正视）：簇头掉线会因缺块3 破坏前簇聚合，去盲层与 $(t,M)$ 解密层的掉线容忍不匹配——需用 $(t,n)$-Shamir 门限替代加法共享或冗余备份掩码份；
2. **无投毒鲁棒性**：需补范数承诺筛选或叠 RBH-FL（纯加法 218 无法密文域范数比较）；
3. **静态密钥，无前向/后向安全**：可借鉴 DynFL 的 epoch 密钥演化；
4. **公开哈希线性泛函泄露**：需盲化哈希或 DP 缓解；
5. **去 NIZK 后簇头假设收紧为半诚实**：不防"主动提交错误解密份额"，且失去逐密文定位（§5.7）；
6. **索引隐私（top-k 稀疏化引入）**：本方案通信优化中的未解决项；
7. **DKG 假设诚实多数**：恶意多数需替换为 New-DKG；
8. **无原型实现**：全部为理论与参数推导，需用 TenSEAL/SEAL 实测校验带宽与噪声预算。
