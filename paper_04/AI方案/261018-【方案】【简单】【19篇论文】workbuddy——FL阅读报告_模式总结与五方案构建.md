### 1.3 演化脉络（循序渐进）

**(1) MKHE 解密链**：`19-CDKS`（MK-CKKS 成立，但部分解密值 μ_i 在公共信道明文泄露，可被服务器+单个客户端合谋拆出他人贡献）→ `xMK-CKKS`（Ma et al.，用聚合公钥加固密文，但**一人掉线即整轮失败**）→ `Wang et al.` TTP 方案（引入可信第三方，信任回潮）→ `26-CDKS-LSS`（对解密份额在 R_q 上做 Shamir 式 LSS：无 TTP、阈值 t 掉线容忍、解密关键步骤从计算安全提升到信息论安全；代价是参与者间 P2P 通信开销大）→ `25-ESAFL`（另一条路：干脆放弃份额分发，ESHE 单步非交互解密，加速 204–953×，代价是 AS 完全可信、退回中央式信任）→ `26-FedOut`（第三条路：ECMK-CKKS 非交互解密+代理外包 SOP，代价是 KDC 可信+双实体非合谋）。**这条链告诉我们：份额分发的安全性、掉线容忍、去信任化三者构成不可能三角，现有工作各自放弃一角。**

**(2) 单密钥效率链**：`25-FedSHE`（可信 KMC+分段 CKKS 突破槽限制）→ `25-FedPHE`（KDC+秘密共享混淆因子，承认"客户端互不信任"仍未解）→ `25-SKHE`（ECC 加密 HE 私钥+秘密分享+TEE 受控解密，绕开 MKHE 但信任转给 TEE）→ `25-HHE`（PASTA+BFV 转译，客户端轻 2000×，服务器重 15621×，且单密钥被恶意客户端击穿）。**链的启示：单密钥路线的天花板是"恶意客户端+合谋"，混合转译路线的天花板是服务器算力。**

**(3) 双服务器信任链**：`23-LSFL`（纯加法秘密共享，最轻，但 Byzantine 过滤启发式）→ `23-ELSA`（恶意模型"几乎免费"，但只保护上行、模型分发不隐私）→ `24-BPVFL`（双向可验证+恶意聚合云，但 S1 解密单点）→ `26-HPRE`（分量分离 H-PRE，把"至少一个完全可信服务器"降为"两服务器不合谋"）→ `26-BPFLH/TDPPFL/PDFL`（密文上拜占庭检测与隐私聚类）。**链的启示：双服务器不串谋已成为 2026 年主流折中，但"服务器合谋怎么办"被所有作者推到 future work。**

**(4) 可验证与鲁棒链**：`BPVFL`（TP-ZKP 双向验证）→ `25-VeSAFL`（Pedersen VSS+BLS，主动恶意）→ `26-VLSFL`（多轮密钥复用+同态哈希验证 200ms）→ `26-HEFLGuard`（密文分组聚出验证模型抓后门，但单密钥+服务器不可被攻陷）→ `26-SMTFL`（检测后**遗忘**，引入可撤销维度）。**链的启示：验证机制（同态哈希、签名、VSS）已成熟到"不算创新"，创新必须发生在验证与隐私机制的耦合方式上。**

**(5) 层次型链**：`25-PrivHFL`（tMK-CKKS 层次密文训练，KGC 初始化+三实体互不串谋假设强）→ `26-PEFL`（TTHE 双陷门抗边缘-参与者合谋+后门）→ `26-PPBR`（CLDP+PLHE 双层过滤，接受精度损失）→ `26-RPPFL`（模型分割+轻量 DP，抗恶意云 IFGIA）。**链的启示：层次型的核心矛盾是"边缘/云要做鲁棒过滤却看不到明文"，现有方案要么信任边缘（RPPFL），要么用 DP 换（PPBR），要么用重密码（PEFL）。**

**(6) UAV/空天地场景的隐私空白**：`25-UAV-AFL`、`26-OAFL`、`26-AchiFL`、`26-FedHRA` 全部**无密码学隐私机制**（空中明文聚合可任意窃听）；唯一带隐私的 `26-PPDO` 是分布式优化而非 FL，且仅半诚实、无掉线设计、无恶意模型。**"UAV 场景 + 强隐私 + 掉线/异步容忍 + 恶意鲁棒"四者无一工作同时满足**——这是本报告 5 个新方案的主要落点。

## 第 2 章 UAV 场景的挑战与值得研究的点

UAV 场景的 FL（UAV-Assist、Edge-Assist、低空经济、LEO 协同）与机房跨 silo FL 有本质差异。综合 45 篇文献与场景分析，挑战如下：

**C1 空地链路的广播窃听性。** UAV 以无线广播收集更新，任何同频接收机可截获。UAV-AFL/OAFL 依赖的 AirComp 空中叠加聚合以明文传输梯度，天然可被窃听与注入。→ **密码保护不是可选项，是第一层需求。**

**C2 高动态拓扑与间歇连接。** UAV 巡航导致地面设备接入窗口短且不规则；设备可能随时离线。SecAgg/CDKS 系的同步屏障假设在 UAV 场景失效；xMK-CKKS"一人掉线即失败"在此不可接受。→ **异步收集 + 阈值掉线容忍是硬需求。**

**C3 机载算力/能量受限。** 全同态乘法的深度与重线性化开销难以由机载计算机承担。→ **聚合操作应退化为同态加法（深度 1），乘法留给地面/云侧或客户端本地。**

**C4 UAV 半信任与被俘威胁。** 移动节点难以物理审计，可能被捕获、伪造或恶意操控；同时地面站与云也未必可信。→ **任何单实体被攻陷/被俘不应导致隐私崩溃（无单点密钥）。**

**C5 覆盖调度与训练调度的耦合。** 通信窗口（UAV 掠过设备上空的几秒到几十秒）与聚合轮的同步直接影响收敛；错过窗口的更新如何处理是开放问题。→ **覆盖-训练协同调度是 UAV-FL 独有的研究点。**

**C6 异步陈旧（straggler/staleness）。** 更新到达时间差异大，陈旧更新直接加权会拖垮收敛（AchiFL 的 obsolescence 效应）。→ **陈旧度感知的聚合权重必须在隐私约束下计算。**

**C7 统计异构性（non-IID）。** 地面设备按区域/任务分布数据，UAV 覆盖区之间分布差异显著；服务器做质量加权时看不见明文。→ **non-IID 下的密文鲁棒聚合是层次型方案的核心难点。**

**C8 无基础设施的密钥分发。** 野外应急场景没有在线 KMC/KGC；飞行前地面窗口是唯一可信 setup 时机。→ **DKG/阈值密钥 + 飞行中自维持是必由之路。**

**C9 多 UAV 编队协作。** 覆盖重叠区设备可能被多架 UAV 重复收集，带来重复计数与跨 UAV 一致性验证问题。→ **需要层级验证链与去重机制。**

**C10 模型下发（下行）隐私。** 多数安全聚合方案只保护上行（客户端→服务器），全局模型下发仍是明文。UAV 广播下发全局模型可被竞争对手截获。→ **下行加密分发值得专门设计。**

**值得研究的点（由挑战推出）**：①异步门限解密的安全聚合；②覆盖-训练协同的密钥与调度联合设计；③密文上的陈旧度/质量感知加权；④移动节点的动态 DKG 与份额失效；⑤层级哈希验证链；⑥下行密文分发。

## 第 4 章 方案一：ATV-FL —— 异步门限可验证联邦学习（标准 FL，单服务器）

### 4.1 场景

跨 silo 联邦学习（医疗机构、银行间风控、跨地域企业），N 个机构客户端，一个聚合服务器（公共云）。客户端位于不同时区、维护窗口各异，**无法保证同一时刻全体在线**；服务器为公共云，诚实但好奇，且可能与少量客户端合谋。无 TTP、无 KGC、无 TEE。

### 4.2 要解决的问题

- **P1（G1）**：MKHE-FL 的解密阶段存在不可能三角——CDKS 系部分解密值公共信道泄露；CDKS-LSS 需要 P2P 份额分发（开销大且要求参与者两两在线）；ESAFL 需要完全可信 AS；FedOut 需要可信 KDC 与双实体非合谋。现实跨 silo 场景中 TTP 与 P2P 都不可接受。
- **P2**：同步解密屏障与异步客户端矛盾：阈值方案要求 t 个客户端**同时**提交，任一繁忙即阻塞整轮。
- **P3**：服务器在解密阶段位于"信任真空"——客户端把解密材料交给服务器后，无法验证服务器是否如实合成、是否如实公布全局模型。

### 4.3 创新点与总体设计目标

- **创新点 1（总体框架）**：我们提出 ATV-FL，据我们所知是**首个面向 MKHE 标准 FL 的"异步门限解密 + 全链路可验证"框架**：客户端用各自独立密钥加密（多密钥），服务器全程只见密文，全局模型的恢复由 t-of-n 异步提交的门限份额完成，任何时刻只需 t 个客户端在线，无 TTP、无客户端间 P2P 信道。
- **创新点 2（SEPD 协议，Signed Encrypted Partial Decryption）**：针对 ESAFL 揭示的"部分解密值公共信道裸奔"问题，我们设计签名加密份额提交协议：客户端的部分解密份额以服务器公钥加密、以客户端签名绑定（份额，轮次，密文哈希）三元组后提交公告板。公共信道上的任何旁观者（含其他客户端）只见密文份额；服务器是唯一可见份额明文者，且无法伪造或替换份额（伪造 = 攻破签名）。
- **创新点 3（AsyncTDec 协议，Asynchronous Threshold Decryption Aggregation）**：我们设计异步门限解密聚合协议：份额在公告板上**随到随验随存**（签名验证 + 与上轮密文同态哈希的交叉校验），服务器在收集到任意 t 份有效份额的任意时刻即可执行合成解密；份额新鲜噪声保证服务器即使集齐全部份额也无法回推出任何客户端的长期密钥材料。
- **创新点 4（实验目标）**：在 MNIST/FMNIST/CIFAR-10/SVHN 上与 CDKS-LSS、ESAFL、MASER 对比，预期端到端训练时间随掉线率平稳（容忍 ≤t−1 任意时刻掉线），通信轮次为 O(1)/轮，双向通信开销显著低于 CDKS-LSS（无 P2P 份额分发）。

### 4.4 威胁模型

**实体**：N 个客户端 {C₁…C_N}、聚合服务器 S、公告板 BB（仅提供 append-only 公开存储与读出，不主动作恶；可用透明日志/区块链实例化）。

**敌手能力**：
- T1：S 为诚实但好奇（HBC）：正确执行协议但试图推断个体客户端更新；S 可与至多 t−2 个客户端合谋。
- T2：至多 t−1 个客户端可被攻陷（HBC）；被攻陷客户端之间的合谋不扩大泄露。
- T3：任意客户端可在任意轮次掉线，掉线总数不受限（每轮只需 ≥t 份份额）。
- T4：外部被动窃听者可见全部信道与 BB 内容。

**安全目标**：①个体更新对 S、其他客户端、窃听者保密（语义安全）；②全局模型聚合结果对所有人正确（可验证）；③掉线不阻塞、不泄露。

**密码学假设**：决策性 RLWE 假设（decisional RLWE）；Schnorr 签名的 EUF-CMA；公告板一致性。

### 4.6 方案设计：闭环实体交互与公式推导

**阶段 0：一次性子密钥分发（无需在线 TTP）。** 采用 §1.2-DKG 笔记的 RLWE 友好 DKG：每客户端 C_i 本地采样 t−1 次随机多项式 f_i(z)=s_i + Σ_{k=1}^{t−1} f_{i,k} z^k，经认证信道向 C_j 发送 f_i(j)。C_j 聚合得门限份额 s_j^* = Σ_i f_i(j)，并验证 Σ_i f_i(0) 对应公钥分量的一致性（零知识一致性证明，标准构件）。长期密钥 s_i 本身不共享——DKG 分发的是**合成密钥 s^* = Σ_i f_i(0)** 的门限份额。可见性：C_j 只见 s_j^*；s^* 从不完整出现。

**阶段 1：多密钥加密上传（客户端本地，公式不跳跃）。**

C_i 本地训练得 Δ_i，用 MK-CKKS 加密（标准 CDKS 编码）：设公共参考串 CRS 提供 a ∈ R_Q 均匀随机。C_i 采样 v_i, e_i⁰, e_i¹ ← χ，计算：

$$c_{i,0} = b_i v_i + e_i^0 + \lfloor \Delta \cdot \Delta_i \rceil, \qquad c_{i,1} = a v_i + e_i^1$$

其中密文 c_i = (c_{i,0}, c_{i,1}) ∈ R_q² 在拼接密钥 **s** = (1, s₁,…,s_{N_cl}) 下满足解密结构 c_{i,0} + c_{i,1}·s_i ≈ ⌊Δ·Δ_i⌉（MK-CKKS 中各分量密钥独立，服务器后续经密钥转换）。C_i 计算声明哈希 h_i = H(⌊Δ·Δ_i⌉)，签名 σ_i = Sig_i(c_i, h_i, r)（r 为轮次），将 (c_i, h_i, σ_i) 上传 S。C_i 本地销毁 Δ_i 明文与 v_i。**信息流向**：C_i→S：密文；S 得 c_i（不可解密个体，密钥在客户端）；h_i 供后续验证。

**阶段 2：密文聚合（服务器侧）。** S 对所有在线客户端密文做同态加（CKKS 深度 0）：

$$c_{agg} = \textstyle\sum_{i \in \mathcal{U}_r} w_i \odot c_i \;=\; \Big(\textstyle\sum_i w_i c_{i,0},\; \textstyle\sum_i w_i c_{i,1}\Big)$$

（w_i ⊙ 为明文标量乘密文，CKKS 原生支持，深度 1。）同时 S 计算聚合声明哈希 h_agg = ∏_{i∈𝒰_r} h_i^{w_i}（LHH 同态性）。S 公布 (c_agg, h_agg, 𝒰_r) 于 BB。**验证闭环**：任何客户端可重算 ∏ h_i^{w_i} 并与 h_agg 比对，检测 S 篡改聚合（篡改 ⇒ 哈希不一致或伪造签名）。

**阶段 3：SEPD —— 签名加密份额异步提交（核心协议 1）。** 解密 c_agg 需拼接密钥下的部分解密。门限化：C_j 用其 DKG 份额 s_j^* 计算聚合密文的部分解密，并注入**份额新鲜掩码** ρ_j ← χ：

$$d_j = c_{agg,0} + c_{agg,1}\cdot s_j^* + \rho_j \pmod q$$

直接发布 d_j 会让公共信道旁观者积累 (c_agg, d_j) 对（ESAFL 揭示的裸奔问题）。SEPD 改为：C_j 计算服务器公钥封装 ct_j = Enc_pkS(d_j)，签名 σ_j^* = Sig_j(d_j, H(c_agg), r)，将 (ct_j, σ_j^*) 追加到 BB。**信息流**：C_j→BB：密文份额（旁观者不可见 d_j 明文）；S→BB 读取 ct_j。BB 仅验证签名合法性后收录，**随到随收**，不要求 t 份同时到达——解决 P2。

**阶段 4：AsyncTDec —— 异步门限解密聚合（核心协议 2）。** 当 BB 中有效份额集合 |𝒮| ≥ t 的任意时刻，S 执行：①解密 ct_j 得 d_j（S 是 Enc_pkS 的唯一解密者）；②逐份验证 σ_j^* 与 H(c_agg) 绑定（防止跨轮重放：σ_j^* 含轮次 r 与 c_agg 哈希）；③合成：

$$\hat{m} = \sum_{j \in \mathcal{S}} \lambda_j^{\mathcal{S}} \, d_j = c_{agg,0} + c_{agg,1}\cdot \underbrace{\textstyle\sum_j \lambda_j^{\mathcal{S}} s_j^*}_{=\, s^*} + \underbrace{\textstyle\sum_j \lambda_j^{\mathcal{S}} \rho_j}_{\text{噪声项 } \rho} = \lfloor\Delta \cdot \textstyle\sum_i w_i \Delta_i\rceil + \rho'$$

其中 Σ_j λ_j^𝒮 s_j^* = s^* 由 Shamir 重构性质成立（f_i 次数 ≤ t−1，|𝒮| ≥ t）；ρ' 为聚合新鲜噪声。④S 公布全局模型 w_{r+1} = w_r − η·Decode( m̂ / Δ ) 及 (𝒮, {σ_j^*}) 于 BB。**为什么服务器集齐份额也拿不到长期密钥**：d_j 含新鲜 ρ_j，S 从 (c_agg, d_j) 中分离不出 s_j^*（等价于解 RLWE 样本）；份额 s_j^* 只用于合成一次性聚合解密的 s^*，且 s^* 从不完整出现于任何单一实体。

**阶段 5：下行与新一轮。** 全局模型为明文公开（跨 silo 场景中全局模型本身非机密）；若需下行机密性（无人机场景，见方案五），可改为对 c_agg 做密文下发 + 客户端门限解密。每轮 r 使用新掩码 ρ_j 与新签名，防跨轮链接。

### 4.7 安全性分析

**定理 1（个体更新机密性）**：在决策性 RLWE 假设下，HBC 服务器与 ≤t−2 客户端合谋无法以优于可忽略的优势区分任一客户端更新 Δ_i。

*证明要点*：①c_i 是 RLWE 样本 (a, av_i+e_i¹) 的线性变形加编码消息，v_i, e_i 在加密后即销毁 ⇒ 由 RLWE 的 IND 性质，c_i 对无 s_i 者隐藏明文（归约：区分 c_i 与均匀样本的敌手可解 decisional RLWE）。②合谋敌手握有的密钥材料：被攻陷客户端的 s_i（仅解密其自身密文）、服务器可见的 d_j 份额（含新鲜 ρ_j）。由份额新鲜性，d_j = c_agg s_j^* + c_agg,0 + ρ_j 是新鲜 RLWE 样本，不泄露 s_j^*。③跨轮链接：每轮新 ρ_j 与签名绑定 (H(c_agg), r)，不可重放。∎

**定理 2（聚合可验证性）**：服务器若发布与诚实聚合不一致的全局模型，则至少违反 LHH 一致性、Schnorr 签名不可伪造性、或公告板一致性之一。

*证明要点*：篡改发生在三处：改 c_agg（⇒ h_agg = Πh_i^{w_i} 不匹配，被任何验证者发现）；替换/丢弃份额（⇒ σ_j^* 签名验证失败，EUF-CMA）；发布错误 m̂（⇒ 与 c_agg 解密结构矛盾，客户端可用其本地 c_i 贡献重算验证）。∎

**定理 3（掉线鲁棒性）**：任意时刻在线客户端 ≥ t 即可推进；掉线客户端不造成任何信息泄露（其密文 c_i 已含其密钥下的 IND 加密）。

*证明要点*：异步收集 + 门限 t 重构；未收集份额的客户端其 ρ_j 未注入，不影响合成正确性（Shamir 重构对任意 ≥t 子集成立）。∎

**局限与缓解**：恶意客户端可在阶段 1 上传精心构造密文（投毒）——ATV-FL 聚焦隐私与可用性，投毒防御交由方案二的验证机制或客户端侧范数裁剪（与 MaskCrypt 的梯度引导加密正交，可叠加）。

```
输入: 客户端集 {C_i}, 服务器 S, 门限 t, 轮数 R
输出: 全局模型 w_R
1:  阶段0 (一次性): 每对客户端执行 DKG 份额交换与一致性 ZK 验证
    → 每 C_j 持有 s_j^*; 所有人持有 pk 分量与 {vk_i}
2:  for r = 1 … R do
3:      S 广播 w_r 与在线请求
4:      每个在线 C_i: Δ_i ← LocalTrain(D_i, w_r)
5:          c_i ← MK-CKKS.Enc(Δ_i);  h_i ← H(⌊Δ·Δ_i⌉)
6:          σ_i ← Sig_i(c_i ‖ h_i ‖ r)
7:          C_i → S: (c_i, h_i, σ_i);  本地销毁 Δ_i, v_i
8:      S: 验签 ∀i;  c_agg ← Σ_{i∈U_r} w_i ⊙ c_i
9:      S → BB: (c_agg, Π h_i^{w_i}, U_r)
10:     每个 C_j (异步, 可在任意后续时刻):
11:         d_j ← c_agg,0 + c_agg,1·s_j^* + ρ_j       // ρ_j ← χ 新鲜采样
12:         BB.append( Enc_pkS(d_j), Sig_j(d_j‖H(c_agg)‖r) )
13:     当 |{有效份额}| ≥ t:
14:         S: d_j ← Dec_skS(ct_j);  验签与轮次绑定
15:         m̂ ← Σ_{j∈S} λ_j^S · d_j
16:         w_{r+1} ← w_r − η · Decode(m̂/Δ)
17:         S → BB: (w_{r+1}, S, {σ_j*})
18: return w_R
```

**算法 2：SEPD（签名加密份额提交）**

```
输入: C_j 的份额 s_j^*, 聚合密文 c_agg, 轮次 r, 服务器公钥 pkS
输出: BB 上的一条有效份额记录
1: ρ_j ← χ;  d_j ← (c_agg,0 + c_agg,1·s_j^* + ρ_j) mod q
2: ct_j ← Enc_pkS(d_j)                 // 公共信道只见密文份额
3: σ_j* ← Schnorr.Sign_sk_j( d_j ‖ H(c_agg) ‖ r )
4: BB.append(ct_j, σ_j*)               // BB 验签后收录; 随到随存
5: C_j 本地销毁 d_j, ρ_j
```

**算法 3：AsyncTDec（异步门限解密聚合）**

```
输入: BB 上份额集合 {(ct_j, σ_j*)}, 门限 t
输出: 全局模型更新 m̂
1: S ← {j : Verify(σ_j*, d_j‖H(c_agg)‖r) = 1 ∧ ct_j 解密合法}
2: if |S| < t: return ⊥              // 继续等待, 不阻塞其他轮
3: ∀j∈S: d_j ← Dec_skS(ct_j)
4: m̂ ← Σ_{j∈S} λ_j^S · d_j          // 拉格朗日合成, 新鲜噪声 ρ = Σλ_jρ_j
5: assert LHH_check(m̂, Π h_i^{w_i})  // 聚合声明一致性
6: return m̂
```

## 第 5 章 方案二：TwinGuard-FL —— 分量密钥双验证联邦学习（标准 FL，双服务器）

### 5.1 场景

模型市场与跨机构联合训练（如多家医院联合训练、再分发给成员机构使用）：客户端上传更新，**全局模型也要下发给成员**。现实中存在两类真实威胁：①聚合服务器被攻陷或本身恶意（篡改聚合、窥伺更新、伪造验证结果）；②参与方中混入投毒/后门客户端，且会伪造"检测通过"报告掩盖自己。

### 5.2 要解决的问题

- **P1（G2）**：HEFLGuard 的后门检测依赖两个强假设——全体客户端共享单一私钥（恶意客户端可解密他人更新）、服务器不可被攻陷（否则验证模型与全局模型都被操纵）。这两个假设在模型市场场景中均不成立。
- **P2（G5）**：HPRE 把信任降为"双服务器不合谋"，但仅解决解密权限分离，**不解决投毒与伪造报告**；PDFL 的隐私聚类依赖完全可信 TA 与双服务器不串通同时成立。
- **P3**：下行分发环节在所有安全聚合方案中普遍明文化（SecAgg/ELSA/本文方案一均只保护上行），模型本身就是资产。

### 5.3 创新点与总体设计目标

- **创新点 1（总体框架）**：我们提出 TwinGuard-FL，首个将**解密权限分量分离**、**后门交叉验证**、**聚合与下发全链路验证**耦合到单一闭环的双服务器 FL 框架：任一服务器被攻陷不泄露隐私；≤f 个恶意客户端无法注入后门且无法伪造验证结论；全局模型以密文分量形式下发。
- **创新点 2（SplitKey-HE 构造）**：我们把 CKKS 私钥按 RLWE 环结构分量化为 (s^{(A)}, s^{(B)})，使每个密文自然分裂为两个"半密文"分量，分别由聚合服务器 AS 与解密服务器 DS 独立聚合、独立部分解密，只有 (AS, DS) 同时参与才能合成明文——这是把 HPRE 的分量思想首次嵌入 SIMD 打包 CKKS 并支持密文分量级聚合的新构造（D = SplitKey-HE），而非对 HPRE 的直接搬运。
- **创新点 3（CrossVote 协议）**：服务器在密文态生成"重叠分组验证模型"（客户端分组两两重叠，借鉴 HEFLGuard 的验证思想但运行在两台服务器各自分量上），客户端本地比对全局模型与验证模型的行为差异，生成**签名门限投票**（≥2f+1 份独立签名判定才定罪）——把 HEFLGuard 的"多数投票"升级为抗伪造报告的密码学门限，恶意客户端无法靠伪造报告为自己脱罪。
- **创新点 4（实验目标）**：MNIST/FMNIST/CIFAR-10 上，后门攻击成功率（ASR）降至无攻击基线 ±2% 以内，干净精度损失 <2%；AS 或 DS 任一被攻陷时客户端更新零泄露；对比 HEFLGuard 去掉"服务器不可攻陷"假设、对比 PDFL 去掉"TA 完全可信"假设。

### 5.4 威胁模型

**实体**：N 个客户端 {C_i}；聚合服务器 AS（密文聚合、分组、分量 A 部分解密）；解密服务器 DS（分量 B 部分解密、合成）；公告板 BB。

**敌手能力**：
- T1：AS、DS 中**至多一台**被攻陷（HBC 或恶意）；两台合谋不在模型内（与 HPRE/BPFLH/PDFL 同级假设，但比"一个完全可信服务器"弱）。
- T2：≤f < N/3 个客户端恶意：可投毒、注入后门、伪造验证报告；可与被攻陷的那台服务器合谋。
- T3：被动外部窃听者。
- T4：客户端可掉线（不影响验证闭环，验证在服务器侧密文态完成）。

**安全目标**：①个体更新对 AS、DS、其他客户端、窃听者保密（任一服务器单独不可解密）；②聚合与分组结果可验证（LHH + 签名）；③≤f 恶意客户端的后门可被检出且不可抵赖（门限投票）；④下行模型仅成员客户端可恢复（分量合成需成员持有的份额）。

**假设**：决策性 RLWE；Schnorr/ BLS 签名 EUF-CMA；BB 一致性；AS 与 DS 不合谋。

### 5.5 符号系统

在方案一符号基础上新增：

| 符号 | 含义 |
|---|---|
| s = s^{(A)} + s^{(B)} | CKKS 私钥的加法分量分解（环 R_2 上分量） |
| c_i = (c_{i,0}, c_{i,1}) | C_i 密文；分量视角 c_{i,k} = c_{i,k}^{(A)} + c_{i,k}^{(B)}（按 s 的线性性自然成立） |
| w_r^{(g)} | 第 r 轮分组 g 的密文聚合模型（重叠分组） |
| γ_{i→g} ∈ {0,1} | 分组归属指示（分组方案公开） |
| β_i ∈ {0,1} | C_i 的验证判定（1 = 发现后门） |
| T_V = 2f+1 | 定罪门限 |

### 5.6 方案设计：闭环公式推导

**阶段 0：分量化密钥建立。** 客户端集体执行 DKG（同方案一阶段 0）合成共享密钥 s 的门限份额。随后 s 被分量化为 s^{(A)}、s^{(B)} 并**分别经由独立信道**交予 AS、DS（分量本身在环 R_2 上，单独均匀分布、无语义）。可见性：AS 只知 s^{(A)}；DS 只知 s^{(B)}；完整 s 从不出现于任一实体——AS、DS 各自被攻陷均不泄露。

**阶段 1：客户端加密上传。** C_i 用公共 pk（对应 s = s^{(A)}+s^{(B)}）执行标准 CKKS 加密（公式同 §4.6 阶段 1，单密钥形式）：

$$c_{i,0} = b v_i + e_i^0 + \lfloor\Delta\,\Delta_i\rceil, \qquad c_{i,1} = a v_i + e_i^1$$

并计算声明哈希 h_i = H(⌊Δ·Δ_i⌉)、签名 σ_i = Sig_i(c_i, h_i, r)。由于解密关于私钥是**线性**的（m̂ = c_0 + c_1·s），把 s 代入分量分解：

$$\hat m_i = c_{i,0} + c_{i,1}\,s = \underbrace{c_{i,0} + c_{i,1}\,s^{(A)}}_{\text{AS 可算}} + \underbrace{c_{i,1}\,s^{(B)}}_{\text{DS 可算}}$$

因此密文无需任何改造即可按分量路径解密——SplitKey-HE 的关键观察：**解密线性性 = 分量分离免费**。C_i → AS：(c_i, h_i, σ_i)。

**阶段 2：分组密文聚合与分量部分解密（AS 与 DS 交互）。** AS 验签后按公开分组方案 𝒢（每组 ≥2f+1 个客户端、组间两两重叠 ≥f+1 个）计算分组聚合：

$$c^{(g)}_0 = \textstyle\sum_i \gamma_{i\to g}\, w_i\, c_{i,0}, \qquad c^{(g)}_1 = \textstyle\sum_i \gamma_{i\to g}\, w_i\, c_{i,1}$$

以及全局聚合 c^{(*)} = Σ_i w_i c_i。AS 计算自己分量的部分解密并注入新鲜掩码 ρ_A ← χ：

$$p^{(A)}_g = c^{(g)}_0 + c^{(g)}_1 \cdot s^{(A)} + \rho_A, \qquad p^{(A)}_* = c^{(*)}_0 + c^{(*)}_1 \cdot s^{(A)} + \rho_A'$$

AS 将 (p^{(A)}_g, p^{(A)}_*, 分组声明哈希 Π h_i^{γ_{i→g}w_i}, 全局声明哈希 Π h_i^{w_i}) 发送 DS。**DS 可见**：p^{(A)} 分量（含 ρ_A，不泄露 s^{(A)}）、声明哈希。DS 验证 LHH 声明后计算自己分量：

$$p^{(B)}_g = c^{(g)}_1 \cdot s^{(B)} - \rho_A, \qquad p^{(B)}_* = c^{(*)}_1 \cdot s^{(B)} - \rho_A'$$

（DS 减 ρ_A 需要 AS 通过加密信道传 ρ_A——或者更干净的构造：AS 传 Enc_pkDS(ρ_A)，DS 在收到后本地抵消；ρ_A 对 DS 之外不可见。）合成：

$$\hat m^{(g)} = p^{(A)}_g + p^{(B)}_g = \lfloor\Delta \textstyle\sum_i \gamma_{i\to g} w_i \Delta_i\rceil + e', \qquad \hat m^{(*)} = p^{(A)}_* + p^{(B)}_*$$

（噪声 e' 由 CKKS 标准噪声分析有界。）**关键性质**：若 AS 被攻陷并篡改某组聚合，则 DS 侧 LHH 校验 Π h_i^{γw_i} 失败；若 DS 篡改，AS 可用 p^{(A)} 与公开声明复核——双向可验证。

**阶段 3：CrossVote —— 重叠分组后门交叉验证。** DS 下发分组模型 m^{(g)} 与全局模型 m^{(*)}（明文给成员客户端——下发通道本身受签名保护；若需对非成员保密见阶段 4）。每客户端 C_i 在本地良性验证集上比对：

$$\beta_i^{(g)} = \mathbb{1}\big[\, \mathcal{L}\big(f_{m^{(g)}}(x)\big) - \mathcal{L}\big(f_{m^{(*)}}(x)\big) > \tau \,\big]$$

重叠分组设计保证：组 g 若含后门，则与其重叠的 ≥f+1 个其他组行为正常，差异可被检出；组 g 中 ≥2f+1 个**独立客户端**（各自签名）提交 β=1 时定罪该组，组内客户端更新被丢弃并以其密文发起撤销（FUL 式重聚合，构件级引用）。恶意客户端伪造 β=0 无法阻止 2f+1 诚实多数。**为什么需要门限而非多数**：HEFLGuard 的多数投票在恶意客户端 ≥40% 时失效；签名门限 T_V = 2f+1 使伪造报告（EUF-CMA）与数量不足二者必居其一。

**阶段 4（可选）：下行机密分发。** 对非成员不可见的场景，DS 不合成明文，而是直接下发 (p^{(B)}_*, c^{(*)}_1)：成员客户端凭其持有的 s^{(A)} 份额（客户端集体 DKG 同时持有 s^{(A)} 的门限份额——建立阶段已含）本地合成 m̂^{(*)} = c^{(*)}_0 + c^{(*)}_1 s^{(A)} + p^{(B)}_*。非成员无 s^{(A)} 份额，无法恢复模型——下行隐私免费获得。

### 5.7 安全性分析

**定理 1（单服务器被攻陷不泄露）**：在决策性 RLWE 假设下，仅攻陷 AS（或仅攻陷 DS）的敌手对任一 Δ_i 的优势可忽略。

*证明要点*：AS 可见 (c_i, p^{(A)}_g)。由分量分离，从 AS 视角，解密所需 s^{(B)} 缺失；p^{(A)}_g 含新鲜 ρ_A，是 RLWE 型样本。形式化：构造归约，攻陷 AS 的敌手 A 可模拟 c_i 为 RLWE 实例 (a, as+e)，由 decisional RLWE 不可区分于均匀，A 无法以非可忽略优势恢复 ⌊Δ·Δ_i⌉。DS 侧对称（DS 无 c_{i,0} 之外的明文路径，且 s^{(A)} 缺失）。∎

**定理 2（后门检出与不可抵赖）**：若组 g 中注入有效后门且组内诚实客户端 ≥2f+1，则该组以概率 1−negl 被定罪；恶意客户端无法使无罪组被定罪。

*证明要点*：检出性——重叠组保证含后门的 g 与正常组行为差异 >τ（HEFLGuard 的一致性验证在 CKKS 分量路径上仍然成立，因为 m^{(g)} 合成误差有界，不影响 logits 比对）；≥2f+1 诚实签名票必然达到门限。不可诬陷——定罪需 2f+1 份对 (β‖H(m^{(g)})‖r) 的有效签名，恶意客户端仅 f 个，伪造签名违反 EUF-CMA。∎

**定理 3（聚合双向可验证）**：AS 或 DS 任一方篡改聚合结果必被发现。

*证明要点*：声明哈希 Π h_i^{γ_{i→g}w_i} 由 LHH 同态性给出分组聚合的密码学承诺；任何与 p^{(A)}+p^{(B)} 合成结果不一致的篡改都会使 m^{(g)} 与承诺矛盾，验证者（客户端或对方服务器）检出。∎

**局限**：AS-DS 合谋仍假设不成立（与全部双服务器文献同级，G5 的彻底解决需跨域分属机构，超出本方案范围）；分组重叠带来 ≈2× 聚合计算（可接受，聚合是加法深度 0/1）。

### 5.8 算法伪代码

**算法 1：TwinGuard-FL 总体执行流程**

```
输入: 客户端 {Ci}, AS, DS, 分组方案 G(两两重叠≥f+1), 门限 TV=2f+1
输出: 无毒全局模型 w_R
1:  DKG 合成 s → 分量 s(A)→AS, s(B)→DS; {vk_i} 上 BB
2:  for r = 1 … R do
3:      Ci: Δ_i ← LocalTrain(D_i, w_r); c_i ← CKKS.Enc_pk(Δ_i)
4:      Ci → AS: (c_i, h_i=H(⌊ΔΔ_i⌉), σ_i=Sig_i(c_i‖h_i‖r))
5:      AS: 验签;  ∀g∈G: c^(g) ← Σ_i γ_{i→g}·w_i ⊙ c_i;  c^(*) ← Σ_i w_i ⊙ c_i
6:      AS → DS: (p^(A)_g = c^(g)_0+c^(g)_1·s(A)+ρ_A,
                    p^(A)_*, Π h_i^{γw_i}, Π h_i^{w_i}, Enc_pkDS(ρ_A))
7:      DS: 验 LHH;  p^(B)_g ← c^(g)_1·s(B) − Dec(ρ_A);  合成 m^(g), m^(*)
8:      DS → Ci: 签名下发 {m^(g), m^(*)}
9:      Ci: β_i^(g) ← 本地比对 logits 差异;  BB.append(Sig_i(β_i^(g)‖H(m^(g))‖r))
10:     对定罪组 g: AS 丢弃组内密文, 以剩余密文重聚合 c^(*)
11:     w_{r+1} ← Decode(合成结果);  BB 发布
12: return w_R
```

**算法 2：SplitKey-HE（分量部分解密与合成）**

```
输入: AS 持 s(A), DS 持 s(B), 聚合密文 c=(c_0,c_1)
输出: 明文聚合 m̂
1: AS: ρ_A ← χ;  pA ← c_0 + c_1·s(A) + ρ_A
2: AS → DS: (pA, Enc_pkDS(ρ_A))
3: DS: ρ_A ← Dec_skB(Enc_pkDS(ρ_A));  pB ← c_1·s(B) − ρ_A
4: DS: m̂ ← pA + pB = c_0 + c_1·(s(A)+s(B)) + (e·v+e0+e1·s)   // CKKS 噪声项
5: return Decode(m̂/Δ)
```

**算法 3：CrossVote（签名门限后门定罪）**

```
输入: 各客户端签名票 {(β_i^(g), σ_i^(g))}, 门限 TV
输出: 定罪组集合 G_bad
1: BB: ∀(β,σ): assert Verify(σ, β‖H(m^(g))‖r)      // 伪造票直接丢弃
2: ∀g: cnt_g ← #{i : β_i^(g)=1 ∧ σ 有效}
3: G_bad ← {g : cnt_g ≥ TV}
4: ∀g∈G_bad: 触发组撤销 → 剩余密文重聚合
5: return G_bad
```

## 第 6 章 方案三：AeroDKG-FL —— UAV 编队分布式密钥联邦学习（层次型：地面设备—UAV 编队—地面站）

### 6.1 场景

UAV-Assist 应急场景（灾害评估、野外环境监测、边境巡检）：大量地面传感器/手持设备产生数据，一架或多架 UAV 沿巡航轨迹掠过设备上空收集模型更新，回传地面站（GS）全局聚合。**野外无网络基础设施、无在线 KGC**；UAV 机载算力有限；空地链路广播开放；设备与 UAV 都可能随时离线。

### 6.2 要解决的问题

- **P1（G4/C8）**：现有 HE-FL 全部分发密钥于在线 KMC/KGC/TA；UAV 野外场景唯一可信时机是**起飞前地面窗口**，飞行中必须自维持。
- **P2（C2/C4）**：UAV 离队、被俘获、设备休眠造成高掉线率；xMK-CKKS 式"一人掉线即失败"不可接受；被俘 UAV 不应导致密钥崩溃。
- **P3（C3）**：机载算力无法承担 MKHE 乘法/重线性化；同时 UAV 是半信任节点——它要参与聚合（性能需求）但不可见个体更新（安全需求）。
- **P4（C9）**：多 UAV 覆盖重叠区设备被重复收集，需去重与层级验证。

### 6.3 创新点与总体设计目标

- **创新点 1（总体框架）**：我们提出 AeroDKG-FL，首个面向 UAV-Assist 场景的**无基础设施、编队自维持密钥**的层次隐私 FL：起飞前一次 DKG 完成全部密钥建立；飞行中 UAV 只做同态加法聚合与份额管理；阈值解密在回传地面站后由存活编队成员完成。隐私、移动性、算力约束三者同时满足。
- **创新点 2（AeroDKG 协议，Airborne DKG with Slot-Bound Shares）**：把 DKG 份额与**飞行时隙**绑定：份额 s_j^{(τ)} 仅在时隙 τ 有效，时隙轮换通过公开哈希链驱动（τ 的链头由 GS 在起飞前预承诺），离队或被俘 UAV 的份额在下一时隙自动失效，无需在线吊销——移动场景的"份额时效性"是新机制，而非标准 DKG 的直接使用。
- **创新点 3（BlindPack 聚合）**：地面设备对更新做**盲化 + SIMD 打包**后仅支持加法聚合的密文上传（CKKS 深度 0），UAV 机载只执行加法（无乘法、无重线性化），同时盲化因子使 UAV 无法从聚合密文反推个体更新；重复收集由设备端随机延迟+序列号去重。
- **创新点 4（实验目标）**：MNIST/FMNIST/SVHN（模拟设备本地数据）上，相对"UAV-AFL 明文空中聚合 + SecAgg"组合方案：端到端收敛时间随 UAV 数量近似线性下降，容忍 ≤t−1 架 UAV 被俘/离队，单 UAV 算力开销 < 机载预算（加法聚合），个体设备更新对 UAV 与窃听者保密。

### 6.4 威胁模型

**实体**：地面设备 {D_i}；UAV 编队 {U_1…U_n}（n ≥ 3t−2 配置）；地面站 GS；公告板 BB（回传后可用）。

**敌手能力**：
- T1：UAV 半诚实（HBC）且**可能≤t−1 架被俘**（恶意）；被俘 UAV 可与地面设备中 ≤t−1 个合谋。
- T2：GS 半诚实；GS 与 UAV 不合谋（地面站与编队分属不同管理域时可弱化，见安全性分析）。
- T3：任意设备掉线/休眠；任意时刻存活 UAV ≥ t。
- T4：空地链路全程被窃听、可重放（时隙哈希链抗重放）。

**安全目标**：①设备个体更新对 UAV、GS、窃听者保密（仅存活 ≥t 编队+GS 合成可见聚合结果）；②被俘 UAV 影响限于其时隙内的聚合份额，可检测（哈希链断裂）；③聚合结果对 GS 正确（LHH 验证）；④无在线可信第三方。

**假设**：决策性 RLWE；签名 EUF-CMA；起飞前地面窗口为可信 setup 时机（与全部 DKG 文献一致的一次性假设）。

### 6.6 方案设计：闭环公式推导

**阶段 0（起飞前可信窗口）：GS 发起时隙化 DKG。** GS 预承诺哈希链 H_0=H(seed)，广播。每 UAV U_j 本地执行 n 方 DKG 的第 j 方：对每个时隙 τ=1…T（T 为任务时长上限），采样 f_j^{(τ)}(z)=s_j^{(τ,0)}+Σ_{k=1}^{t−1}f_{j,k}^{(τ)}z^k，向 U_l 发送 f_j^{(τ)}(l)。U_j 聚合得时隙份额 s_j^{(τ)}=Σ_i f_i^{(τ)}(j)，全体合成公钥 pk^{(τ)}（对应 s^{(τ)}=Σ_i f_i^{(τ)}(0)）并预置到每架 UAV。**可见性**：U_j 只见自己各时隙份额；s^{(τ)} 从不整体出现；GS 无份额（GS 不直接解密，见阶段 4）。

**阶段 1（设备加密，地面侧，公式不跳跃）。** 设备 D_i 在时隙 τ 内被 UAV 覆盖时，用 pk^{(τ)} 做 CKKS 加密并盲化。编码 Δ_i 后：

$$c_{i,0} = b^{(\tau)} v_i + e_i^0 + \lfloor\Delta\,\Delta_i\rceil + \lfloor\Delta\,\beta_i\rceil \cdot \kappa_i, \qquad c_{i,1} = a^{(\tau)} v_i + e_i^1$$

其中盲化项 ⌊Δ·β_i⌉·κ_i 以序列号 κ_i 为缩放（κ_i 为公开小整数序号），β_i ← χ 本地采样。密文 c_i=(c_{i,0}, c_{i,1}) 经空地链路上传给当前覆盖 UAV。D_i 销毁 Δ_i、v_i；β_i **保留至收到全局模型后**（阶段 5 除盲）。签名 σ_i = Sig_i(c_i‖κ_i‖τ‖H_τ)。

**阶段 2（UAV 机载加法聚合，BlindPack）。** UAV U_j 在时隙 τ 收集集合 𝒞_j^{(τ)} 后：①验签与去重（κ_i 重复则丢弃）；②仅执行加法聚合与明文标量乘（CKKS 深度 ≤1，机载可行）：

$$c_j^{(\tau)} = \textstyle\sum_{i \in \mathcal{C}_j^{(\tau)}} w_i \odot c_i, \qquad h_j^{(\tau)} = \textstyle\prod_{i \in \mathcal{C}_j^{(\tau)}} h_i^{w_i}$$

③UAV 计算**时隙份额的部分解密**并注入新鲜掩码：

$$d_j^{(\tau)} = c_{j,0}^{(\tau)} + c_{j,1}^{(\tau)} \cdot s_j^{(\tau)} + \rho_j^{(\tau)}$$

④U_j 将 (c_{j,1}^{(τ)}, d_j^{(τ)}, h_j^{(τ)}, σ-bundle, H_τ) 存入机载缓存并继续巡航。**UAV 可见性**：只见聚合密文与其份额解密，个体 Δ_i 被盲化 β_i 与 IND-CPA 双重隐藏。

**阶段 3（重叠覆盖去重）。** 若 D_i 在时隙 τ 被多架 UAV 覆盖（位置重叠），设备端仅向**信号最强**的 UAV 上传（本地决策，无需协调）；UAV 间不交换个体密文。GS 回传后按 κ_i 全局去重：重复 κ_i 的密文在解密前以盲化结构相减剔除（β_i 相同则贡献相同，去重 = 聚合时权重归一）。

**阶段 4（回传地面站与阈值合成）。** 任务段结束（或每 τ），UAV 回传缓存。GS 收到来自存活编队 𝒮（|𝒮|≥t）的 (c_{j,1}, d_j, h_j) 后：①验签、验 H_τ 链头（检测被俘 UAV 伪造时隙——哈希链断裂即暴露）；②合成各时隙聚合明文：

$$\hat m^{(\tau)} = \sum_{j \in \mathcal{S}_\tau} \lambda_j^{\mathcal{S}_\tau}\, d_j^{(\tau)} = c_{j^*,0}^{(\tau)} + c_{j^*,1}^{(\tau)}\, s^{(\tau)} + \rho^{(\tau)} \;\Rightarrow\; \textstyle\sum_{i} w_i\big(\Delta_i + \beta_i \kappa_i\big)$$

（j* 为任一回传 UAV 的密文分量；合成由份额重构性质成立。）③LHH 校验 Π_j h_j^{(τ)} 与声明一致。

**阶段 5（全局聚合与下行除盲）。** GS 对多时隙 m̂^{(τ)} 做时隙加权平均得 m̂_agg（盲化仍残留）。全局模型与聚合盲化和 Σ_i w_i β_i κ_i 一起**签名广播**下发（空中下发亦受签名保护）；设备 D_i 本地计算最终更新：

$$\Delta_{agg} = \hat m_{agg} - \textstyle\sum_i w_i \beta_i \kappa_i \;\Rightarrow\; \textstyle\sum_i w_i \Delta_i$$

除盲在设备本地完成——GS 与 UAV 全程不见未盲化的个体更新，也无需在密文上做减法（同态减法亦可，但本地除盲使 GS 无需求 β_i 明文）。新一轮时隙 τ+1 自动启用新密钥 s^{(τ+1)}，被俘 UAV 的旧份额 s_j^{(τ)} 即时作废。

### 6.7 安全性分析

**定理 1（个体更新对 UAV 保密）**：盲化 β_i 下，HBC UAV 对 Δ_i 的优势可忽略。

*证明要点*：UAV 可见 (c_i, c_j^{(τ)} 聚合, d_j^{(τ)})。盲化使明文等价于 Δ_i+β_iκ_i，β_i 均匀于 R_2 分量分布——对 UAV 而言等价于一次 OTP 于编码域（CKKS 编码域上 β_iκ_i 统计均匀覆盖 ⌊Δ·Δ_i⌉ 的低比特段，由 χ 的熵论证）；加之 c_i 本身的 RLWE-IND，双重隐藏。被俘 UAV 同理（其可见信息与 HBC 相同）。∎

**定理 2（被俘 UAV 的可控影响与可检测性）**：≤t−1 架被俘 UAV 无法合成任何时隙密钥，且其伪造行为被哈希链与签名检测。

*证明要点*：合成需 ≥t 份额（Shamir 门限）；被俘 UAV 注入错误 d_j 或伪造时隙会被 H_τ 链头校验与 σ 验签拒绝（EUF-CMA）；其掌握的 s_j^{(τ)} 在下一时隙作废（份额时效性）。∎

**定理 3（聚合正确性）**：GS 合成的 m̂^{(τ)} 与诚实聚合一致，除非 LHH 被破坏。

*证明要点*：同方案一定理 2，声明哈希 Π h_i^{w_i} 在 UAV 层与 GS 层两级校验。∎

**局限**：GS 与 ≥t UAV 合谋可解密聚合（分域管理可缓解）；设备端需保存 β_i 至下行（内存开销小）；恶意设备投毒不在本方案范围（可叠加方案四的符号统计粗筛）。

## 第 7 章 方案四：StaleHE-HFL —— 陈旧感知异步层次联邦学习（层次型：客户端—边缘—云）

### 7.1 场景

Edge-Assist 层次 FL（移动群智感知、车联网、厂区物联网）：海量移动端/传感器经多个边缘服务器（基站侧 MEC）接入，云做全局聚合。**设备异步**——电池、网络、任务优先级各异，更新到达时间差异大；数据 **non-IID** 严重（按区域/工种聚簇）；边缘与云均为半诚实。

### 7.2 要解决的问题

- **P1（G3/C6）**：异步层次 FL（AchiFL）没有任何密码学隐私；全部 HE-FL（FedSHE/PrivHFL/BPFLH…）要求同步屏障，straggler 要么拖垮整轮要么被丢弃损失数据。
- **P2（C7）**：non-IID 下需要按质量/陈旧度加权聚合，但服务器看不见明文更新，无法计算权重；让客户端自报权重又会被恶意夸大（经典自评攻击）。
- **P3**：边缘节点要执行"鲁棒过滤"（剔除投毒更新）但不可见明文——PPBR 用 CLDP 符号统计接受精度损失，PDFL 用完全可信 TA。

### 7.3 创新点与总体设计目标

- **创新点 1（总体框架）**：我们提出 StaleHE-HFL，首个**异步 + 隐私 + 层次**三者同时成立的 FL 框架：边缘"软屏障"异步聚合（到达比例 θ 即聚合），云侧只做密文加法合并，陈旧度感知加权在**客户端本地明文侧**完成——密文通路上全程只有加法与标量乘（深度 ≤1），异步性、隐私性、non-IID 加权三者解耦后重新耦合为一个闭环。
- **创新点 2（SWP 协议，Staleness-aware Weighted Packing）**：权重计算的"明文化"与"防夸大"分离：客户端本地以明文计算陈旧度/质量权重 w_i = exp(−α·age_i)·q_i（q_i 为本地验证损失），上传 w_i·Δ_i 的密文与**加密绑定的权重声明** Enc_pkE(w_i)；边缘仅解密 Σw_i（权重和，不泄露个体）用于归一化，个体权重不可见 ⇒ 服务器无法操纵权重；夸大权重被边缘侧"权重和异常检测 + CLDP 符号一致性粗筛"联合约束。权重不再依赖服务器看见明文，这条通路本身是新机制。
- **创新点 3（AsyncBarrier-HE 协议）**：边缘软屏障 + 密文跨边缘合并：每边缘在收集比例 ≥θ 时即聚合本地密文并**异步上行**；云对不同时刻到达的边缘密文做纯加法合并（CKKS 深度 0），陈旧边缘的聚合包以本地时间戳加权（明文标量乘密文）。无全局同步点，任何实体迟到不阻塞他人。
- **创新点 4（实验目标）**：MNIST/FMNIST/CIFAR-10 non-IID（Dirichlet α=0.1/0.5）上，对比 AchiFL（明文异步基线）精度差距 <1%，对比同步 HE-FL 基线在 30% straggler 下端到端时间降低 ≥40%；恶意客户端 ≤20% 时夸权攻击被抑制（聚合偏移有界）。

### 7.4 威胁模型

**实体**：客户端 {C_i}；边缘服务器 {E_1…E_M}（半诚实、互不串谋、可与少量客户端合谋）；云 CS（半诚实）；BB。

**敌手能力**：
- T1：CS 与任意单一边缘合谋（但见其他边缘密文仍不可解密个体）；边缘之间不串谋。
- T2：≤20% 客户端恶意：夸权、投毒、伪造签名；不与边缘合谋的夸权受统计检测约束。
- T3：任意 straggler 模式（到达时间任意）；边缘/客户端可随时掉线。
- T4：被动窃听者。

**安全目标**：①个体更新对 CS、其他边缘、其他客户端保密；②聚合权重不可被服务器侧操纵（权重声明加密绑定 + 权重和公开验证）；③异步推进不被任何单点阻塞；④聚合结果 LHH 可验证。

**假设**：决策性 RLWE；签名 EUF-CMA；边缘互不串谋（与 PPBR/PrivHFL 同级）。

### 7.6 方案设计：闭环公式推导

**阶段 0：边缘域密钥建立。** 每个边缘域内，边缘服务器 E 与下辖客户端执行 t-of-n DKG（同 §4.6 阶段 0 构造），合成域公钥 pk_E（对应 s_E）。CS 无密钥。可见性：E 持 s_E 门限份额（t_E 门限）；客户端持加密公钥。

**阶段 1：客户端本地加权与加密（公式不跳跃）。** C_i 在本地轮 r_i 训练得 Δ_i，计算本地验证损失 q_i（明文，自己数据），得权重 w_i = exp(−α·age_i)·exp(−β·q_i)。构造加权编码：

$$p_i = \lfloor\Delta\, w_i \Delta_i\rceil, \qquad c_i = (b_E v_i + e_i^0 + p_i,\; a_E v_i + e_i^1) = (c_{i,0}, c_{i,1})$$

即标准 CKKS 加密明文 w_i·Δ_i（权重已在编码层，服务器无需见明文权重即可聚合）。另加密权重声明：ĉ_i = Enc_pkE(⌊Δ·w_i⌉)（独立加密，供边缘做权重和检测）。签名 σ_i = Sig_i(c_i, ĉ_i, age_i, r_i)。C_i → 所属边缘 E：((c_i, ĉ_i), σ_i, meta_i=(age_i, r_i))。**meta 公开**（age 不算敏感，且检测需要），**w_i 与 w_iΔ_i 均加密**。

**阶段 2：边缘软屏障聚合与鲁棒粗筛（AsyncBarrier-HE 核心）。** 边缘 E 持续接收；当到达数 |ℰ| ≥ θ·|registered| 或超时 T_bar 时触发聚合（先到先算，不等迟到者）：①验签；②**权重和检测**：边缘门限解密（域内 t_E 份额，公式同 §4.6 阶段 4）得 Ŵ = Σ_{i∈ℰ} w_i；若 max_i w_i 声明上界 w_max 已知（公开超参），则 Ŵ ∈ [|ℰ|·w_min, |ℰ|·w_max] 外即存在夸权 ⇒ 触发细筛：③**CLDP 符号一致性粗筛**（借鉴 PPBR 但运行于边缘）：客户端上报经 CLDP 扰动的 Δ_i 符号统计 s_i（轻量 DP，ε 预算小），边缘对声明权重 top-k% 的客户端做符号分布一致性检验，不一致者降权或剔除（其密文以 0 权重参与）；④密文聚合：

$$\tilde c_E = \textstyle\sum_{i \in \mathcal{E}} c_i \;=\; \Big(\textstyle\sum_i c_{i,0},\; \textstyle\sum_i c_{i,1}\Big), \qquad \tilde h_E = \textstyle\prod_{i\in\mathcal{E}} h_i$$

边缘计算新鲜部分解密 d_E = c̃_{E,0} + c̃_{E,1}·s_E^{(share)} + ρ_E 并签名。E → CS：(c̃_{E,1}, d_E, Ŵ, h̃_E, σ_E, τ_E)。**CS 可见**：密文分量、聚合权重和 Ŵ（不泄露个体）、时间戳。**CS 不可见**：任何个体更新与个体权重。

**阶段 3：云侧异步密文合并。** CS 对陆续到达的边缘包（各自 τ_E 不同）做纯加法合并 + 时间戳衰减加权 γ_E = exp(−δ·(r − τ_E))（明文标量乘密文，深度 1）：

$$c_{glob} = \textstyle\sum_{E} \gamma_E \odot (\tilde c_{E,0},\; \tilde c_{E,1}), \qquad d_{glob} = \textstyle\sum_{E} \gamma_E \odot d_E, \qquad \hat m = d_{glob} + \text{合成项}$$

（合成细节：CS 无 s_E，因此边缘包解密采用**边缘门限直接解密制**——边缘在阶段 2 末已用域内门限把 c̃_E 解出明文 m̃_E = Σ w_iΔ_i + 噪声，再以 CS 公钥加密上传 Enc_pkCS(m̃_E)。则云合并为明文加权：m_glob = Σ_E γ_E·m̃_E。此变式让 CS 只见边缘级聚合明文，不见个体，异步合并零同态深度。两变式按边缘算力选择，本方案默认此变式。）LHH 校验 Π_E (Π_i h_i)^{γ_E}。CS 发布 m_glob 与 (ℰ_E 集合, {σ}) 于 BB。

**阶段 4：下行与本地验证。** 客户端从 BB 取回 m_glob（签名保护），更新 w。任何客户端可验：其自身贡献 h_i 是否包含于全局声明哈希（个人可验证性），防服务器漏聚合。

### 7.7 安全性分析

**定理 1（个体机密性）**：CS 与单一边缘合谋下，任一 C_i 的 Δ_i 与 w_i 对敌手优势可忽略。

*证明要点*：c_i 为 RLWE-IND 密文（边缘域公钥）；合谋敌手（CS+E）可见 m̃_E = Σ_{i∈ℰ} w_iΔ_i + 噪声（边缘级聚合，非个体）；Ŵ 为权重和。从 (m̃_E, Ŵ) 分离个体 (w_i, Δ_i) 是欠定方程组（|ℰ| 未知量、2 个标量方程），信息量论不可解；其余边缘密文敌手不可解密（域密钥独立）。∎

**定理 2（权重抗操纵）**：服务器侧无法使任一客户端权重偏离其声明 w_i，夸权攻击被检测。

*证明要点*：权重在客户端编码层（Enc(w_iΔ_i)），CS 改权重需改密文 ⇒ LHH 声明哈希失效；夸权使 Ŵ 越界或符号分布不一致 ⇒ 粗筛触发。恶意客户端夸权上界：单客户端权重贡献 ≤ w_max/Ŵ ≤ w_max/(|ℰ|·w_typ)，随 |ℰ| 增大趋零。∎

**定理 3（异步活性）**：任何客户端/边缘迟到或掉线不阻塞其他参与者完成本轮。

*证明要点*：软屏障 θ 与超时 T_bar 保证边缘局部终止；云合并随到随做；无全局屏障点。∎

**局限**：CLDP 粗筛有 DP 固有精度代价（ε 预算可调）；边缘域内合谋 ≥t_E 份额可解密该域聚合（域规模小，风险面小）；跨边缘 non-IID 聚簇由 γ_E 时间衰减近似（云不见明文聚类的代价）。

### 7.8 算法伪代码

**算法 1：StaleHE-HFL 总体执行流程**

```
输入: 客户端 {Ci}, 边缘 {E}, 云 CS, 软屏障 θ, 超参 (α, β, δ, w_max)
输出: 全局模型 w
1:  阶段0: 每边缘域 DKG → pk_E
2:  for r = 1 … R do
3:      Ci (异步, 本地轮 r_i): Δ_i ← LocalTrain;  q_i ← 本地验证损失
4:          w_i ← exp(−α·age_i)·exp(−β·q_i)
5:          c_i ← Enc_pkE(⌊Δ w_iΔ_i⌉);  ĉ_i ← Enc_pkE(⌊Δ w_i⌉)
6:          Ci → E: ((c_i, ĉ_i), Sig_i(c_i‖ĉ_i‖age_i‖r_i), meta)
7:      E: while |E| < θ·|reg| and 未超时: 接收
8:          验签;  Ŵ ← ThresholdDec(Σ ĉ_i);  assert Ŵ ≤ |E|·w_max
9:          符号一致性粗筛(CLDP);  m̃_E ← ThresholdDec(Σ c_i)
10:         E → CS: (Enc_pkCS(m̃_E), Ŵ, Πh_i, σ_E, τ_E)
11:     CS (随到随做): m_glob ← Σ_E exp(−δ(r−τ_E))·Dec(Enc_pkCS(m̃_E))
12:         LHH 校验 → BB 发布 (m_glob, 声明, 签名集)
13:     Ci: 验个人贡献;  w ← w − η·m_glob
14: return w
```

**算法 2：SWP（陈旧-质量加权打包）**

```
输入: Δ_i, age_i, q_i, 公钥 pk_E
输出: (c_i, ĉ_i, meta_i)
1: w_i ← exp(−α·age_i)·exp(−β·q_i)        // 本地明文, 权重自计算
2: c_i ← CKKS.Enc_pkE(⌊Δ·w_i·Δ_i⌉)         // 权重入编码层
3: ĉ_i ← CKKS.Enc_pkE(⌊Δ·w_i⌉)             // 权重声明(加密绑定)
4: meta_i ← (age_i, r_i);  σ_i ← Sig_i(c_i‖ĉ_i‖meta_i)
5: return (c_i, ĉ_i, meta_i, σ_i)
```

**算法 3：AsyncBarrier-HE（边缘软屏障密文聚合）**

```
输入: 边缘缓冲区 {((c_i, ĉ_i), σ_i)}, 屏障 θ, 超时 T_bar
输出: 边缘聚合包
1: while |{有效}| < θ·|reg| and elapsed < T_bar: 验签接收
2: Ŵ ← DomThresholdDec(Σ ĉ_i)               // 域内门限解密权重和
3: if Ŵ > |E|·w_max: 触发符号一致性细筛, 剔除异常密文
4: m̃_E ← DomThresholdDec(Σ c_i)             // 域内门限解密聚合
5: return (Enc_pkCS(m̃_E), Ŵ, Π h_i, Sig_E(·‖τ_E))
```

## 第 8 章 方案五：CAMASK-FL —— 覆盖协同任务绑定联邦学习（层次型：云—多 UAV—地面设备）

### 8.1 场景

多 UAV 区域覆盖与任务分配场景（CAMASK 背景）：广阔区域内分布大量地面设备，多架 UAV 按覆盖调度巡航，各自负责子区域的数据收集与边缘聚合，云做全局聚合与任务分配。低空经济典型形态：云管平台—UAV 集群—地面设备三层。挑战的叠加：覆盖调度（通信窗口短）× 训练调度（聚合轮同步）× 密钥分发（无基础设施）× 多层验证。

### 8.2 要解决的问题

- **P1（C5/G4）**：覆盖调度与训练调度完全脱节——现有 OAFL/UAV-AFL 只优化轨迹与聚合系数，窗口错过即丢更新；隐私 FL 完全不感知覆盖。
- **P2（C9）**：多层聚合（设备→UAV→云）缺乏逐层验证链，任一层篡改难以定位。
- **P3（C4/C10）**：UAV 可被俘；全局模型下行广播给覆盖区内所有设备，非授权接收机同频可截获。

### 8.3 创新点与总体设计目标

- **创新点 1（总体框架）**：我们提出 CAMASK-FL，首个**覆盖-训练协同**的层次隐私 FL：任务分配包携带密钥材料（TBKD），UAV 覆盖航迹与聚合轮次显式对齐，错过窗口的密文缓存在 UAV 机载存储中跨窗口补传（CKKS 密文可长期存储不降解），覆盖调度与收敛速度联合优化。
- **创新点 2（TBKD 协议，Task-Bound Key Distribution）**：把 Threshold CKKS 的密钥份额**嵌入覆盖任务分配包**：云为每架 UAV 的每个任务包生成份额片段，份额与 (UAV 身份, 任务包 ID, 有效窗口) 三元组绑定并签名；任务完成或窗口过期，份额即焚毁（前向安全）——密钥分发与任务调度共享同一条可信下发通道，野外无需独立 KGC 在线服务。这是"密钥分发 = 任务控制面的一部分"的新耦合（D = TBKD）。
- **创新点 3（HCVC 协议，Hierarchical Ciphertext Verification Chain）**：层级同态哈希验证链：设备签名 → UAV 验证其覆盖区聚合（LHH）并生成链上节点证明 → 云验证跨 UAV 合并。任一中间层篡改都会被下一层检出，且**定位到责任 UAV**（可审计性）。
- **创新点 4（实验目标）**：MNIST/FMNIST/SVHN + 真实覆盖轨迹模拟：覆盖率 95% 下端到端收敛轮数较"独立调度 + OAFL"降低 ≥25%；单 UAV 被俘仅影响其任务包窗口（可检测、可重派）；下行全局模型仅授权设备可解密（Threshold CKKS 模数链 [60,40,40,60]）。

### 8.4 威胁模型

**实体**：云 CS（半诚实）；UAV 集群 {U_k}（半诚实，≤t−1 可被俘为恶意）；地面设备 {D_i}；任务下发通道（云→UAV，签名保护）。

**敌手能力**：
- T1：≤t−1 架 UAV 被俘；被俘 UAV 可篡改其覆盖区聚合、伪造验证节点；可与 ≤t−1 个设备合谋。
- T2：CS 半诚实（可窥探、可操纵聚合权重，但篡改被 HCVC 检出）；CS 不与被俘 UAV 合谋解密（合谋仅见覆盖区聚合）。
- T3：任意设备掉线；覆盖窗口任意错过；同频窃听者。
- T4：任务包下发通道完整性由云签名保证（被攻破则该任务包整体失效可检测）。

**安全目标**：①个体设备更新对 UAV、CS、窃听者保密；②聚合逐层可验证且可定位；③被俘 UAV 影响限于其任务窗口；④下行模型仅授权设备可恢复。

**假设**：决策性 RLWE；Threshold CKKS 模数链 [60,40,40,60]（乘法深度 2 + 缩放余量，与 CAMASK 工程参数一致）；BLS 签名 EUF-CMA（聚合签名适配 UAV 带宽）。

| ν_k^{(τ)} | HCVC 链节点证明（UAV k 在窗口 τ 的聚合验证证据） |

### 8.6 方案设计：闭环公式推导

**阶段 0：云侧任务-密钥联合编排。** 云按覆盖调度生成窗口序列 τ=1…T 与航迹指派。对每个窗口 τ，云执行 Threshold CKKS 密钥生成：主密钥 s^{(τ)} 拆分为 n 份（t-of-n，n = 参与 UAV 数），并将**每份份额碎片化处理**：U_k 的任务包 Q_k^{(τ)} 内含 s_k^{(τ)} 的密封片段（Enc_pkUk，仅 U_k 可开）+ 有效窗口 + 航迹 + σ_CS。模数链配置 [60,40,40,60]：60-bit 首层保编码精度，40/40 支撑乘法深度 2（聚合标量乘 + 下行重加密），末层 60 保解密精度。Q → U_k：签名任务下发通道。**UAV 可见**：自己的份额片段（窗口 τ 有效）；**UAV 不可见**：完整 s^{(τ)}（<t 架合谋不可合成）。

**阶段 1：窗口内设备加密上传。** 窗口 τ 内被 U_k 覆盖的设备 D_i 用公共 pk^{(τ)} 加密（同 §6.6 阶段 1，去盲化版——本方案下行走密文，无需 β_i）：

$$c_{i,0} = b^{(\tau)} v_i + e_i^0 + \lfloor\Delta\,\Delta_i\rceil, \qquad c_{i,1} = a^{(\tau)} v_i + e_i^1, \qquad \eta_i = H(\lfloor\Delta\Delta_i\rceil)$$

D_i → U_k：(c_i, η_i, Sig_i(c_i‖η_i‖Q_k^{(τ)}.ID))。错过窗口的设备：密文在 D_i 本地缓存，下一窗口补传（设备缓存密文，明文 Δ_i 可销毁后重训）。

**阶段 2：UAV 覆盖区聚合与验证链生成（HCVC 第一层）。** U_k 验签去重后加法聚合：c_k^{(τ)} = Σ_i w_i ⊙ c_i，声明哈希 H_k^{(τ)} = Π η_i^{w_i}。U_k 计算部分解密（Threshold CKKS 份额）：

$$d_k^{(\tau)} = c_{k,0}^{(\tau)} + c_{k,1}^{(\tau)} \cdot s_k^{(\tau)} + \rho_k^{(\tau)}$$

并生成链节点证明：ν_k^{(τ)} = BLS.Sign_skCS? 不——UAV 无云私钥；ν 定义为 (Q_k^{(τ)}, H_k^{(τ)}, H(c_k^{(τ)}), τ, Sig_k(ν))，即 UAV 对"我在任务包 Q 下聚合了声明 H"的签名承诺。U_k → CS：(c_{k,1}^{(τ)}, d_k^{(τ)}, H_k^{(τ)}, ν_k^{(τ)})。**缓存语义**：若 U_k 本窗口未回传（链路中断），机载缓存保留 (c_{k,1}, d_k)，窗口 τ+1 补传——密文不过期。

**阶段 3：云侧跨 UAV 合并与验证链校验（HCVC 第二层）。** CS 收集窗口 τ 存活 UAV 集 𝒮_τ（|𝒮_τ|≥t）：①验 ν：任务包签名 σ_CS 有效（确属授权窗口）、Sig_k 有效（确由 U_k 出具）；②合成聚合明文：

$$\hat m^{(\tau)} = \sum_{k \in \mathcal{S}_\tau} \lambda_k^{\mathcal{S}_\tau} d_k^{(\tau)} = c_{k^*,0}^{(\tau)} + c_{k^*,1}^{(\tau)} s^{(\tau)} + \rho^{(\tau)} \;\Rightarrow\; \textstyle\sum_{i} w_i \Delta_i$$

③验证链闭环：全局声明 H^{(τ)} = Π_k H_k^{(τ)} 与 m̂^{(τ)} 编码一致性（LHH）；若某 U_k 的 H_k 与其实际聚合不符，云可用覆盖区设备的上行记录（η_i 已在 ν 承诺）定位责任 UAV。④跨窗口全局合并（明文加权，时间衰减）。

**阶段 4：下行密文分发（解决 C10）。** 云计算全局更新密文 c_glob（同态加权合并各窗口 c_{k,1} 分量与部分解密），广播 (c_glob, 声明) 至覆盖区。**授权设备凭其持有的下行份额**恢复：下行份额在阶段 0 由云随任务体系预置（设备注册时获得长期下行份额 s_i^{(dl)}，门限 t_d），设备本地合成：

$$\Delta_{glob} = c_{glob,0} + c_{glob,1}\cdot \textstyle\sum_{i \in \mathcal{S}_{dl}} \lambda_i s_i^{(dl)}$$

非授权同频接收机无份额，只见 RLWE 密文。新一轮窗口 τ+1 启用新密钥（前向安全）。

### 8.7 安全性分析

**定理 1（个体机密性）**：≤t−1 被俘 UAV 与 CS 合谋下，个体 Δ_i 优势可忽略。

*证明要点*：c_i 为 RLWE-IND；合谋敌手见覆盖区聚合 m̂^{(τ)} 与 <t 份额，无法合成 s^{(τ)}（Shamir 门限）；跨窗口前向安全阻止旧份额积累。∎

**定理 2（层级可验证与责任定位）**：任一层的篡改必被检出且定位到责任 UAV/窗口。

*证明要点*：设备层 η_i 签名不可伪造；UAV 层 ν_k^{(τ)} 绑定 (Q, H_k, H(c_k), τ)；云层 LHH 闭环。篡改 H_k ⇒ 与 ν_k 中承诺矛盾；伪造 ν_k ⇒ σ_CS 或 Sig_k 伪造（EUF-CMA）。∎

**定理 3（被俘 UAV 影响有界）**：被俘 UAV 仅能污染其任务包窗口的聚合，且可被检测、重派。

*证明要点*：份额与 (UAV, 任务包, 窗口) 绑定 ⇒ 越权使用无效；污染被 HCVC 检出后云重派该窗口任务（覆盖调度重优化，借鉴 CAMASK 任务分配）。∎

**局限**：云需维护任务-密钥编排（控制面开销，换取野外无 KGC）；t 与覆盖冗余度（≥t UAV 重叠覆盖）存在资源折中；设备注册时的下行份额预置依赖一次可信注册（与全部 DKG 文献同级）。

### 8.8 算法伪代码

**算法 1：CAMASK-FL 总体执行流程**

```
输入: 设备 {Di}, UAV {Uk}, 云 CS, 覆盖调度, 门限 (t, td)
输出: 全局模型 w
1:  CS: 覆盖编排 → 窗口序列 τ 与航迹;  ∀τ: 生成 s^(τ) 阈值份额
2:  CS → Uk: Q_k^(τ) = {航迹, Enc_pkUk(s_k^(τ)), 窗口, σ_CS}
3:  for τ = 1 … T do
4:      Uk 巡航覆盖: Di → Uk: (c_i, η_i, Sig_i)
5:      Uk: c_k^(τ) ← Σ w_i ⊙ c_i;  d_k ← c_{k,0}+c_{k,1}·s_k^(τ)+ρ_k
6:      Uk → CS: (c_{k,1}, d_k, Πη_i^{w_i}, ν_k^(τ)=Sig_k(Q‖H_k‖H(c_k)‖τ))
7:      (错过窗口: 机载缓存, τ+Δ 补传)
8:      CS: 验签;  m̂^(τ) ← Σ_{k∈S_τ} λ_k d_k;  LHH 闭环;  定位异常 UAV
9:      CS: 明文加权跨窗口合并 → 全局更新密文 c_glob 广播
10:     Di: 门限份额本地合成 → Δ_glob;  w ← w − η·Δ_glob
11: return w
```

**算法 2：TBKD（任务绑定密钥分发）**

```
输入: 主密钥 s^(τ), 任务包 Q_k^(τ), UAV 公钥 pkUk
输出: 密封任务包
1: s_k^(τ) ← Shamir.Share(s^(τ), k)          // t-of-n 份额
2: frag ← Enc_pkUk(s_k^(τ) ‖ Q.ID ‖ τ ‖ expiry)
3: Q_k^(τ) ← {航迹, frag, 窗口, σ_CS = BLS.Sign_skCS(Q‖frag‖τ)}
4: return Q_k^(τ)                            // 窗口过期即焚毁 frag
```

**算法 3：HCVC（层级密文验证链）**

```
输入: 设备声明 {η_i, Sig_i}, UAV 链节点 {ν_k^(τ)}
输出: accept / 定位异常
1: ∀i: assert Verify(Sig_i, c_i‖η_i‖Q.ID)      // 设备层
2: ∀k: assert Verify(σ_CS, Q‖frag‖τ) ∧ Verify(Sig_k, ν_k)   // UAV层
3: assert H(m̂^(τ)) == Π_k H_k^(τ) == Π_k Π_i η_i^{γw_i}     // 云闭环
4: if ∃k 链节点矛盾: return (reject, 定位 Uk, 窗口 τ)      // 责任定位
5: return accept
```

| 闭环推导无跳跃 | ✔ §4.6 五阶段 | ✔ §5.6 四阶段 | ✔ §6.6 五阶段 | ✔ §7.6 四阶段 | ✔ §8.6 四阶段 |

**推导过程中的否决记录（回应"推倒现有推论，从第 1 步重新推导"的要求）**：
1. 方案一初版采用"服务器公钥代管全部解密"：检验发现服务器拿 t 份可重建合成密钥 ⇒ 违反无 TTP 目标 ⇒ 否决，改为"份额新鲜掩码 + 服务器仅合成不持钥"。
2. 方案二初版为"单密钥 + HEFLGuard 式分组验证"：检索确认与 HEFLGuard（TIFS'26）机制等价 ⇒ 否决，引入分量密钥使服务器可被攻陷。
3. 方案三初版为"起飞前一次静态阈值 CKKS（同 PPDO）"：不满足被俘失效 ⇒ 否决，引入时隙化 AeroDKG。
4. 方案四初版为"边缘解密后明文加权上传"：与 PEFL 的 TTHE 边缘信任模型等价 ⇒ 部分否决，保留边缘仅解密 Σw（权重和）与边缘级聚合，个体权重不出域。
5. 方案五初版"覆盖调度与密钥分发独立两条通道"：野外双通道不可维护 ⇒ 否决，合并为 TBKD 单通道。

### 9.4 后续工作建议

1. **恶意模型扩展**：五个方案均以 HBC + 可验证构件防篡改；主动恶意客户端的投毒（非后门类）统一防御需要跨方案的组合验证框架。
2. **MKHSS 引入**：26-MKHSS（S&P'26）的独立密钥 + 非交互编码有望替换 ATV-FL 的 MK-CKKS 层，进一步压缩密钥协商成本。
3. **HHE 化客户端**：方案三/五的地面设备可引入 PASTA 式转译（25-HHE）把客户端加密成本再降数量级，代价是云端转译算力。
4. **统一实验基准**：建议在 MNIST/FMNIST/CIFAR-10/SVHN 上建立"掉线率 × 合谋数 × 精度"三维基准，与 CDKS-LSS、ESAFL、AchiFL、PPDO 对齐可比。
