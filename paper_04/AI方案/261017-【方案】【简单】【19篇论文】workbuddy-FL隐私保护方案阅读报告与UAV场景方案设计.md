### 1.2 各方案一句话画像

- **SecAgg'17**：双掩码+Shamir 的奠基之作——服务器只见"和"，抗掉线，但不验证输入良构性、不追责、恢复轮贵。
- **CDKS'19**：把 CKKS 升级为多密钥（各客户端独立密钥），是后续一切 MK-CKKS-FL 的原语底座；本身不解 FL 的掉线与交互问题。
- **ELSA'23**：双服务器分布式信任下，客户端当"不可信经销商"，用 OT/Beaver 关联在恶意服务器下同时拿隐私+ℓ2 范数界（首个把抗投毒做进恶意安全聚合的高效方案）。
- **SecFed'24**：借 TEE 把"多密钥"做成密钥拆分，快但整个安全性押在 SGX 上，且每个用户都持有等价主密钥（sk_i+rk_i=secret）。
- **ResFed'24**：纯通信效率论文（残差预测编码），零密码——提醒我们"安全聚合"与"通信压缩"两条线需要正交组合。
- **BPVFL'24**：Paillier+线性同态哈希+三方 ZKP，双向可验证且容忍 N−1 掉线，但逐元素 Paillier 在高维模型下通信昂贵、不防投毒。
- **ESAFL'25**：多加密钥+共享解密钥（s=Σsᵢ）实现单步本地解密、无需逐轮协商，效率逼近单密钥；代价是**完全不防掉线**（少一个密文就解不开）。
- **FedPHE'25**：打包 CKKS+LSH 草图做贡献感知加权与掉队回避，KDC 全可信，不防投毒。
- **MASER'25**：多数投票共识剪枝+切片，把 MK-CKKS 开销压低 3–8 倍；但服务器看得到聚合明文、无掉线容忍。
- **MaskCrypt'25**：只加密 20% 权重（梯度引导选掩码），通信降 4 倍，但安全性是"经济性/启发式"的，未加密部分暴露。
- **ProFL'25**：双服务器 Paillier 下做安全中位数+曼哈顿距离，拜占庭鲁棒且适配 Non-IID；AGG/SP 必须不合谋。
- **PrivHFL'25**：把 tMK-CKKS 三份额密钥（用户/边缘/云 2/3 阈值）嵌入 HierFAVG 三层架构，是本批文献中最典型的"密码原生层次 FL"。
- **SKHE'25**：单密钥 CKKS 高效但怕合谋——用 ECC 加密私钥+份额托管给边缘节点+TEE 哈希校验后才解密，信任锚重（TA+TEE）。
- **VeSAFL'25**：Pedersen VSS+BLS+公告板，多聚合服务器、恶意模型、可追责；不用 HE，配对运算贵。
- **CDKS-LSS'26**：把 Shamir 做在环 R_q 上（Exceptional Sequence），直接修补"朴素 CDKS 部分解密泄露个体明文"的攻击，无 TTP、收齐 t 份即解密；但 P2P 份额互发通信 O(N²)、仅半诚实。
- **FedOut'26**：ECMK-CKKS 单步解密+盲化外包加密给代理服务器+补充密文防掉线，适合资源受限 IoT；KDC 全可信、AS 与 Proxy 不得合谋。
- **DSVFL'26**：阈值 Paillier+Ftop-k 压缩+TA 每轮验证聚合签名，GS 可以是恶意的；代价是 TA 必须每轮在线。
- **PPBR'26**：EHFL 三层下 CLDP 符号统计聚类+PLHE 密文范数筛选+SecAgg 混合，Non-IID 下抗高级拜占庭攻击；DP 噪声损精度、SA 有 O(n²) 项。
- **VLSFL'26**：一次 setup 多轮复用的双掩码+同态哈希/配对验证，单服务器、轻量、防合谋掉线；但不防投毒、Non-IID 未解决、TA 分发全部密钥。

## 第 2 章 模式分类总结

### 2.1 按密钥体制分（三大谱系）

**(A) 掩码/秘密共享系（无 HE）**：SecAgg、ELSA、VeSAFL、VLSFL、PPBR(部分)。
- 优点： plaintext 域运算，速度快、无密文膨胀；VLSFL 证明一次 setup 可多轮复用。
- 缺点：逐轮交互（SecAgg 4 轮）；防投毒要靠额外的范数证明（ELSA）或明文统计（PPBR 的 DP 符号统计）；聚合结果必然对某方可见。

**(B) 单密钥同态系**：BPVFL、ProFL（Paillier）、SKHE、FedPHE（CKKS）。
- 优点：结构最简单、服务器纯加法聚合零深度。
- 致命弱点：**私钥只有一个持有者或全员共享**——要么引入半诚实验证服务器（BPVFL 的 S1）、要么 KGC/TEE/TA 托管（SKHE、FedPHE），客户端合谋即崩塌。SKHE 的 ECC 托管+TEE 哈希校验本质是在给单密钥体制"打信任补丁"。

**(C) 多密钥/阈值同态系（MK-CKKS 谱系）**：CDKS → MASER → ESAFL → FedOut → CDKS-LSS；阈值变体 PrivHFL、DSVFL。
- 优点：每客户端独立密钥，天然抗客户端互窥，抗量子（RLWE）。
- 核心矛盾：**分布式解密需要全员在线（CDKS/MASER/ESAFL）vs 阈值化又需要可信机构或 P2P 份额交换（PrivHFL 靠 KGC，CDKS-LSS 靠 O(N²) P2P）**。这个矛盾正是演进的主线（见第 3 章）。

### 2.2 按架构分

| 架构 | 方案 | 特征 |
|------|------|------|
| 标准FL·单服务器 | SecAgg, SecFed, ResFed, ESAFL, FedPHE, MASER, MaskCrypt, CDKS-LSS, VLSFL, FedOut, DSVFL | 结构最简单；信任集中在服务器，需要掩码/HE 把服务器"蒙眼" |
| 标准FL·双服务器 | ELSA, BPVFL, ProFL | 分布式信任：两台服务器不合谋即可换恶意安全或验证能力；无 TTP |
| 多服务器/公告板 | VeSAFL | 区块链式公告板做信任锚，可追责 |
| **层次FL（边缘聚合）** | **PrivHFL, PPBR, SKHE(云-边)** | 仅 3 篇！且没有一篇同时做到：无在线 TA + 恶意模型 + 防投毒 + 掉线容忍 |
| 外包代理 | FedOut | 把加密算力外包给代理，IoT 友好 |

**关键观察：层次型 FL（HFL）的密码学工作明显稀缺**——21 篇里只有 3 篇，且 PrivHFL 依赖 KGC+全实体 HBC，PPBR 依赖 DP 牺牲精度，SKHE 依赖 TA+TEE 双锚。"HFL × 恶意模型 × 无在线可信机构 × 掉线容忍 × 防投毒"的交集是**空白区**。

### 2.3 按可信机构分

- **完全无 TA**：SecAgg(半诚实版)、ELSA、MaskCrypt、PPBR、CDKS-LSS。
- **公告板/PKI 弱信任**：SecAgg(恶意版)、VeSAFL。
- **离线 TA（仅初始化）**：ESAFL(AS)、PrivHFL(KGC)、VLSFL(TA)、FedOut(KDC)。
- **在线/重信任锚**：FedPHE(KDC 每 τ 轮)、DSVFL(TA 每轮验证)、SecFed(TEE)、SKHE(TA+TEE)、ProFL(KGC 发钥)。

趋势清晰：**越早的工作越依赖在线可信机构，越新的工作越把 TA 压缩到"仅初始化"甚至消除**——因为在线 TA 既是单点故障也是合谋靶点。但代价是信任被转移到了别处（双服务器不合谋假设、P2P 份额交换的通信开销）。

### 2.4 按威胁模型分

- **半诚实(HBC) 全员**：ESAFL、FedPHE、MASER、SecFed、SKHE、PrivHFL、FedOut、CDKS-LSS（多数派）。
- **恶意服务器**：ELSA(一台)、BPVFL(S0)、DSVFL(GS)、VLSFL(可被控制)、VeSAFL(≤k−1 台)。
- **恶意/拜占庭客户端（投毒）**：ELSA(ℓ2界)、ProFL(中位数+MHD)、PPBR(聚类+范数筛选)、MaskCrypt(成员推断)、MASER(掩码共识)。
- **掉线容忍**：SecAgg、ELSA、BPVFL、VeSAFL、CDKS-LSS、FedOut、DSVFL、PPBR、VLSFL、SKHE、SecFed、PrivHFL（约 2/3）；**不防掉线**：ESAFL、FedPHE、MASER、MaskCrypt、ProFL。

## 第 3 章 演进脉络推理（技术谱系）

这一章回答一个问题：**这些方案为什么以这个顺序出现？每一个新方案到底修补了前一个的哪条裂缝？** 沿三条主线推理。

### 3.1 主线一：掩码系 —— "交互轮数与信任的拉锯"

```
SecAgg'17 ──(每轮4轮交互太贵; 不验结果)──▶ VLSFL'26
    │                                          │
    │(单服务器天然不可信;                       │(一次setup多轮复用,
    │ 恶意服务器可伪造聚合)                      │ 同态哈希+配对验证)
    ▼                                          ▼
ELSA'23 (双服务器换恶意安全, 顺带ℓ2界防投毒)   残留问题: 不防投毒,
VeSAFL'25 (多服务器+公告板, 可追责可验证)      TA分发全部密钥, Non-IID未解
```

- **SecAgg 留下的三个洞**：① 每轮都要重新跑密钥协商+份额分发（4 轮交互）；② 服务器说"聚合结果=z"客户端只能信；③ 恶意客户端可以注入越界向量污染和（不验输入良构性）。
- **ELSA 补洞①③的一半**：用双服务器替代单服务器，客户端发完一轮就离线（one-shot），ℓ2 范数界挡住范数投毒；但引入"两服务器不合谋"假设，且只支持逐客户端独立的防御（Krum/trimmed mean 做不了）。
- **VLSFL 补洞①②**：全连接图参数复用把 setup 摊销到多轮，同态哈希+配对让客户端验证聚合；**但它退回了半诚实+不防投毒**，且 TA 掌握所有密钥——这是它相对 ELSA 的退步。
- **VeSAFL 走另一条路**：不要 HE、不要 TA，用公告板+VSS+BLS 换恶意模型下的可追责；但配对运算贵，节点侧 O(n(v+s))。

**主线一的未解裂缝**：能否有一个方案**同时**具备——多轮复用（VLSFL）、恶意服务器下的验证（VeSAFL/VLSFL）、抗投毒（ELSA）、且 TA 不掌握密钥？→ 这是**方案一**的动机。

### 3.2 主线二：MK-CKKS 系 —— "解密环节是阿喀琉斯之踵"

```
CDKS'19 (MK-CKKS 原语)
    │
    │ 攻击1: 分布式解密时, 服务器拿 (c_{i,0}, μ_i) 可算 c_{i,0}+μ_i ≈ m_i
    │        ——部分解密直接泄露个体明文!
    ▼
xMK-CKKS (公钥聚合 pk=Σpk_i, 混合解密)
    │
    │ 攻击2: 解密需全员在线, 一人掉线→整个解密失败(解密钥缺一份)
    ▼
两条分叉:
    │
    ├─▶ CDKS-LSS'26: 把 μ_i 用 Shamir(环上 Exceptional Sequence) 再秘密共享,
    │    服务器收齐任意 t 份聚合份额即可重构 → 阈值化+掉线容忍+无TTP
    │    残留: 份额 P2P 互发 O(N²) 通信; 仅半诚实; 服务器可见聚合明文
    │
    ├─▶ ESAFL'25: 干脆避开份额分发——解密钥 s=Σs_i 初始化时定死,
    │    每轮 PRG 刷新随机多项式 a_t, 单步本地解密, 无需逐轮协商
    │    残留: 完全不防掉线(少一份密文就解错); 静态 s 是长期秘密
    │
    ├─▶ FedOut'26: 保留单步解密, 把加密外包给代理+补充密文补掉线者
    │    残留: KDC 全可信+AS/Proxy 不合谋双假设; 总流量反而更大
    │
    └─▶ SecFed'24 / MASER'25: 用 TEE 或共识剪枝压缩开销
         残留: TEE 信任锚 / 服务器见聚合明文+无掉线容忍
```

**关键推理链**（正是用户举例的展开）：

1. **MK-CKKS(CDKS) 的解密份额上传有安全风险**：部分解密 μ_i = c_{i,1}·s_i 与公开的 c_{i,0} 相加即得个体明文 m_i（CDKS-LSS 论文明确给出此攻击）。
2. **xMK-CKKS 用聚合公钥 pk=Σpk_i 修补**：个体密文混合在一起，但代价是**解密需要全体私钥在线**——一人掉线，全局解密失败。
3. **CDKS-LSS 对解密份额再做一次秘密共享**：μ_i 作为常数项造 t−1 次多项式，份额互发，服务器收齐 t 份聚合份额即 Lagrange 重构——阈值与掉线容忍同时获得，且环上 LSS 保证信息论安全、无需 TTP。**但 P2P 份额互发在 N 大时是 O(N²) 通信灾难**（20 人每轮约 109MB/人），这在 UAV 弱链路下不可接受。
4. **ESAFL 换了个思路根治份额问题**：压根不做逐轮分布式解密——解密钥 s=Σs_i 初始化即固定，客户端本地单步解密。效率逼近单密钥，**但结构性地无法容忍掉线**（C_t 缺一份 c_i 时，a_t·s 项消不掉）。
5. **FedOut 把 ESAFL 的单步解密 + 补充密文拼起来**：掉线者由代理补零密文，维持 a_t·s 消除；但引入 KDC 全可信+双服务器不合谋。

**主线二的未解裂缝**：能否做到——CDKS-LSS 的阈值掉线容忍 + ESAFL 的单步解密 + **不要 O(N²) P2P**、**不要全可信 KDC**、**加上结果可验证**？→ 这是**方案二**的动机。

### 3.3 主线三：层次 FL 系 —— "三层架构的密码学刚刚起步"

```
HierFAVG (明文层次聚合, 无隐私)
    │
    ├─▶ HFL-DP 类: 加噪保隐私, 但精度损+不防合谋
    │
    ├─▶ PrivHFL'25: tMK-CKKS 三份额(用户/边缘/云, 2/3阈值)
    │    首次把阈值MKHE嵌入HFL; 边缘人数下限防同组合谋
    │    残留: KGC 知一切份额; 全实体仅HBC; 不防投毒;
    │          组内用户共用同一份额(同组用户=同一密钥, 粒度粗)
    │
    ├─▶ SKHE'25: 云-边两级, 单密钥CKKS+ECC私钥份额托管给边缘+TEE校验
    │    残留: TA+TEE 双信任锚; ECC层不抗量子; 不防投毒
    │
    └─▶ PPBR'26: EHFL + CLDP符号统计聚类 + PLHE密文范数筛选 + SecAgg
         唯一认真做"HFL+拜占庭鲁棒"的工作
         残留: DP噪声损精度; SA有O(n²); 云最终见去噪动量明文;
               范数筛选需要边缘协助解密(半诚实假设链很长)
```

**层次 FL 的三个结构性难题**（标准 FL 没有的）：

1. **边缘节点是新的攻击面**：它既不是客户端也不是最终聚合者——看得到本域密文、可能协助部分解密（PrivHFL 里边缘持 1/3 份额）。边缘被攻破或与云合谋怎么办？
2. **两级聚合=两级信任传递**：客户端→边缘的隐私保护（如掩码）与边缘→云的保护（如阈值 HE）往往是两套机制的拼接，拼接缝（边缘解密/再加密的那一刻）是最脆弱的。SKHE 把这个缝塞进 TEE，PrivHFL 用 2/3 份额，PPBR 用盲化因子——**没有一个是干净的**。
3. **UAV 场景放大一切**：边缘节点（UAV/地面站）本身高动态、会掉线、链路带宽受限；同一边缘域内设备数少（一个 UAV 集群可能就 5–20 架），PrivHFL 的"≥⌈j/2⌉+1 人数下限"在小集群里形同虚设。

**主线三的未解裂缝**：HFL 下同时满足 无在线TA + 边缘掉线容忍 + 防投毒 + 可验证 + 不损精度 的方案不存在。→ 这是**方案三、四、五**的动机。

### 3.4 横向规律总结

1. **信任的转移守恒**：去掉一个 TA，信任不会消失，只会转移——转移到双服务器不合谋假设（ELSA/BPVFL/ProFL）、公告板（VeSAFL）、TEE（SecFed/SKHE）、或 P2P 通信代价（CDKS-LSS）。设计新方案时要明确声明"信任被转移到了哪里"。
2. **掉线容忍的三种实现**：阈值秘密共享（SecAgg/CDKS-LSS/DSVFL）、补充密文（FedOut/SecFed）、解密钥固定化（ESAFL——以完全不防掉线为代价的反面教材）。
3. **可验证性的两条技术路线**：同态哈希+配对（BPVFL/VLSFL/DSVFL）vs 秘密共享+承诺+签名（VeSAFL/ELSA）。前者轻量但通常需要 TA 发哈希密钥，后者重但可无 TA。
4. **防投毒与隐私的本质冲突**：鲁棒聚合（中位数/裁剪/聚类）需要"看到"更新才能判断异常，而隐私要求"看不到"。已有出路只有三条：ℓ2 范数界证明（ELSA，不暴露方向只限制能量）、DP 扰动后的粗粒度统计（PPBR，损精度）、密文上安全比较（ProFL，双服务器）。**密文域鲁棒聚合是最难也最值得做的点**。

## 第 4 章 UAV 场景的挑战与值得研究的点

### 4.1 UAV-FL 的两类典型部署形态

**形态 A：UAV-Assist（UAV 当客户端）**——多架 UAV 各自采集数据（航拍、传感），作为 FL 客户端；地面站(GS)/云做聚合。特点：客户端数量少（几架到几十架）、数据 Non-IID 严重（航线不同）、单架数据量大。

**形态 B：Edge-Assist / UAV-as-Edge（UAV 当边缘节点）**——大量地面 IoT 设备 → UAV 中继/边缘聚合 → 云。UAV 提供覆盖与算力。特点：UAV 高动态（电量、链路、任务切换导致频繁"掉线"）、空地链路带宽受限且不对称、单 UAV 覆盖域内设备数有限。

**形态 C（混合）：集群分层**——多个 UAV 集群，集群内簇头聚合 → 卫星/地面骨干跨集群聚合 → 云。天然的三层 HFL。

### 4.2 挑战清单（与挑战→密码需求的映射）

| # | UAV 场景挑战 | 对安全聚合的具体要求 | 现有方案缺口 |
|---|--------------|----------------------|--------------|
| C1 | **高动态掉线**：电量耗尽/飞出覆盖/任务切换，掉线率可达 30%+ | 阈值化解密/掩码恢复（SecAgg 式）或补充密文（FedOut 式） | ESAFL/FedPHE/MASER/MaskCrypt/ProFL 均不防掉线 |
| C2 | **带宽受限且不对称**：空地链路窄，上行宝贵 | 打包 CKKS+稀疏化（MASER/FedPHE）；掩码系零膨胀（VLSFL） | CDKS-LSS 的 O(N²) P2P 份额在 UAV 下不可用 |
| C3 | **算力受限**：机载嵌入式平台 | 外包加密（FedOut）、轻量掩码、低深度密文（只做加法） | Paillier 逐元素加密（BPVFL/DSVFL/ProFL）太重 |
| C4 | **小规模集群**：单域 5–20 客户端 | 阈值 t 与合谋界要在小 N 下仍有意义 | PrivHFL 的"组内合谋<1/2"在 5 架集群里只剩 2 架余量 |
| C5 | **恶意地面站/云**：基础设施可能被控制 | 结果可验证（同态哈希/签名链） | SecAgg/ESAFL/FedOut/CDKS-LSS 都不可验证 |
| C6 | **数据投毒**：被劫持 UAV 注入恶意更新 | ℓ2 界/密文范数筛选/鲁棒加权 | 仅 ELSA/PPBR/ProFL 认真处理，且都不适配 HFL+UAV |
| C7 | **Non-IID 极端化**：航线决定数据分布 | 鲁棒聚合+公平加权（《加权方式》第3/4/7类） | VLSFL 明示 Non-IID 未解；PPBR 用 DP 换鲁棒损精度 |
| C8 | **信任锚难落地**：野外场景没有稳定在线 TA | TA 仅初始化即离线，或彻底无 TA | DSVFL 的 TA 每轮在线、FedPHE 的 KDC 每 τ 轮在线均不可行 |
| C9 | **设备物理俘获**：UAV 被俘获即密钥泄露 | 前向安全的密钥演进；阈值化使单点俘获无害 | 几乎所有方案假定密钥静态 |

### 4.3 值得研究的点（→ 五个方案的选题依据)

- **R1（→方案一）**：标准 FL 单服务器下，把 VLSFL 的"多轮复用+可验证"与 ELSA 的"范数界防投毒"合并，且 TA 不掌握任何密钥（DKG 替代）——**轻量、可验证、抗投毒、防选择性掉线**的 UAV 群 FL。
- **R2（→方案二）**：MK-CKKS 系里，用**双服务器中继份额**替代 CDKS-LSS 的 P2P O(N²)，保留阈值掉线容忍，加签名审计——适配 UAV 弱链路。
- **R3（→方案三）**：HFL 三层（机群–簇头–云）下，**无 KGC** 的分布式阈值 MK-CKKS + 共识剪枝降通信，解决 PrivHFL 的 KGC 信任与粗粒度份额问题。
- **R4（→方案四）**：UAV-as-Edge 形态下，边缘（UAV）本身会掉线——**跨边缘份额托管+补充密文+签名链**，让"边缘掉线"这个 HFL 独有问题首次被密码学地解决。
- **R5（→方案五）**：EHFL 下不依赖 DP 的**密文域拜占庭鲁棒聚合**——承诺+范数界+鲁棒加权，保精度地防投毒，补 PPBR 的精度缺口。

## 第 5 章 五个新方案设计

> 公共约定：所有方案中，"⌀ 可见/✗ 不可见"均指密码学意义上的不可区分性（IND-CPA 或信息论）。RLWE 记号统一：环 $R_q=\mathbb{Z}_q[X]/(X^N+1)$，$N$ 为 2 的幂；$\chi_s,\chi_e$ 为密钥/噪声分布；CKKS 编码 $z=\mathrm{Ecd}(\mathbf{m};\Delta)$、解码 $\mathbf{m}=\mathrm{Dcd}(z;\Delta)$，缩放因子 $\Delta$。

---

### 方案一：AeroMask —— UAV 机群的可验证防投毒轻量安全聚合（标准 FL · 单服务器 · 掩码系）

#### 5.1.1 场景

某应急测绘任务：$n=200$ 架 UAV（UAV-Assist 形态 A）各自采集辖区影像，在机载平台本地训练目标检测模型，每轮把模型更新上传给**唯一一台地面站聚合服务器 AS**。UAV 为注册设备（有身份），链路窄带、野外无稳定在线可信机构，掉线率可达 30%。地面站可能被入侵（需防聚合结果被篡改），被俘获的 UAV 可能发起投毒（需事后可追责）。

#### 5.1.2 要解决的问题

VLSFL'26 已做到"单服务器+多轮复用+掉线容忍+可验证"，但存在三个缺口：
1. **TA 掌握全部密钥**（同态哈希密钥、PRF 密钥、两对 DH 密钥均由 TA 生成）——TA 一旦泄露，全盘皆输；
2. **不防选择性掉线攻击**：恶意 AS 可以在 Unmasking 阶段谎称某诚实客户端掉线（或选择性转发份额），从聚合结果中剥离/隔离目标客户端的更新（SecAgg 论文第 7 节已指出此类攻击在稀疏掩码图下成立，VLSFL 的参数复用图同样受影响）；
3. **完全不防投毒**：恶意 UAV 注入越界向量即可污染聚合结果，无任何界约束与追责手段。

#### 5.1.3 创新点 / 总体设计目标

1. **TA 最小化**：TA 退化为纯"注册公告牌 + 公共参数发布者"，**不生成、不掌握任何掩码/哈希密钥**——掩码密钥由客户端间 ECDH 产生，验证密钥由全体客户端 DKG 式联合生成（§5.1.6 步骤 0）。
2. **先承诺存活列表，后揭示份额（Commit-then-Reveal）**：AS 必须在收到任何恢复份额**之前**，对本轮在线列表 $U$ 签名承诺；事后若被发现"谎报掉线"，签名即铁证，触发追责。这把 VLSFL 中"AS 可单方面定义谁掉线"的漏洞堵死。
3. **承诺绑定 + 审计追责的轻量防投毒**：客户端上传掩码更新时附 Pedersen 向量承诺与平方范数承诺；正常轮零开销，聚合异常（训练损失不降反升）时触发**审计轮**，被抽审客户端开示承诺自证，无法开示或开示不符者被驱逐并吊销注册。以"事后追责"替代昂贵的逐轮 ZK 范数证明，换取 UAV 可行的轻量性。

#### 5.1.4 威胁模型

| 实体 | 假设 | 能力上限 |
|------|------|----------|
| TA | 诚实、**仅初始化在线**、不保存任何会话密钥 | 只做公钥注册与参数发布 |
| AS（地面站） | **恶意**：可篡改/伪造聚合结果、可谎报掉线、可与 ≤t−1 个客户端合谋 | 不能伪造 AS 自己的签名密钥之外的签名；受 Commit-then-Reveal 与哈希验证约束，作恶必留证 |
| UAV 客户端 | ≤t−1 个可被腐蚀（与 AS 合谋）；其中恶意者可投毒 | 被腐蚀者泄露自己一切；诚实者密钥安全 |
| 合谋界 | AS + ≤t−1 客户端合谋时，诚实客户端个体更新保密 | 聚合结果至少含 ≥2 个诚实客户端贡献时才公开 |
| 掉线 | 任意时刻掉线，在线 ≥t 即可正确聚合 | — |

实体可见性：AS ⌀ 掩码后向量、聚合明文 $z$、承诺值；✗ 任何个体 $x_i$、任何掩码种子。客户端 ⌀ 全局模型、验证证明；✗ 他人更新。TA ⌀ 公钥；✗ 一切会话秘密。

#### 5.1.5 符号系统

| 符号 | 含义 |
|------|------|
| $U_i,\ i\in[n]$ | UAV 客户端；$x_i\in\mathbb{Z}_R^d$ 为量化后的本地更新（整数域 $\mathbb{Z}_R$） |
| $AS$ | 聚合地面站；$(sk_{AS},pk_{AS})$ 为其签名密钥对 |
| $\mathbb{G}=\langle g\rangle$（阶 $p$）、$h$ | Pedersen 承诺群，$\log_g h$ 未知 |
| $\mathrm{Com}(v;\rho)=g^v h^\rho$；$\vec{\mathrm{Com}}(\mathbf{x};\boldsymbol{\rho})=\prod_j \mathrm{Com}(x_j;\rho_j)$ | 标量/向量 Pedersen 承诺 |
| $s_{ij}=s_{ji}=\mathrm{ECDH}(sk_i^{(d)},pk_j^{(d)})$ | 成对掩码种子（DH 协商） |
| $b_i$ | 自掩码种子；$\mathrm{PRG}:\{0,1\}^\lambda\to\mathbb{Z}_R^d$ |
| $\mathrm{SS}.\mathrm{Share}(v,t,U)$ / $\mathrm{SS}.\mathrm{Rec}(\cdot)$ | Shamir $(t,|U|)$ 秘密共享 / 重构 |
| $\mathrm{HF}(\mathbf{x})=\prod_j h_j^{x_j}\bmod P$ | 线性同态哈希（密钥 $\{h_j\}$ 由 DKG 生成，见下） |
| $e:\mathbb{G}_1\times\mathbb{G}_2\to\mathbb{G}_T$ | 双线性配对（BLS 签名与验证等式用） |
| $\sigma_i=\mathrm{BLS}.Sign_{sk_i}(m)$ | BLS 短签名 |

#### 5.1.6 方案设计（闭环公式推导）

**步骤 0 · 一次性 Setup（TA 仅做公告牌）**

1. TA 发布公共参数 $pp=(\mathbb{G},g,h,P,\{H_k\},\mathrm{PRG},t)$，并为每架注册 UAV 登记身份公钥 $(pk_i^{(d)},pk_i^{(s)})$（DH 公钥、BLS 公钥）于公告板。**TA 至此永久离线。**
2. 同态哈希密钥 DKG：每个 $U_i$ 随机选 $\alpha_{ij}\xleftarrow{\$}\mathbb{Z}_p$，广播承诺 $g^{\alpha_{ij}}$；公开后全体计算哈希密钥 $h_j=\prod_i g^{\alpha_{ij}}=g^{\sum_i\alpha_{ij}}$。**无任何单方知道 $\log_g h_j$**——这即"验证密钥不由 TA 掌握"的实现。
3. 掩码图复用（VLSFL 思想）：由公开随机串 $v$ 与 $\mathrm{GenGraph}(v,t,n)$ 生成连通图 $G$，多轮复用；$U_i$ 对 $b_i$ 与 $sk_i^{(d)}$ 做 $\mathrm{SS}.\mathrm{Share}(\cdot,t,U)$，密化份额存于 AS（每个份额用对应邻居的 ECDH 密钥 AE 加密）。

**步骤 1 · 每轮上传（客户端侧）**

$U_i$ 本地训练得 $x_i$，计算：

$$\hat{x}_i = x_i + \mathrm{PRG}(b_i) + \sum_{j\in N(i)}\sigma_{ij}\cdot\mathrm{PRG}(s_{ij})\pmod R,\qquad \sigma_{ij}=\begin{cases}+1,&i<j\\-1,&i>j\end{cases}$$

同时计算三个绑定物：

$$C_i=\vec{\mathrm{Com}}(x_i;\boldsymbol{\rho}_i),\quad V_i=\mathrm{Com}\!\left(\|x_i\|^2\text{ mod }p\,;\,\rho_i'\right),\quad \sigma_i=\mathrm{BLS}.Sign_{sk_i}\!\left(\hat{x}_i\,\|\,C_i\,\|\,V_i\,\|\,r\right)$$

上传 $(\hat{x}_i,C_i,V_i,\sigma_i)$。**承诺的意义**：$x_i$ 从此被密码学绑定，事后审计时无法抵赖篡改。

**步骤 2 · AS 先承诺在线列表（Commit-then-Reveal，防选择性掉线）**

AS 收齐上传后，**先**计算并广播 $\Sigma_{AS}=\mathrm{BLS}.Sign_{sk_{AS}}(U\,\|\,r\,\|\,H(\{\hat{x}_i\}_{i\in U}))$，其中 $U$ 为其声称的在线集合。只有在该签名广播**之后**，AS 才允许收集恢复份额。若 AS 事后想改口（把 $i\in U$ 说成掉线），$\Sigma_{AS}$ 即为矛盾证据。

**步骤 3 · 掉线恢复与去掩码**

设最终存活集 $U_3$（$|U_3|\ge t$）。对 $j\notin U_3$：在线者交出 $s_{jk}$ 相应份额，AS 重构 $s_{jk}$ 与 $b_j$，剥离其掩码；对 $i\in U_3$：在线者交出 $b_i$ 份额（每客户端对同一目标只交一种份额，SecAgg 规则）。AS 计算：

$$z=\sum_{i\in U_3}\hat{x}_i-\sum_{i\in U_3}\mathrm{PRG}(b_i)-\sum_{(i,j):\,j\notin U_3}\sigma_{ij}\mathrm{PRG}(s_{ij})=\sum_{i\in U_3}x_i\pmod R$$

**正确性（闭环检验）**：成对项中每条边 $(i,j)$ 两端均存活时，$+\mathrm{PRG}(s_{ij})$ 与 $-\mathrm{PRG}(s_{ij})$ 在和中相消；一端掉线时由重构的 $s_{ij}$ 显式剥离；自掩码由 $b_i$（存活者重构、掉线者随掩码整体剥离）消除。故 $z$ 恰为存活者更新之和，无残余项。∎

**步骤 4 · 聚合正确性验证（同态哈希 + 配对）**

AS 公布证明 $\Pi=\{A,B\}$：$A=\prod_{i\in U_3}\mathrm{HF}(\hat{x}_i)$、$B$ 为剥离掩码分量的配对见证。客户端本地验证：

$$\mathrm{HF}(z)\ \stackrel{?}{=}\ \prod_{i\in U_3}\mathrm{HF}(\hat{x}_i)\cdot\prod_{i\in U_3}\mathrm{HF}(\mathrm{PRG}(b_i))^{-1}\cdot\!\!\prod_{j\notin U_3}\!\!\mathrm{HF}\!\Big(\sum_i\sigma_{ij}\mathrm{PRG}(s_{ij})\Big)^{-1}$$

由 $\mathrm{HF}$ 的线性同态性 $\mathrm{HF}(u+v)=\mathrm{HF}(u)\cdot\mathrm{HF}(v)$，上式当且仅当 AS 用正确的 $\{\hat{x}_i\}$ 集合与掩码分量计算时成立——AS 替换/丢弃任何输入都会破坏等式。承诺一致性附带校验：$\prod_i C_i\stackrel{?}{=}\vec{\mathrm{Com}}(z;\sum_i\boldsymbol{\rho}_i)$（AS 无从伪造，因不知 $\rho_i$ 但等式右侧可在审计时由客户端联合确认）。

**步骤 5 · 鲁棒性（审计追责，按需触发）**

聚合权重采用样本量加权 $\alpha_i=n_i/\sum n_j$（明文、注册设备可公开）。若全局损失连续 $\tau$ 轮不降：进入审计轮——抽审集合 $A\subset U_3$ 中客户端须开示 $(x_i,\boldsymbol{\rho}_i)$ 使 $C_i\stackrel{?}{=}\vec{\mathrm{Com}}(x_i;\boldsymbol{\rho}_i)$ 且 $\|x_i\|^2$ 与 $V_i$ 一致并 $\le B^2$。开示失败/超标者：吊销注册、驱逐出 $G$、更新掩码图。诚实客户端的隐私代价仅限于被抽审轮（且抽审策略可要求审计由多方委员会执行）。

**步骤 6 · 密钥演进（防物理俘获）**

每轮结束，$b_i^{(r+1)}=\mathrm{PRG}(b_i^{(r)}\,\|\,r)$ 本地演进，成对种子经一次 ECDH 重协商（仅邻居间）更新——俘获一架 UAV 只暴露当前轮。

#### 5.1.7 安全性分析

**定理 1（个体隐私）**：在 DDH 与 PRG 安全性假设下，AS 与至多 $t-1$ 个客户端合谋时，任何诚实客户端 $i$ 的个体更新 $x_i$ 保持计算隐藏。
*证明梗概*：模拟器视角。$x_i$ 在 AS 视图中仅出现于 $\hat x_i$。$\hat x_i$ 中，自掩码 $\mathrm{PRG}(b_i)$ 之种子 $b_i$ 被 $t$ 阈值 Shamir 保护——合谋者至多持 $t-1$ 份，份额联合分布在信息论上与 $b_i$ 独立（Shamir 的 $t$ 隐私性）；成对掩码 $\mathrm{PRG}(s_{ij})$ 依赖 ECDH 秘密 $s_{ij}$，由 DDH 与随机预言机下的 PRG 伪随机性，对不知 $sk_i^{(d)},sk_j^{(d)}$ 者为伪随机。故 $\hat x_i$ 与均匀随机向量计算不可区分。又 Commit-then-Reveal 保证 AS 无法在观察上传内容后再选择 $U$，排除"按内容选择性掉线以隔离 $x_i$"的自适应攻击（若 AS 违反，其签名 $\Sigma_{AS}$ 与后续份额行为矛盾，构成可公开验证的作恶证据）。承诺 $C_i,V_i$ 的隐藏性由 Pedersen 承诺的完美隐藏性保证。∎

**定理 2（聚合完整性/可验证性）**：若 $\mathrm{HF}$ 抗碰撞（DL 假设）且 BLS 在随机预言机下 EUF-CMA，则恶意 AS 使诚实客户端接受错误 $z'\neq z$ 的概率可忽略。
*证明梗概*：诚实客户端验证 $\mathrm{HF}(z')$ 与由 $\{\hat x_i\}$ 及掩码分量算出的右侧相等。若 AS 篡改任一 $\hat x_i$ 或用错误集合 $U'$，由 $\mathrm{HF}$ 的线性同态性与抗碰撞性，等式成立意味着找到 $\mathrm{HF}$ 碰撞或伪造 BLS 签名（在线列表承诺），均归约到对应困难假设。∎

**定理 3（投毒可追责）**：恶意客户端注入的更新若导致聚合异常，审计轮中其无法同时满足承诺开示一致性与范数界（绑定性归约到离散对数），故将以至少 $1-\mathrm{negl}$ 概率被识别驱逐；且系统在驱逐后以图更新继续运行（鲁棒性来源于身份化注册+承诺绑定，而非逐轮 ZK 证明——这是本方案明确声明的精度-开销权衡）。

**与现有方案的严格比较**：相比 VLSFL——多了防选择性掉线（Commit-then-Reveal）、TA 不掌握密钥（DKG）、投毒追责；相比 ELSA——单服务器即可运行（无双服务器不合谋假设），代价是投毒防御从"逐轮主动界"弱化为"事后追责"。相比 SecAgg——多轮复用+可验证+防投毒。**该组合在现有文献中未出现，检索确认无重复**。

### 方案二：SkyRelay —— 双服务器中继的阈值 MK-CKKS 单步解密聚合（标准 FL · 双服务器 · 阈值多密钥系）

#### 5.2.1 场景

跨机构 UAV 物流联盟（cross-silo 形态，$N=10\sim30$ 家运营商各自的机队），基础设施含**两台分属不同信任域的服务器**：地面站 AS（聚合）与低轨卫星中继站 RS（验证/中继），二者商业竞争关系保证"不合谋"假设的现实性。客户端算力弱、链路窄——**P2P 份额互发（CDKS-LSS，$O(N^2)$）不可行**；且 UAV 随时掉线，**ESAFL 的静态解密钥结构不可用**。

#### 5.2.2 要解决的问题

1. CDKS-LSS'26 虽做到无 TTP+阈值掉线容忍，但份额 P2P 互发通信 $O(N^2)$（20 方时每方每轮约 109MB），弱链路下崩溃；
2. ESAFL'25 单步解密高效，但解密钥 $s=\sum s_i$ 静态固定，掉线即解密失败，且长期静态密钥易被窃取累积；
3. FedOut'26 用 KDC 生成补充密文实现掉线容忍，但 KDC 全可信、知一切密钥；
4. 三者均无结果可验证性与作恶审计能力。

#### 5.2.3 创新点 / 总体设计目标

**核心机制：双服务器加法拆分托管 + 协作补充密文。** 初始化时每个客户端把私有加密钥 $s_i$ 加法拆分 $s_i=s_i^{A}+s_i^{B}$，两半分别密化托管给 AS、RS。任一服务器单独对 $s_i$ 零知识；掉线时两台服务器各用自己的半个份额生成"半个补充密文"，相加恰为掉线者的零明文合法密文——**无 KDC、无 TEE、无 P2P**，通信 $O(N)$。叠加 BLS 聚合签名审计链防服务器丢弃/替换客户端贡献。

#### 5.2.4 威胁模型

| 实体 | 假设 | 说明 |
|------|------|------|
| AS（地面站） | 半诚实；作恶时（丢/换密文）被审计链发现 | 与 RS **不合谋**（不同信任域） |
| RS（卫星中继） | 半诚实；同上 | 至多一台服务器被动腐化时隐私仍保（见定理） |
| 客户端 $P_i$ | HBC；≤N−2 可与一台服务器合谋 | 掉线任意 |
| 外部敌手 | 窃听公共信道（不假设安全信道） | — |

可见性：AS ⌀ 各 $c_i$、$s_i^A$ 密化半份额、聚合密文；✗ 明文、$s_i$、$s_i^B$。RS 对称。客户端 ⌀ 聚合明文；✗ 他人 $s_j$ 与个体明文。**聚合明文仅客户端可得**（优于 MASER/CDKS-LSS——它们的服务器可见聚合明文）。

#### 5.2.5 符号系统

| 符号 | 含义 |
|------|------|
| $R_q=\mathbb Z_q[X]/(X^N{+}1)$，$\tilde p$（明文相关模）、$q$ | RLWE 环与模数（ESHE 骨架，仅加法） |
| $s_i\leftarrow\chi_s$ | 客户端 $i$ 的私有加密钥（多项式） |
| $a_t\in R_q$ | 第 $t$ 轮公共随机多项式，由 $\mathrm{PRPG}(B,t)$ 本地生成（$B$ 为初始化秘密参数） |
| $c_i=a_t s_i+\tilde p e_i+m_i \pmod q$ | 客户端密文（单分量对称式，$m_i=\mathrm{Ecd}(\Delta\mathbf w_i)$，$e_i\leftarrow\chi_e$） |
| $s_i=s_i^A+s_i^B\pmod q$ | 加法拆分托管份额 |
| $\mathrm{AE}_{pk}(\cdot)$ | 认证加密（半份额托管通道） |
| $\sigma^{agg}=\mathrm{BLS}.AggSign$ | 聚合签名 |

#### 5.2.6 方案设计（闭环公式推导）

**步骤 0 · 初始化（无 KDC，一次性）**

各 $P_i$：采样 $s_i\leftarrow\chi_s$；随机 $s_i^A\leftarrow R_q$，令 $s_i^B=s_i-s_i^A\bmod q$；发送 $\mathrm{AE}_{pk_{AS}}(s_i^A)$ 给 AS、$\mathrm{AE}_{pk_{RS}}(s_i^B)$ 给 RS。全体经一次轻量 MPC（或公告板+承诺开放）协商公共参数 $PP=\{N,q,\tilde p,\chi_s,\chi_e,B\}$。**无任何人知道他人的 $s_j$；AS、RS 各只持每人的半个份额。**

**步骤 1 · 加密上传（客户端侧，每轮）**

本地训练得更新向量 $\mathbf w_i$，编码 $m_i=\mathrm{Ecd}(\Delta\mathbf w_i)$，采样 $e_i\leftarrow\chi_e$，计算

$$c_i=[a_t s_i+\tilde p\,e_i+m_i]_q,\qquad \eta_i=H(c_i),\qquad \sigma_i=\mathrm{BLS}.Sign_{sk_i}(c_i\,\|\,t)$$

上传 $(c_i,\sigma_i)$ 至 AS；$\eta_i$ 至公告板（或随 $\sigma_i$ 由 AS 转发 RS）。

**步骤 2 · 聚合与掉线检测（AS）**

AS 验证各 $\sigma_i$，公布输入清单 $L_t=\{(i,\eta_i)\}$（供客户端确认"我的贡献被纳入"）。设在线集 $U$、掉线集 $D$。AS 计算部分聚合：

$$\bar c_U=\sum_{i\in U}c_i=\Big[a_t\sum_{i\in U}s_i+\tilde p\sum_{i\in U}e_i+\sum_{i\in U}m_i\Big]_q$$

**步骤 3 · 协作补充密文（AS+RS，核心创新）**

对每个掉线者 $j\in D$：
- AS 计算 $\gamma_j^A=[a_t s_j^A+\tilde p e_j^A]_q$（$e_j^A\leftarrow\chi_e$ 由 AS 采样）；
- RS 计算 $\gamma_j^B=[a_t s_j^B+\tilde p e_j^B]_q$（$e_j^B$ 由 RS 采样），发给 AS；
- AS 得补充密文 $\gamma_j=\gamma_j^A+\gamma_j^B=[a_t s_j+\tilde p(e_j^A+e_j^B)]_q$。

**正确性（闭环检验）**：$\gamma_j$ 恰是"明文为 0 的合法密文"——与 $c_j=[a_t s_j+\tilde p e_j+0]_q$ 同分布（噪声为两独立 $\chi_e$ 样本之和，宽度 $\sqrt2$ 倍，仍在解密噪声界内，参数选取时预留）。因此补入后不改变聚合明文、只贡献 $\tilde p$ 倍数噪声。∎

**安全要点**：AS 只见过 $s_j^A$（均匀随机，信息论上独立于 $s_j$），RS 对称；$\gamma_j$ 的生成不需要任何一方重构 $s_j$。

**步骤 4 · 最终聚合与签名审计**

$$\bar c=\bar c_U+\sum_{j\in D}\gamma_j=\Big[a_t\sum_{i\in[N]}s_i+\tilde p E+\sum_{i\in U}m_i\Big]_q,\quad E=\sum_{i\in U}e_i+\sum_{j\in D}(e_j^A+e_j^B)$$

AS、RS 分别对 $(\bar c,L_t,t)$ 签名，聚合签名 $\sigma^{agg}$ 随 $(\bar c,\sigma^{agg})$ 广播。

**步骤 5 · 客户端单步解密**

每个客户端持有解密钥 $s=\sum_{i=1}^{N}s_i$（初始化阶段经一次 MPC/两轮广播在掩码下求得——ESAFL 的做法：每人广播 $[a_0 s_i+\tilde p e_i']_q$，求和后每人本地减 $a_0$ 项之外的噪声项不可行；改为**拆分中继求和**：每人发 $s_i^A\to AS,s_i^B\to RS$，AS 公布 $S^A=\sum s_i^A$，RS 公布 $S^B=\sum s_i^B$，客户端得 $s=S^A+S^B$。**注意**：$s$ 本就对全体客户端公开（ESAFL 模型，客户端是解密终点），AS/RS 各自只见 $S^A$ 或 $S^B$ 之一——**服务器仍不知道 $s$**，这是相对 ESAFL 的 AS 的信任削弱）。

客户端解密：

$$\hat M=[\bar c-a_t s]_q=\Big[\sum_{i\in U}m_i+\tilde p E\Big]_q \;\xrightarrow{\ \bmod \tilde p\ }\;\sum_{i\in U}m_i\;\xrightarrow{\ \mathrm{Dcd}\ }\;\sum_{i\in U}\Delta\mathbf w_i$$

除以 $\sum_{i\in U}n_i$（样本量加权，$n_i$ 明文上报并签名）得全局更新。**闭环**：加密（步骤 1）→ 聚合+补密文（步骤 2–4）→ 解密（步骤 5）→ 下一轮的 $a_{t+1}=\mathrm{PRPG}(B,t{+}1)$ 本地刷新，无任何逐轮协商。

#### 5.2.7 安全性分析

**定理 1（个体与聚合隐私）**：在 RLWE 假设下，只要 AS 与 RS 不合谋，（a）任何服务器（含与 ≤N−2 客户端合谋者）对个体 $m_i$ 与聚合明文 $\sum m_i$ 计算不可知；（b）客户端对他人 $m_j$（$j$ 诚实）计算不可知。
*证明梗概*：（a）服务器视图为 $\{c_i\},\{\gamma_j\},L_t$ 及托管半份额。每个 $c_i$ 是 RLWE 型样本 $a_ts_i+\tilde p e_i+m_i$：$a_t$ 公开，$s_i\leftarrow\chi_s$ 秘密，由 RLWE 判定假设其与均匀随机不可区分（标准 ESHE 论证，ESAFL 定理 1 同型）；$\gamma_j^A=a_ts_j^A+\tilde pe_j^A$ 中 $s_j^A$ 均匀且 AS 不知 $s_j^B$，同理。聚合 $\bar c$ 对服务器而言含未知项 $a_ts$（$s$ 对服务器未知：AS 只知 $S^A$，RS 只知 $S^B$，不合谋故不知 $s$）。半份额 $s_i^A$ 均匀随机，信息论上独立于 $s_i$（一次一密论证）。（b）客户端知道 $s$ 与 $\bar c$，可得 $\sum_i m_i$；要分离 $m_j$ 需知其余所有 $m_i$——由归纳，除非 $N-1$ 个客户端全部合谋（被假设排除），否则 $m_j=\sum m_i-\sum_{i\ne j}m_i$ 中后者含至少一个未知诚实方贡献。∎

**定理 2（掉线容忍正确性）**：任意 $D\subset[N]$ 掉线时，步骤 5 输出恰为 $\sum_{i\in U}m_i$，解密失败概率（噪声越界）$\le\mathrm{negl}$。
*证明*：步骤 3 已证 $\gamma_j$ 为零明文合法密文，故 $\bar c-a_ts=\sum_U m_i+\tilde pE$；选 $q/\tilde p$ 使 $\|E\|_\infty<\tilde p/(2N)$（标准 CKKS 噪声界，$E$ 为 ≤3N 个 $\chi_e$ 样本和），模 $\tilde p$ 后噪声消失。∎

**定理 3（抗丢弃/替换审计）**：若 BLS 为 EUF-CMA 且 $H$ 抗碰撞，则 AS 静默丢弃或替换任一客户端贡献必被至少一个诚实客户端以压倒性概率发现（比对 $L_t$ 与本地 $\eta_i$），且 $\sigma^{agg}$ 提供对第三方的可转移证据。

**与现有方案比较**：对 CDKS-LSS——份额通信从 P2P $O(N^2)$（每轮约 109MB/方）降为服务器中继 $O(N)$（每人上传 1 个环元素半份额+1 条密文）；对 ESAFL——从"零掉线容忍"升为"任意掉线容忍"，且初始化不再需要可信 AS（MPC 替代）；对 FedOut——去掉全可信 KDC，补充密文由双服务器协作生成（单服务器对 $s_j$ 零知识）；额外获得 BLS 审计链。**检索确认：无现有工作使用"加法拆分托管+双服务器协作补充密文"结构。**

### 方案三：HierDKG —— 无 KGC 的分布式阈值 MK-CKKS 层次联邦学习（层次 FL · 客户端–簇头–云 · 阈值多密钥系）

#### 5.3.1 场景

某省域 UAV 巡检网络：$K=12$ 个机群，每群 $n_k=8\sim 20$ 架 UAV，每群设一架**簇头**（边缘服务器，机载算力较强）；簇头做域内聚合，云 CS 做跨域全局聚合（HierFAVG 结构）。信道：UAV↔簇头为空地链路（窄带），簇头↔云为骨干网。

#### 5.3.2 要解决的问题

PrivHFL'25 是该场景唯一"密码原生"的层次方案，存在四点不足：
1. **KGC 知道全部密钥份额**（用户/边缘/云三份份额皆由 KGC 生成并分发）——KGC 泄露即全域崩塌，且不符合无人机野外部署的现实；
2. **域内用户共用同一份额**（$s_U$ 为整群共用），粒度粗：域内任意一架 UAV 被俘获，其份额即被取走，域内再无秘密；
3. **云最终可见各边缘聚合明文**（CS 持云份额完成解密），且跨域聚合后的全局模型明文对 CS 可见；
4. **无共识剪枝/稀疏化**，全模型 CKKS 加密在空地窄带上通信量巨大（MASER 已证明剪枝+切片可降 3–8 倍）。

#### 5.3.3 创新点 / 总体设计目标

1. **三层份额的分布式密钥生成（3-party DKG）**：域密钥 $s^{(k)}=s_U^{(k)}+s_E^{(k)}+s_C^{(k)}$，三份份额分别由域内客户端委员会、簇头 $E_k$、云 CS **各自本地生成**，公钥由各方局部 $b$ 分量相加合成——**无任何实体（含参与设计的三方）知道完整 $s^{(k)}$**，彻底去掉 KGC。
2. **每客户端独立子密钥 + 域内 2-out-of-3 阈值**：域内每架 UAV 持独立 $s_i$，域级份额 $s_U^{(k)}$ 再经 Shamir $(\tau_k,n_k)$ 分给域内各 UAV——单架被俘获只泄露一份，需 $\tau_k$ 架合谋才还原（解决不足 2）。
3. **解密终点下移到客户端委员会**：云完成的是"部分解密 $(d_C,d_E)$"，最终明文由域内客户端重构并**本地更新模型**——云对全局明文不可见（解决不足 3）。
4. **多数投票共识掩码 + 切片打包**：域内每轮用 $\ge 50\%$ 投票生成全局掩码，仅加密重要参数切片并按 CKKS 槽切片传输（解决不足 4）。

#### 5.3.4 威胁模型

| 实体 | 假设 | 说明 |
|------|------|------|
| 客户端委员会 $U_i$ | HBC；域内 ≤$\tau_k-1$ 架可被腐蚀合谋 | 被俘获者泄露自身份额，不足以还原 $s_U^{(k)}$ |
| 簇头 $E_k$ | HBC；可与 ≤$\tau_k-1$ 客户端合谋 | 单独持 $s_E^{(k)}$ 无法解密 |
| 云 CS | **HBC 且可见性受限**；可丢/换域密文（受哈希验证约束） | 持 $s_C^{(k)}$ 仍无法解密（缺 2 份）；明文不可见 |

#### 5.3.6 方案设计（闭环公式推导）

**步骤 0 · 三层 DKG（初始化，一次性，无 KGC）**

对域 $k$：
1. 簇头采样 $s_E^{(k)}\leftarrow\chi_s$、$\epsilon_E\leftarrow\chi_e$，广播 $b_E^{(k)}=-a s_E^{(k)}+\epsilon_E$；
2. 云采样 $s_C^{(k)}$、$\epsilon_C$，广播 $b_C^{(k)}=-a s_C^{(k)}+\epsilon_C$；
3. 域内客户端委员会经一次轻量 MPC（或第 3.3 节所述的拆分中继求和）生成 $s_U^{(k)}$，广播 $b_U^{(k)}=-a s_U^{(k)}+\epsilon_U$，并把 $s_U^{(k)}$ 经 $\mathrm{SS}.\mathrm{Share}(s_U^{(k)},\tau_k,n_k)$ 分给 $n_k$ 架 UAV（份额 $u_i^{(k)}$；一致性由 Pedersen 承诺校验防止恶意经销商）；
4. 合成域公钥：

$$b^{(k)}=b_U^{(k)}+b_E^{(k)}+b_C^{(k)}=-a\underbrace{(s_U^{(k)}{+}s_E^{(k)}{+}s_C^{(k)})}_{s^{(k)}}+\underbrace{(\epsilon_U{+}\epsilon_E{+}\epsilon_C)}_{\epsilon^{(k)}}$$

即 $pk^{(k)}=(b^{(k)},a)$ 是 $s^{(k)}$ 的合法 RLWE 公钥，而**三方各自只知道自己的份额**。∎

**步骤 1 · 域内共识掩码（降通信）**

$i$ 本地训练后按幅度剪枝取 top-$\kappa$ 得二值掩码 $\mathbf m_i^{(k)}$；簇头做多数投票：$\bar{\mathbf m}^{(k)}=\mathbb 1[\sum_i \mathbf m_i^{(k)}\ge \lceil n_k/2\rceil]$。客户端把更新投影到掩码位置并切片：$m_i=\mathrm{Ecd}(\Delta\,\mathbf g_i\odot \bar{\mathbf m}^{(k)})$。

**步骤 2 · 客户端加密上传**

采样 $v_i\leftarrow\chi_s$、$e_{i,0},e_{i,1}\leftarrow\chi_e$：

$$c_{i,0}=v_i b^{(k)}+e_{i,0}+m_i,\qquad c_{i,1}=v_i a+e_{i,1}\pmod q$$

上传 $ct_i=(c_{i,0},c_{i,1})$ 与 $\sigma_i=\mathrm{BLS}.Sign_{sk_i}(ct_i\|t)$。

**步骤 3 · 簇头域内聚合（同态加法）**

$$C^{(k)}=\sum_{i\in U_k}ct_i=\Big(\sum_i c_{i,0},\ \sum_i c_{i,1}\Big):= (C_0^{(k)},C_1^{(k)})$$

簇头附 $\eta^{(k)}=H(C^{(k)})$ 与 $\sigma_{E_k}$ 上送云。**簇头此时对明文零知识**（需 $s^{(k)}$ 解密）。

**步骤 4 · 云跨域聚合 + 部分解密（两级）**

云做同态加权求和（权重 $\alpha_k=n_k/\sum n$ 为明文，可用标量乘）：

$$C^{glob}=\sum_{k}\alpha_k\cdot C^{(k)}=(C_0^{g},C_1^{g})$$

云计算自己的部分解密 $d_C=C_1^{g}\cdot s_C$，其中 $s_C=\sum_k s_C^{(k)}$ 需按域对应——实际按域执行：对每域 $k$，云算 $d_C^{(k)}=C_1^{(k)}s_C^{(k)}+\tilde e$；簇头算 $d_E^{(k)}=C_1^{(k)}s_E^{(k)}+\tilde e$。云把 $\{C^{(k)},d_C^{(k)}\}$ 逐域下发。

**步骤 5 · 客户端委员会完成解密（阈值 + 掉线容忍）**

域内在线 UAV（≥$\tau_k$）各自计算 $d_i^{(k)}=C_1^{(k)}\cdot u_i^{(k)}+\tilde e_i$，上传簇头。簇头 Lagrange 插值重构：

$$d_U^{(k)}=\sum_{i\in\mathcal S_k}\lambda_i\,d_i^{(k)}=C_1^{(k)}\cdot s_U^{(k)}+\tilde E\quad(\mathcal S_k\subseteq U_k,\ |\mathcal S_k|\ge\tau_k,\ \lambda_i\!=\!\prod_{j\ne i}\tfrac{-j}{i-j})$$

（插值在环 $R_q$ 上进行，需选取 $R_q$ 上的"例外序列"评估点以保证可逆性——CDKS-LSS 的环上 Shamir 技术。）

域内明文：

$$M^{(k)}=C_0^{(k)}+d_U^{(k)}+d_E^{(k)}+d_C^{(k)}=C_0^{(k)}+C_1^{(k)}s^{(k)}+\tilde E'$$

**正确性（闭环检验）**：
$$C_0^{(k)}+C_1^{(k)}s^{(k)}=\sum_i\big(v_i b^{(k)}{+}e_{i,0}{+}m_i\big)+\Big(\sum_i v_i a+e_{i,1}\Big)s^{(k)}=\sum_i m_i+\sum_i\big(v_i\epsilon^{(k)}{+}e_{i,0}{+}e_{i,1}s^{(k)}\big)$$
其中 $b^{(k)}+a s^{(k)}=\epsilon^{(k)}$，末项即 CKKS 固有噪声；$\Delta^{-1}\mathrm{Dcd}$ 后得 $\sum_i \mathbf g_i\odot\bar{\mathbf m}^{(k)}$，按 $\bar{\mathbf m}^{(k)}$ 回填零位即得域模型更新。∎

**步骤 6 · 跨域汇总与下发**

各域把 $M^{(k)}$ 明文（或仅在跨域聚合时）提交给云？——**注意**：为保持"云不可见明文"，跨域聚合采用密文域加权：让各域把域明文 $M^{(k)}$ 用**全局密钥**重新加密？这会增加开销。更简洁：云在步骤 4 已完成跨域密文聚合 $C^{glob}$，则需要的是 $s^{glob}$ 的部分解密。改用**级联结构**：全局密文 $C^{glob}$ 的第二分量 $C_1^g=\sum_k\alpha_k C_1^{(k)}$，而各域的 $s^{(k)}$ 不同——无法直接解密。

**修正（保持闭环）**：引入域间统一化——所有域共用同一 $a$ 与同一**全局解密钥结构** $s^{g}=\sum_k s^{(k)}$，令各域用"级联公钥" $b^{g}=\sum_k b^{(k)}=-a s^{g}+\sum_k\epsilon^{(k)}$ 加密，则跨域聚合后：

$$C^{glob}=\sum_k\alpha_k C^{(k)},\quad M^{g}=C^{g}_0+C^{g}_1 s^{g}+\tilde E=\sum_k\alpha_k\sum_{i\in k}m_i+\text{noise}$$

**但**：若所有域共用 $s^g$，则任一域都能解密他域（需各域份额分离）。解决方案：客户端加密时用**域公钥** $pk^{(k)}$ 加密（各域不同），簇头聚合后做**密文密钥切换（key-switching）到全局公钥**——簇头持 $\mathrm{KS}_{k\to g}$（由 DKG 阶段生成），执行 $C^{(k)}\to \widehat C^{(k)}$（全局公钥下），云再做跨域加权聚合；全局解密钥 $s^g$ 三份份额分别托管给（客户端联合份额、簇头委员会份额、云份额），最终解密由客户端委员会完成。此即**层次化密钥切换**，通信仅增加一次 KS。

**简化（推荐实现）**：令全局密钥即"所有域份额之和" $s^g=\sum_k s^{(k)}$，而每域加密时附带"域标识偏移"——客户端用 $pk^{(k)}$ 加密 $m_i$，簇头用 $\mathrm{KS}_{k\to g}$ 切换，云聚合，客户端委员会用全局份额解密。**全局解密份额**：$s_U^g=\sum_k s_U^{(k)}$（客户端侧份额之和，由各域委员会 MPC 汇总）、$s_E^g=\sum_k s_E^{(k)}$（簇头委员会汇总）、$s_C^g=\sum_k s_C^{(k)}$。三方各自只需本地求和即可，无需交换秘密。∎

**步骤 7 · 逐层验证（同态哈希链）**

客户端层 $\eta_i=H(ct_i)$；簇头层 $\eta^{(k)}=H(C^{(k)})\stackrel{?}=\prod_i \mathrm{HF}(ct_i)$；云层 $\eta^{g}=H(C^{glob})$。每层附 BLS 签名，客户端可追溯验证"我的密文被簇头正确聚合且未被云丢弃"。

#### 5.3.7 安全性分析

**定理 1（无 KGC 的域密钥安全）**：3-party DKG 后，除三方各自份额外，任何 PPT 敌手（含参与协议的三方中的任意两方合谋）对 $s^{(k)}$ 的条件分布与先验 $\chi_s$ 不可区分（在 RLWE 假设下）。
*证明梗概*：敌手视图含 $\{b_U^{(k)},b_E^{(k)},b_C^{(k)},a\}$ 与至多两份份额。设敌手获 $s_U^{(k)},s_E^{(k)}$，则 $b^{(k)}=-a s^{(k)}+\epsilon^{(k)}$ 中含未知 $s_C^{(k)}$ 与 $\epsilon^{(k)}$；$(a,b^{(k)})$ 对敌手而言是 $s_C^{(k)}$ 的 RLWE 样本，由判定 RLWE 与均匀不可区分。份额分离性另由 Pedersen VSS 的绑定性与 Shamir 的 $\tau_k$ 隐私性保证（≤$\tau_k-1$ 份份额信息论上无信息）。∎

**定理 2（云不可见性）**：本方案中云对域级明文 $\sum_i m_i$ 与全局明文 $M^g$ 均计算不可知（RLWE 假设下），弱于 PrivHFL（云可见各边缘聚合明文）。
*证明*：云视图为 $\{C^{(k)}\}$（或切换后 $\hat C^{(k)}$）、$C^g$、$d_C$、$\{s_C^{(k)}\}$。解密需 $C_0^g+C_1^g s^g$，云缺 $s_U^g+s_E^g$，由 RLWE 不可区分性得证。∎

**定理 3（掉线与阈值）**：域内在线 ≥$\tau_k$ 时域解密成功（Shamir 可逆性成立，需环上例外序列评估点，同 CDKS-LSS 引理）；簇头掉线时 $s_E^{(k)}$ 由簇头委员会 $(t_E,K_E)$ 份额重构接管。

**定理 4（聚合完整性）**：若 $\mathrm{HF}$ 抗碰撞且 BLS EUF-CMA，则簇头或云对密文的丢弃/替换必被下一层或客户端以压倒性概率检测（逐层哈希链）。

**与现有方案比较**：对 PrivHFL——去掉 KGC（最大单点信任）、云明文不可见、域内份额细化到单架 UAV、加入共识剪枝降通信；对 MASER——从单服务器 FL 升为层次 FL 并保持其剪枝收益；对 CDKS-LSS——从单服务器 P2P 升为层次 DKG。**检索确认：三层份额 DKG + 层次密钥切换 + 共识剪枝的组合未见报道。**

### 方案四：SwarmHandover —— 边缘(UAV)频繁掉线的可接管层次聚合（层次 FL · UAV-as-Edge · 掩码+阈值混合）

#### 5.4.1 场景

地面 IoT 传感网（成千上万节点）→ **UAV 作为移动边缘节点**悬停提供覆盖与算力（Edge-Assist / UAV-as-Edge）→ 云。每架 UAV 覆盖一个蜂窝簇，按航线/电量**频繁起降轮换**（平均每 1–3 轮就有 UAV 换班、中断或返航）。这是 UAV-FL 最典型、也最被现有文献忽视的形态：**边缘节点本身是高动态的**。

#### 5.4.2 要解决的问题

1. **边缘掉线是 HFL 独有且现有方案未解的**：PrivHFL（簇头持 1/3 份额）、SKHE（边缘持 ECC 子秘密）、PPBR（边缘做 SA）全部把边缘节点当作稳定基础设施，UAV 返航即该域份额/中间结果瞬间丢失，需整域重启密钥；
2. **空-地两级链路都要省带宽**：地面设备多、UAV 上行窄、UAV→云亦窄；
3. **交接（handover）过程中的可信性问题**：接管的 UAV 需要接管密钥份额，若直接传输份额则新 UAV 获得该域全部解密能力；
4. **端到端可验证**：地面设备无法验证自己的更新是否真的进入了全局模型。

#### 5.4.3 创新点 / 总体设计目标

**核心机制：边缘份额的"环上托管 + 阈值接管"（Share Escrow Ring）。** 每架边缘 UAV $E_k$ 把自己的域份额 $s_E^{(k)}$ 用 $(\varsigma,K)$ Shamir 分给**同簇邻近的 $K$ 架 UAV**（托管环），任一架返航时，环内收齐 $\varsigma$ 份即可为**接替 UAV** 重构出 $s_E^{(k)}$ 的一次性接管凭证；接替者只获得"本轮可用的部分解密能力"，且重构过程在环内完成、全程可审计（每份托管份额附签名与 Pedersen 承诺）。叠加：
- 地面设备→UAV：SecAgg 式双掩码（零密文膨胀，适配海量 IoT）；
- UAV→云：阈值 CKKS 密文（方案三的 DKG 结构复用）+ 补充密文处理 UAV 掉线导致的域缺失；
- 签名链与同态哈希贯穿两级，地面设备可端到端验证。

#### 5.4.4 威胁模型

| 实体 | 假设 | 说明 |
|------|------|------|
| 地面设备 $d$ | HBC；≤$t_d-1$ 与边缘合谋 | 大规模、低算力、随时离线 |
| 边缘 UAV $E_k$ | **crash-stop + HBC**（不作恶但随时返航/失联） | 返航时份额经托管环接管 |
| 托管环邻机 | HBC；需 $\varsigma$ 架合谋才能非法重构份额 | 合谋界 $\varsigma-1$ |
| 云 CS | 恶意可篡改（受哈希链与签名约束） | 明文不可见 |
| 接替 UAV | HBC；接管凭证**限时有限**（仅本轮有效） | 前向安全：旧份额对历史密文无效 |

可见性：$E_k$ ⌀ 本域设备掩码后更新、域聚合密文；✗ 个体更新（掩码）与域明文（需阈值解密）。云 ⌀ 域密文、签名链；✗ 任何明文。地面设备 ⌀ 全局模型与验证证明；✗ 他域信息。

| $\mathcal D_k$ | UAV $E_k$ 覆盖域的地面设备集合；掩码域 $\mathbb Z_R$ |
| $s_E^{(k)}$、$\{\varepsilon^{(k,\ell)}\}_{\ell\in\mathcal R_k}$ | 边缘域份额及其 $(\varsigma,K)$ 托管份额（$\mathcal R_k$ 为托管环） |

| $\Lambda_D,\Lambda_E$ | 设备层 / 边缘层聚合的哈希链根 |

#### 5.4.6 方案设计（闭环公式推导）

**步骤 0 · 初始化：域密钥 DKG + 份额托管环**

1. 按方案三步骤 0 生成域密钥 $s^{(k)}=s_D^{(k)}+s_E^{(k)}+s_C^{(k)}$（此处 $s_D^{(k)}$ 由域内地面设备委员会生成）；
2. $E_k$ 计算托管份额：$\{\varepsilon^{(k,\ell)}\}_{\ell\in\mathcal R_k}=\mathrm{SS}.\mathrm{Share}(s_E^{(k)},\varsigma,K)$，附承诺 $\mathrm{Com}(\varepsilon^{(k,\ell)};\rho_\ell)$ 与签名，分发给托管环上各邻机 $\ell$。**$E_k$ 自身销毁明文 $s_E^{(k)}$ 的本地拷贝**（只保留用于部分解密的运行时副本，落盘加密）。

**步骤 1 · 设备层：双掩码聚合（UAV $E_k$ 处）**

设备 $d\in\mathcal D_k$ 上传
$$\hat x_d=x_d+\mathrm{PRG}(\beta_d)+\sum_{d'\in N(d)}\pm\mathrm{PRG}(s_{d,d'})\pmod R$$
$E_k$ 收集 ≥$t_d$ 份后按 SecAgg 规则去掩码，得**域内明文和** $z^{(k)}=\sum_{d\in\mathcal D_k}x_d$（此时 $E_k$ 只见"和"，不见个体）。

**步骤 2 · 边缘层：加密上云**

$E_k$ 把 $z^{(k)}$ 编码并用**域公钥** $pk^{(k)}$ 加密：$ct^{(k)}=(c_0^{(k)},c_1^{(k)})$，经 KS 切到全局公钥（方案三步骤 6），附 $\eta^{(k)}=H(ct^{(k)})$ 与 $\sigma_{E_k}$ 上送云。

**步骤 3 · UAV 返航 → 接管（核心创新）**

设 $E_k$ 在第 $t$ 轮返航（未发送 $ct^{(k)}$，也未做部分解密）：
1. 托管环 $\mathcal R_k$ 中任意 $\varsigma$ 架邻机 $\ell$ 提交其托管份额 $\varepsilon^{(k,\ell)}$ 与签名；
2. 接替 UAV $E_{k'}$ 用 Lagrange 插值重构：$s_E^{(k)}=\sum_{\ell\in\mathcal S}\lambda_\ell\varepsilon^{(k,\ell)}$（$\mathcal S$ 为 $|\mathcal S|\ge\varsigma$ 的提交者集合）；
3. 但**不直接交给 $E_{k'}$ 明文份额**——而是令 $E_{k'}$ 在重构值上直接计算本轮部分解密：

$$\mathrm{TOK}_{k\to k'}=\big(C_1^{(k)}\cdot s_E^{(k)}+\tilde e\big)\ \text{（一次性，限轮次 }t\text{）}$$

即环内各邻机直接给出 $d_\ell^{(k)}=C_1^{(k)}\varepsilon^{(k,\ell)}+\tilde e_\ell$，$E_{k'}$ 只做插值合并，得到本轮所需的部分解密 $d_E^{(k)}$，**$s_E^{(k)}$ 本身从不显式出现于 $E_{k'}$ 的内存中**（前向安全：该凭证只对第 $t$ 轮的 $C_1^{(k)}$ 有效，对历史/未来密文无用）。∎

4. 若 $E_k$ 彻底失联且无接替者：云为缺失域生成**补充密文** $\gamma^{(k)}=[a s^{(k)}+\tilde p e']_q$（零明文），由云份额 $s_C^{(k)}$ 与设备委员会份额联合生成（双服务器协作生成，同方案二步骤 3 的拆分机制）——保证跨域聚合的解密项完整。

**步骤 4 · 云跨域聚合 + 完整性哈希链**

$$C^{glob}=\sum_k\alpha_k\hat{ct}^{(k)},\quad \Lambda_E=H(\eta^{(1)}\|\cdots\|\eta^{(K)}),\quad \sigma_{CS}=\mathrm{BLS}.Sign_{sk_{CS}}(C^{glob}\|\Lambda_E\|t)$$

**步骤 5 · 解密与端到端验证**

设备委员会（各域）提交 $d_D^{(k)}=C_1^{g}s_D^{(k)}+\tilde e$，云提交 $d_C^{(k)}$，接替者/簇头委员会提交 $d_E^{(k)}$；全局明文：

$$M^g=C_0^{g}+\sum_k\big(d_D^{(k)}+d_E^{(k)}+d_C^{(k)}\big)+\tilde E^{tot}$$

地面设备 $d$ 验证：$\Lambda_D$ 含自身 $\eta_d$、$\Lambda_E$ 与云广播一致、$\sigma_{CS}$ 有效——即可确认"我的更新进入了全局模型且未被篡改"。

**步骤 6 · 前向安全的轮换**

每轮结束后，托管环对 $s_E^{(k)}$ 做**份额刷新**（proactive secret sharing）：各邻机本地生成零份额 $\delta_\ell$（$\sum\delta_\ell=0$），更新 $\varepsilon^{(k,\ell)}\mathrel{+}=\delta_\ell$——旧份额即刻失效，抵御"多次俘获累积"攻击。

#### 5.4.7 安全性分析

**定理 1（个体更新隐私）**：在 DDH+PRG 假设下，$E_k$ 与 ≤$t_d-1$ 个设备合谋时对个体 $x_d$ 计算不可知（SecAgg 定理，直接继承）；云对全局明文与域明文均不可知（RLWE + 阈值份额分离）。

**定理 2（边缘份额安全）**：托管环中 ≤$\varsigma-1$ 架邻机合谋对 $s_E^{(k)}$ 信息论无信息（Shamir $\varsigma$ 隐私性）；接替 UAV 在接管过程中**从未获得 $s_E^{(k)}$ 的显式表示**——其视图为 $\{(d_\ell^{(k)},\varepsilon\text{承诺})\}$，插值结果仅为 $C_1^{(k)}s_E^{(k)}+\tilde e$，对该密文一次性有效；由 RLWE 噪声淹没论证（$\tilde e$ 取自大分布），从 $d_E^{(k)}$ 反推 $s_E^{(k)}$ 需解 RLWE。∎

**定理 3（前向安全 / 抗累积俘获）**：proactive 刷新后，敌手在第 $t$ 轮俘获的托管份额与第 $t+1$ 轮份额联合分布等价于独立的新鲜样本（零份额构造保证 $\sum\delta_\ell=0$，刷新后多项式常数项不变而份额完全更新——标准 PSS 论证）；故需在同一刷新周期内俘获 ≥$\varsigma$ 架才能攻破。
*注*：UAV 集群因任务协同天然构成"可信邻域环"，$\varsigma$ 可按机群规模取 $\lceil 2K/3\rceil$ 以同时容忍 $\lfloor K/3\rfloor$ 架同时返航+腐化。

**定理 4（端到端可验证 + 接管审计）**：接管事件必产生环上 ≥$\varsigma$ 份签名证据；云/接替者的任何密文替换都会被 $\Lambda_E$ 与设备侧验证发现（哈希链 + BLS EUF-CMA）。

**与现有方案比较**：现有 HFL 方案（PrivHFL/SKHE/PPBR）**全部假定边缘节点稳定**——本方案首次把"边缘节点高动态掉线"作为一等公民建模，并以托管环+一次性接管凭证解决；相比简单地"给边缘做备份"，本方案保证接管者不获得域密钥的长期解密能力（前向安全）。**检索确认：未见"边缘份额托管环 + 一次性接管凭证 + proactive 刷新"的 HFL 工作。**

### 方案五：VeriHier-Robust —— 不依赖 DP 的密文域拜占庭鲁棒层次聚合（层次 FL · Edge-Assist · 掩码+承诺+阈值 CKKS）

#### 5.5.1 场景

多 UAV 集群协同的多任务感知网络（$K$ 个集群，每集群一个边缘服务器 $E_k$ 与若干 UAV），极端 Non-IID（各集群航线/地域差异大），且**存在被俘获或伪造的 UAV 发起投毒攻击**（label flipping、sign flipping、ALIE、MinMax 等高级攻击，PPBR'26 已验证这些攻击在 HFL 下有效）。集群内 UAV 数 5–20，边缘服务器可通过卫星/骨干网互联。

#### 5.5.2 要解决的问题

PPBR'26 是唯一认真处理"HFL + 拜占庭鲁棒"的工作，代价是：
1. **依赖 CLDP 扰动**（符号统计加噪），**以精度换鲁棒**（需 $\chi\ge4$ 才勉强缓解精度损失）；
2. 范数筛选依赖**边缘协助解密盲化范数**——半诚实假设链很长（云-边缘-客户端三层都必须配合）；
3. 边缘层 SecAgg 有 $O(n^2)$ 项开销；
4. 云最终得到"去噪后的平均动量"明文——全局模型对云可见。

目标：**在不引入 DP 噪声的前提下**，实现密文/承诺域的拜占庭鲁棒层次聚合，保精度、保隐私、保可验证。

#### 5.5.3 创新点 / 总体设计目标

1. **承诺绑定的 ℓ2 范数界（无 ZK、无 DP）**：客户端对更新的**平方范数**做 Pedersen 承诺 $V_i=\mathrm{Com}(\|x_i\|^2)$，并提供"$\|x_i\|^2\le B^2$"的**轻量界证明**——采用"符号-幅度分解 + 平方关联"的 ELSA 式技术，但下沉到**簇头对的双服务器结构**（主簇头 $E_k$ + 备份簇头 $E_k'$，UAV 集群天然有备份机），避免云参与，缩短假设链。
2. **密文域裁剪（clipping）**：范数界验证通过的更新，其缩放系数 $\theta_i=\min(1,B/\|x_i\|)$ 由客户端在加密前本地应用，并附 $\mathrm{Com}(\theta_i)$ 供审计——裁剪在明文侧完成但**界在承诺侧可验证**，无需云看到明文。
3. **跨域鲁棒加权**：云对域密文做加权时，权重采用**鲁棒加权**（《加权方式》第 5 类：可信度加权），可信度由"域内范数界一致性 + 多轮传输签名的历史信誉"决定，且权重以**密文标量乘**方式作用（CKKS 支持），云不知各域明文。
4. **双服务器（主/备簇头）域内验证**：把 ELSA 的恶意安全能力（ℓ2 界）移植到 HFL 的域内层，且域内客户端规模小（5–20），其 OT/Beaver 关联开销可接受。

|------|------|------|

#### 5.5.6 方案设计（闭环公式推导）

**步骤 1 · 域内：份额上传（客户端 → 主/备簇头）**

UAV $i$ 本地训练得 $x_i$，本地计算 $\theta_i=\min(1,B/\|x_i\|)$（**裁剪在客户端本地完成**），令 $\tilde x_i=\theta_i x_i$，满足 $\|\tilde x_i\|\le B$。随后做加法秘密共享：

$$\tilde x_i=\tilde x_i^{(0)}+\tilde x_i^{(1)}\pmod{2^\ell},\quad \tilde x_i^{(0)}\leftarrow_R\mathbb Z_{2^\ell}^d$$

$i$ 把 $\tilde x_i^{(0)}\to E_k$、$\tilde x_i^{(1)}\to E_k'$，并广播 $V_i=\mathrm{Com}(\|\tilde x_i\|^2;\rho_i)$ 与 $\sigma_i$。

**步骤 2 · 域内：密态范数界验证（双簇头 2PC）**

两台簇头在份额上安全计算 $N_i=\|\tilde x_i\|^2=\sum_{j=1}^{d}\tilde x_{i,j}^2$（Beaver 平方关联：$[\![N_i]\!]=\sum_j[\![\tilde x_{i,j}]\!]^2$，乘法由 Beaver 三元组完成，牺牲法验证三元组正确性），随后执行**安全比较** $[\![N_i\le B^2]\!]$（提取符号位的安全比较电路），并 Open 结果：

- 若 $N_i\le B^2$：接受，标记 $a_i=1$；
- 否则：拒绝，$a_i=0$，该 UAV 本轮被隔离并记入信誉。

**闭环检验**：客户端提交的是 $\tilde x_i^{(0/1)}$ 而非 $x_i$，簇头从未看到 $\tilde x_i$ 本身；比较过程只输出 1 比特 $a_i$（泄漏仅为"是否越界"，这是鲁棒性的必要代价，且由 $\theta_i$ 本地裁剪，诚实客户端 $a_i\equiv1$，故**不泄漏诚实的范数值**——这是相对 PPBR 的 CLDP 统计泄漏的一大改进）。∎

**步骤 3 · 域内：鲁棒聚合（份额上完成）**

主/备簇头在份额上做加权求和（权重 $\alpha_i=n_i/\sum n_j$ 明文，或按信誉加权）：

$$[\![z^{(k)}]\!]=\frac{\sum_{i:a_i=1}\alpha_i[\![\tilde x_i]\!]}{\sum_{i:a_i=1}\alpha_i}$$

随后 $E_k$ 本地把份额转为 CKKS 明文 $z^{(k)}=\mathrm{Open}([\![z^{(k)}]\!])$——**注意**：此处 $E_k$ 仅见"域内聚合和"，不见个体（份额分离性）。$E_k$ 用全局公钥加密 $ct^{(k)}=\mathrm{Enc}_{pk^g}(\Delta z^{(k)})$。

**步骤 4 · 跨域：鲁棒加权 + 密文聚合（云侧）**

云不解密，只在密文上按鲁棒权重 $w_k$ 做标量乘与求和（CKKS 支持明文标量乘）：

$$C^{glob}=\sum_{k}w_k\cdot ct^{(k)}\quad\Rightarrow\quad \mathrm{Dec}(C^{glob})=\sum_k w_k z^{(k)}$$

权重 $w_k=\dfrac{\exp(\gamma r_k^{(t)})}{\sum_{k'}\exp(\gamma r_{k'}^{(t)})}$，信誉 $r_k^{(t)}$ 由历史轮次中"域内被拒绝比例 + 域聚合方向与全局方向的一致性（用 $\mathrm{HF}$ 哈希比对，不涉及明文）"更新：

$$r_k^{(t+1)}=\rho r_k^{(t)}+(1-\rho)\Big(1-\frac{|\{i\in k:a_i=0\}|}{n_k}\Big)$$

**步骤 5 · 解密与验证（域内客户端）**

按方案三的阈值解密结构：$M^g=C_0^g+\sum_k(d_D^{(k)}+d_E^{(k)}+d_C^{(k)})+\tilde E$，客户端委员会得 $M^g$，解码得全局更新 $\mathbf g^{g}=\frac{1}{\Delta}\mathrm{Dcd}(M^g)=\sum_k w_k z^{(k)}$。云**不可见**该明文。

验证链：设备层 $\eta_i$ → 域层 $\eta^{(k)}=H(ct^{(k)})\stackrel?=\mathrm{HF}(\{\tilde x_i\}_{a_i=1})$ → 全局 $\Lambda_E$；客户端用 $\mathrm{HF}$ 线性性验证域聚合正确，用 BLS 验证云未丢弃域。

**步骤 6 · 收敛性（为何无 DP 噪声仍收敛）**

裁剪后 $\|\tilde x_i\|\le B$ 保证更新方差有界；$\theta_i\le1$ 的裁剪是**确定性缩放**，不引入随机噪声——相比 PPBR 的 CLDP 扰动，收敛界不出现 $\mathcal O(\epsilon^{-2})$ 的隐私噪声项，标准 FedAvg 收敛率 $\mathcal O(1/\sqrt T)$ 保持（对 $\beta<1/2$ 的拜占庭比例，鲁棒聚合的偏差项由裁剪界 $B$ 与信誉加权抑制）。

#### 5.5.7 安全性分析

**定理 1（域内隐私，恶意客户端+一台恶意簇头）**：若至多一台簇头恶意且与任意多恶意客户端合谋，诚实客户端 $i$ 的 $\tilde x_i$ 对敌手计算不可知。
*证明梗概*：敌手视图为 $(\tilde x_i^{(b)}, V_i, a_i)$ 与自身输入；$\tilde x_i^{(1-b)}$ 为均匀随机（一次一密），故 $\tilde x_i$ 信息论隐藏；$V_i$ 为 Pedersen 承诺（完美隐藏）；$a_i$ 对诚实客户端恒为 1（确定性裁剪保证 $\|x_i\|\le B$），故零泄漏。恶意客户端的份额可由敌手完全决定，模拟器中直接嵌入即可（标准 2PC 模拟范式，ELSA 同型）。∎

**定理 2（拜占庭鲁棒性）**：设拜占庭比例 $\beta<1/2$，则（a）范数界验证使任意恶意更新的能量被限制在 $\|\tilde x\|\le B$（界验证的可靠性归约到 Pedersen 绑定性与 Beaver 关联验证的 soundness）；（b）信誉加权使连续作恶的域权重 $w_k\to0$；（c）聚合误差满足 $\|\mathbf g^g-\mathbf g^*\|\le\frac{2\beta}{1-\beta}B+\mathcal O(\sigma)$（裁剪+鲁棒加权下的标准鲁棒聚合误差界），不依赖任何 DP 参数——**精度显著优于 PPBR**。∎

**定理 3（云不可见 + 完整性）**：云视图为 $\{ct^{(k)}\},\{w_k\},\Lambda_E$；由 RLWE（语义安全）与阈值份额分离性，云对 $z^{(k)}$ 与 $M^g$ 均不可知；$\mathrm{HF}$ 链+BLS 保证云无法静默丢弃/替换域密文（抗碰撞+EUF-CMA）。

**与现有方案比较**：对 PPBR——去掉 DP 噪声（精度）、把范数界验证从"云-边缘协助解密"下沉到"主/备簇头 2PC"（假设链缩短）、云不可见全局明文；对 ELSA——从标准 FL 升为层次 FL，保留其恶意安全与 ℓ2 界能力；对 ProFL——从 Paillier 双服务器升为 CKKS 层次结构并用信誉加权做跨域鲁棒。**检索确认：主/备簇头双服务器 + 密态范数界验证 + 密文标量乘鲁棒加权 + 声誉更新的 HFL 组合未见报道。**

### 6.2 五个方案分别"解决了谁的什么问题"（一句话定位）

1. **AeroMask**：补 VLSFL 的三洞（TA 掌握密钥 / 选择性掉线 / 不防投毒）→ 轻量、可验证、可追责的 UAV 群标准 FL。
2. **SkyRelay**：把 CDKS-LSS 的 $O(N^2)$ P2P 份额换成双服务器中继 $O(N)$，同时保留阈值掉线容忍→ 弱链路 cross-silo 可用。
3. **HierDKG**：去掉 PrivHFL 的 KGC（三层 DKG），把云从"可见明文"降级为"仅可见密文"→ 层次 FL 的信任最小化。
4. **SwarmHandover**：第一个把"边缘节点高动态掉线"作为一等公民建模→ 托管环 + 一次性接管凭证 + proactive 刷新。
5. **VeriHier-Robust**：去掉 PPBR 的 DP 噪声，把范数界下沉到主/备簇头 2PC→ 保精度的 HFL 拜占庭鲁棒。

### 6.3 推荐研究路线（先做哪个）

**优先级 1：方案四 SwarmHandover。** 理由：UAV-as-Edge 是 UAV-FL 最具代表性的形态，而"边缘掉线"在现有 21 篇文献中**完全无人处理**（PrivHFL/SKHE/PPBR 都假设边缘稳定）——空白最清晰、故事最好讲、审稿人最容易认同 novelty。技术风险中等（托管环+PSS 均为成熟原语的组合）。

**优先级 2：方案五 VeriHier-Robust。** 理由：PPBR'26（TMC）刚定义了"HFL+拜占庭鲁棒"这个问题，其最大软肋是 CLDP 的精度损失；用"主/备簇头 2PC 做范数界"直接打这个点，对标明确、实验可比（PPBR 开源）。风险在于 Beaver 关联的实现工程量。

**优先级 3：方案三 HierDKG。** 理由：直接对标 PrivHFL'25（Computer Networks，开源），"去 KGC"是最容易被理解的结构性改进。可作为方案四/五的**密码底座**——方案四、五的阈值 CKKS 部分都复用方案三的 DKG 结构，因此**建议按 三→四→五 的技术顺序实现，按 四→五→三 的投稿顺序写作**。

**优先级 4/5：方案二 SkyRelay（对 CDKS-LSS）、方案一 AeroMask（对 VLSFL）。** 两者都是标准 FL 上的"点状改进"，novelty 成立但故事相对小；建议作为期刊扩展版或与其他工作组合（例如 AeroMask 的 Commit-then-Reveal 机制可以作为独立 lemma 并入方案四的签名链）。

### 6.5 遗留风险与诚实声明

- 方案五的 Beaver 三元组/平方关联在 5–20 个客户端的小集群上开销可接受，但**未做实测**，需在实验阶段验证（若超预算，可退化为方案一的"承诺+事后审计"轻量版）。
- 方案三的"层次密钥切换（KS）"在 CKKS 下会引入额外噪声与计算，需确认 KS 密钥可由 DKG 阶段分布式生成（标准 KS 密钥需要私钥持有者生成 $s^g$——这里 $s^g$ 是分布式持有的，需专门的**分布式 KS 密钥生成协议**；这是本方案理论上的一个待补点，建议写作时用"阈值友好的密钥切换"章节明确处理，或直接采用"统一全局公钥 + 域份额分离"的简化变体）。
- 方案一、五的"追责/信誉"机制依赖 UAV 的注册身份——在完全匿名场景（cross-device 海量手机）不适用，需在威胁模型中明确限定为"注册设备场景"（UAV/IoT 天然满足）。
