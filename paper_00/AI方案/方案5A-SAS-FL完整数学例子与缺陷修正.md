## 0. 先回答你的两个疑问

### 疑问一：CDKS-LSS 每一轮都要秘密共享吗？

**是的，每一轮都要，而且是 $O(N)$ 次点对点传输。**

CDKS-LSS（P9）的一轮里，第 4–5 步是这样的（原文 Algorithm 1/2）：

```
第4步  客户端 P_i 计算部分解密值   μ_i = c_{i,1} · s_i
第5步  P_i 采样 t−1 次多项式 f_i(X)，令 f_i(0) = μ_i
       对每个 j ≠ i，计算份额 f_i(α_j)，【点对点发送给 P_j】   ← 这就是秘密共享
第6步  P_j 收到 N−1 个份额后求和  μ̃_j = Σ_i f_i(α_j)
       把 μ̃_j 上传服务器
第7步  服务器取 t 个 μ̃_j，Lagrange 插值恢复 Σ_i μ_i，完成解密
```

注意 $\mu_i$ 是一个 $R_q$ 元素（$n=2^{14},\log_2q=318$ 时约 **0.62 MB**），不是几十字节。所以第 5 步中，$P_i$ 要向 $N-1$ 个对端各发一个 0.62 MB 的多项式。原文实测（$N=20$，MNIST，多环元素打包）：

| 方向 | 流量 |
|---|---|
| $P_i \to S$ | 10.410 MB |
| **$P_i \to P_j$（P2P）** | **98.895 MB** |
| $P_i \leftarrow S$ | 0.437 MB |
| **$P_i \leftarrow P_j$（P2P）** | **98.895 MB** |
| 每方每轮总发送 | **109.305 MB** |

**而且这是每一轮都要付的**。更糟的是 P2P 要求客户端之间有直连链路——跨机构联盟和地面 IoT 通常根本没有这种链路。

### 疑问二：5.A 是怎么解决的？

**核心是一个代数观察：$\mu_i = c_{i,1}\cdot s_i$ 对 $s_i$ 是线性的。**

CDKS-LSS 每轮把 $\mu_i$ 秘密共享，是因为它把"$\mu_i$ 需要被隐藏"和"$\mu_i$ 每轮都在变"这两件事绑在了一起处理。但 $\mu_i$ 的变化**全部来自 $c_{i,1}$**，而 $s_i$ 是**固定不变的**。于是：

$$\underbrace{\mu_i^{(r)} = c_{i,1}^{(r)}\cdot s_i}_{\text{每轮变化}} \quad\Longrightarrow\quad \text{把 } s_i \text{ 拆开共享，} \mu_i^{(r)} \text{ 由份额持有者每轮【本地】算}$$

具体地，setup 期一次性把 $s_i$ 加性拆成 $N$ 份：

$$s_i = \sum_{j=1}^{N} s_{i,j}, \qquad \text{客户端 } j \text{ 持有 } s_{i,j}$$

之后**任何一轮**，客户端 $j$ 都能本地算出"自己那一份的部分解密"：

$$D_j^{(S)} = c_{1}^{(r)}\cdot \underbrace{\sum_{i\in S} s_{i,j}}_{\bar s_j^{(S)},\ \text{本地列和}}$$

服务器把 $N$ 个 $D_j$ 加起来，就得到完整的部分解密——**不需要任何客户端之间通信**。

成本转移的账：

| | CDKS-LSS（P9） | SAS-FL |
|---|---|---|
| setup 一次性 | Exceptional Sequence 协商 | $N(N-1)/2$ 个 **32 字节**种子 ≈ **6 KB**（$N=20$） |
| **每轮 P2P** | $N(N-1)$ 个**环元素** ≈ **98.9 MB** | **0** |
| 每轮上行 | $N+1$ 个环元素 ≈ **109.3 MB** | **2** 个环元素 ≈ **1.3 MB** |
| 每轮本地计算 | 1 次多项式乘 | $|S|$ 次 PRG 展开 + 环加 + 1 次多项式乘 |

**"每轮 0.62 MB × $N$ 次网络传输" 换成 "一次性 32 字节 × $N$ 次 + 每轮 $N$ 次本地运算"**，改善 $(N+1)/2 = 10.5\times$，且 P2P 归零。这就是 5.A 效率优势的来源。

> 关键在**传输的单位**：CDKS-LSS 每轮传的是环元素（0.62 MB 量级），SAS-FL 只在 setup 传种子（32 字节），两者差了 **5 个数量级**。

## 1. 玩具参数

为了让每一步都能手算复核，用极小的参数。**结构完全同真实方案，只是数字小。**

| 参数 | 玩具值 | 真实值（P9 同款） |
|---|---|---|
| 环 | $R_q=\mathbb Z_q[X]/(X^2+1)$ | $\mathbb Z_q[X]/(X^{2^{14}}+1)$ |
| 多项式次数 $n$ | 2 | $2^{14}$ |
| 模数 $q$ | 1019（$1019\equiv3\bmod 4$ ⇒ $X^2+1$ 不可约 ⇒ $R_q$ 是域） | $\log_2q=318$ |
| 客户端数 $N$ | 3 | 20 |
| 明文定点标度 $Q$ | 60 | $2^{40}$ |
| 单个环元素大小 | 8 字节 | **0.62 MB** |

**记号**：环元素 $(c_0,c_1)$ 表示 $c_0+c_1X$，乘法用 $X^2=-1$，即
$$(x_0,x_1)\cdot(y_0,y_1) = (x_0y_0-x_1y_1,\ x_0y_1+x_1y_0)$$
显示时取**有符号代表元**（$c>q/2$ 则减去 $q$），例如 $1000 \to -19$。

**公共参数（CRS）**：

$$a = (7,3),\qquad v^{1}=(5,2),\qquad u^{1}=v^{1}\cdot a=(5\cdot7-2\cdot3,\ 5\cdot3+2\cdot7)=(29,29)$$

$u^1$ 是**公开**的，且**与客户端 $i$ 无关**——这是"只上传一个分量"的前提。

**各客户端的秘密与明文**：

| | $s_i$（私钥） | $e_i$（密钥噪声） | $b_i=-a s_i+e_i$（公钥，公开） |
|---|---|---|---|
| C1 | $(2,5)$ | $(1,1)$ | $(2,-40)$ |
| C2 | $(4,1)$ | $(2,-1)$ | $(-23,-20)$ |
| C3 | $(1,3)$ | $(-1,2)$ | $(1,-22)$ |

本地增量 $\Delta_i$（浮点，已定点）、样本数 $d_i$、加权后的明文 $m_i=\lfloor Q\alpha_i\Delta_i\rceil$，其中 $\alpha_i=d_i/D$，$D=\sum d_i=12$：

| | $\Delta_i$ | $d_i$ | $\alpha_i$ | $m_i=\lfloor 60\cdot\alpha_i\cdot\Delta_i\rceil$ |
|---|---|---|---|---|
| C1 | $(3,-2)$ | 4 | 4/12 | $(60,-40)$ |
| C2 | $(1,5)$ | 6 | 6/12 | $(30,150)$ |
| C3 | $(-2,1)$ | 2 | 2/12 | $(-20,10)$ |

$$\sum_i m_i = (70,120)\ \Rightarrow\ /Q=(1.1667,\ 2.0000)$$
$$\text{真值}\ \sum_i\alpha_i\Delta_i=\left(\tfrac{4\cdot3+6\cdot1+2\cdot(-2)}{12},\ \tfrac{4\cdot(-2)+6\cdot5+2\cdot1}{12}\right)=(1.1667,\ 2.0000)\quad\checkmark$$

**加权在明文域完成**（客户端本地乘 $\alpha_i$ 再加密），所以服务器只需做同态加法 ⇒ **零乘法深度**。这是 §3.5 的约束。

## 2. Setup：加性预共享（一次性）

### 2.1 成对种子

任意两方 $i<j$ 通过一次 DH 协商出 32 字节种子 $\sigma_{ij}$，经 PRG 展开成环元素（**通信只传 $\sigma$，不传环元素**）：

$$\text{PRG}(\sigma_{12})=(11,4),\quad \text{PRG}(\sigma_{13})=(-3,7),\quad \text{PRG}(\sigma_{23})=(9,-2)$$

### 2.2 份额构造

$$s_{i,j}=\begin{cases}\text{PRG}(\sigma_{ij}) & i<j\\[2pt] s_i-\sum_{k>i}\text{PRG}(\sigma_{ik})+\sum_{k<i}\text{PRG}(\sigma_{ki}) & i=j\\[2pt] -\text{PRG}(\sigma_{ji}) & i>j\end{cases}$$

对角元是"余量"，使行和恰好等于 $s_i$。以 C1 的对角元为例：

$$s_{1,1}=s_1-\text{PRG}(\sigma_{12})-\text{PRG}(\sigma_{13})=(2,5)-(11,4)-(-3,7)=(-6,-6)$$

### 2.3 份额矩阵（行 = 私钥拆分，列 = 持有者）

| | 持有者 C1 | 持有者 C2 | 持有者 C3 | **行和** |
|---|---|---|---|---|
| **C1** | $(-6,-6)$ | $(11,4)$ | $(-3,7)$ | $(2,5)=s_1$ ✓ |
| **C2** | $(-11,-4)$ | $(6,7)$ | $(9,-2)$ | $(4,1)=s_2$ ✓ |
| **C3** | $(3,-7)$ | $(-9,2)$ | $(7,8)$ | $(1,3)=s_3$ ✓ |

**列和**（客户端 $j$ 本地持有整列，不需通信）：

$$\bar s_1=(-14,-17),\quad \bar s_2=(8,13),\quad \bar s_3=(13,13)$$
$$\sum_j \bar s_j=(7,9)=\sum_i s_i \quad\checkmark$$

> **这一列和就是"预共享"的全部价值**：$\sum_j\bar s_j$ 恒等于 $\sum_i s_i$，且每个 $\bar s_j$ 只由客户端 $j$ 本地持有。任何轮的部分解密都能拆成 $N$ 份本地计算。

### 2.4 每轮成对掩码

每轮用**新鲜的** DH 派生 $\sigma^r_{jk}$（与长期种子不同，见第 7.2 节），$G_{jk}=\text{PRG}(\text{'mask'}\|\sigma^r_{jk})$：

$$G_{12}=(31,-6),\quad G_{13}=(14,19),\quad G_{23}=(-8,25)$$

客户端 $j$ 的掩码净值 $P_j=\sum_{k>j}G_{jk}-\sum_{k<j}G_{kj}$：

$$P_1=(45,13),\quad P_2=(-39,31),\quad P_3=(-6,-44),\qquad \sum_j P_j=(0,0)\ \checkmark$$

**掩码层的全部要求就是 $\sum_jP_j=0$**——它在求和时精确抵消，不引入任何噪声。

## 3. 第 1 轮完整闭环（全员在线）

### 步骤 1：本地训练 + 明文预缩放 + 定点化

见 §1 的表，得 $m_1=(60,-40),\ m_2=(30,150),\ m_3=(-20,10)$。

### 步骤 2：加密，只上传一个分量

$$\boxed{\;c_{i,0}^{r} = -\,u^{r}\cdot s_i \;+\; m_i^{r} \;+\; e_{i,0}^{r}\pmod q\;}$$

> ⚠️ 这里用的是**修正后**的加密式。原报告写的是 $c_{i,0}=v^rb_i+m_i+e_{i,0}$（带公钥 $b_i$），**那个式子有致命漏洞**，见第 7.1 节。

取 $e_{1,0}=(1,0),\ e_{2,0}=(0,1),\ e_{3,0}=(-1,0)$：

| | $-u^1\cdot s_i$ | $c_{i,0}^{1}$（上传） |
|---|---|---|
| C1 | $(87,-203)$ | $(148,-243)$ |
| C2 | $(-87,-145)$ | $(-57,6)$ |
| C3 | $(58,-116)$ | $(37,-106)$ |

$c_{i,1}^r=u^r$ 对所有 $i$ 相同且公开 ⇒ **不上传**。

### 步骤 3：服务器广播存活集

$S=\{1,2,3\}$，**只有 3 bit**。所有客户端独立验证自己是否在其中（可验证性由 5.B 提供）。

### 步骤 4：客户端计算部分解密贡献（核心创新）

$$\bar s_j^{(S)}=\sum_{i\in S}s_{i,j},\qquad K_j=u^{1}\cdot\bar s_j^{(S)},\qquad D_j^{(S)}=K_j+P_j$$

| $j$ | $\bar s_j^{(S)}$ | $K_j=u^1\bar s_j^{(S)}$ | $P_j$ | $D_j$（上传） |
|---|---|---|---|---|
| C1 | $(-14,-17)$ | $(87,120)$ | $(45,13)$ | $(132,133)$ |
| C2 | $(8,13)$ | $(-145,-410)$ | $(-39,31)$ | $(-184,-379)$ |
| C3 | $(13,13)$ | $(0,-265)$ | $(-6,-44)$ | $(-6,-309)$ |

$$\sum_j K_j=(-58,464),\qquad \sum_j D_j=(-58,464)\quad\checkmark\ \text{掩码精确抵消}$$
$$u^{1}\cdot s^{(S)}=(29,29)\cdot(7,9)=(29\cdot7-29\cdot9,\ 29\cdot9+29\cdot7)=(-58,464)\quad\checkmark$$

**计算量**：$|S|$ 次 PRG 展开 + $|S|$ 次环加法 + **1 次环乘法**（$u^1$ 全局共享，可预计算）。$u^1\bar s_j^{(S)}$ 是全场唯一的乘法，且 $u^1$ 是常数 ⇒ 服务器侧**零多项式乘法**。

### 步骤 5：服务器聚合（纯加法，零深度）

$$c_0^{(S)}=\sum_{i\in S}c_{i,0}^{r}=(128,-343)$$
$$M^{(S)}=c_0^{(S)}+\sum_{j=1}^{N}D_j^{(S)}=(128,-343)+(-58,464)=(70,121)$$

### 步骤 6：闭环公式推导（定理 5.A.1）

$$\begin{aligned}
M^{(S)}&=\sum_{i\in S}\big(-u s_i+m_i+e_{i,0}\big)+u\sum_{j}\bar s_j^{(S)}+ \underbrace{\sum_jP_j}_{=0}\\[4pt]
&=-u\underbrace{\sum_{i\in S}s_i}_{=\,s^{(S)}}+\sum_{i\in S}m_i+\sum_{i\in S}e_{i,0}+u\,s^{(S)}\\[4pt]
&=\boxed{\ \sum_{i\in S}m_i+\sum_{i\in S}e_{i,0}\ }\qquad(\text{两个 }u s^{(S)}\text{ 精确抵消})
\end{aligned}$$

数值校验：

| 量 | 值 |
|---|---|
| $\sum_i m_i$（信号） | $(70,120)$ |
| $\sum_i e_{i,0}$（噪声，$\|\cdot\|_\infty=1$） | $(0,1)$ |
| 理论 $M$ | $(70,121)$ |
| **实算 $M^{(S)}$** | $(70,121)$ ✓ **完全一致** |

解码：

$$\text{Decode}(M)/Q=(70/60,\ 121/60)=(1.1667,\ 2.0167)$$
$$\text{真值}\ \sum\alpha_i\Delta_i=(1.1667,\ 2.0000),\qquad \text{误差}=(+0.0000,\ +0.0167)$$

**正确性判据**：$\|\text{信号}\|_\infty+\|\text{噪声}\|_\infty=120+1=121 \ll q/2=509$ ✓

> 玩具参数下 $Q=60$ 太小，误差 $0.0167$ 看着显眼；真实 CKKS 中 $Q=2^{40}$，同样的相对噪声变成 $\sim2^{-40}$，可忽略。
>
> **修正后的一个额外好处**：噪声只剩 $\sum e_{i,0}$，**不含** $v\sum e_i$（密钥噪声）。因为 $us^{(S)}$ 项是被 $D_j$ 精确抵消的，不是靠 $b_i=-as_i+e_i$ 抵消的。原设计的噪声是 $v\sum e_i+\sum e_{i,0}$，多一项 ⇒ 修正版噪声预算更宽松。

## 4. 掉线场景

### 4.1 场景 A：C3 上传密文后、部分解密前失联

**SAS-FL 的处置：子集重选，两个集合同步收缩。**

服务器手里有全部 $c_{i,0}$，本地一次减法即可：

$$c_0^{(S')}=c_0^{(S)}-c_{3,0}=(128,-343)-(37,-106)=(91,-237)$$

（校验：直接按 $S'=\{1,2\}$ 求和也得 $(91,-237)$ ✓）

幸存者按 $S'$ 重算列和（**每人少了 $s_{3,j}$ 这一项**）：

| $j$ | $\bar s_j^{(S)}$（原） | $\bar s_j^{(S')}$（新） | $D_j^{(S')}$ |
|---|---|---|---|
| C1 | $(-14,-17)$ | $(-17,-10)$ | $(-158,249)$ |
| C2 | $(8,13)$ | $(17,11)$ | $(135,-176)$ |
| C3 | $(13,13)$ | $(6,5)$ | $(23,275)$ |

$$M^{(S')}=(91,-237)+(-67,348)=(91,111)$$

理论值 $\sum_{i\in S'}m_i+\sum_{i\in S'}e_{i,0}=(60+30,\ -40+150)+(1,1)=(91,111)$ ✓ **一致，无任何 C3 残留**

解码 $(91/60,111/60)=(1.5167,1.8500)$，真值 $\alpha_1\Delta_1+\alpha_2\Delta_2=(1.5,1.8333)$。

**代价**：1 次额外广播（$N$ bit）+ $|A_2|$ 次 0.62 MB 重传。**关键是无静默污染**：$c_0^{(S)}$ 与 $\bar s_j^{(S)}$ 严格对应同一个 $S$。

### 4.2 场景 B：S 已定、$c_0^{(S)}$ 已含 C3，但 C3 未上传 $D_3$

这是第二阶段掉线。**原报告的"创新点 4"给出的解法是错的**（第 7.2 节），正确解法仍是**子集重选**：

$$S''=S\setminus\{3\},\qquad c_0^{(S'')}=c_0^{(S)}-c_{3,0}$$

幸存者按 $S''$ 重算 $D_j$ 并**重传**（不需要重新加密，因为 $c_{i,0}$ 服务器手里都有）。结果与场景 A **逐比特相同**：$M^{(S'')}=(91,111)$ ✓

## 5. 威胁模型逐条演示

### 5.1 实体与信任假设

| 实体 | 假设 | 能力 | **不能做到** |
|---|---|---|---|
| 云服务器 $S$ | **恶意（active）** | 丢弃任意密文；谎报 $S$；篡改 $M^{(S)}$；重放旧轮；与 $\le N-2$ 客户端共谋 | 还原任何诚实方的 $m_i$ 或 $s_i$；在 5.B 验证层下**不可察觉地**篡改结果 |
| 客户端 $C_i$ | 半诚实，可共谋 $\kappa\le N-2$ | 观察公共信道全部内容；互换所持份额 $\{s_{i,j}\}_{j\in C}$；与服务器共谋 | 分离诚实方 $h$ 的 $s_h$；还原 $m_h$ |
| 掉线客户端 | 任意比例、任意时刻 | — | 第一阶段掉线：剔除，无副作用；第二阶段掉线：子集重选 |
| 信道 | **公共，不假设保密** | 全部消息可窃听 | 需签名做客户端↔服务器认证 |
| **不假设** | — | **无 TEE、无 KDC、无 TA、无常驻可信机构、无客户端间直连链路** | — |

安全归约基础：**RLWE** + **PRG 安全性** + **DDH**（成对种子） + **EUF-CMA 签名**。

### 5.2 G1 个体隐私：服务器 + C1 共谋，能否还原 $m_2$？

敌手 $\mathcal A$ 的完整视图：$a,\ v^1,\ u^1,\ S,\ \{c_{i,0}\},\ \{D_j\},\ M^{(S)}$，加上 **C1 的全部秘密**（私钥 $s_1=(2,5)$、列份额 $s_{(i,1)}=\{(-6,-6),(-11,-4),(3,-7)\}$）。

要还原 $m_2$ 必须知道 $u^1\cdot s_2$，即必须知道 $s_2$：

$$s_2=\underbrace{s_{(2,1)}}_{\mathcal A\ \text{知}\ =(-11,-4)}+\underbrace{s_{(2,2)}}_{\text{仅 C2 有}}+\underbrace{s_{(2,3)}}_{\text{仅 C3 有}}$$

$$s_2-s_{(2,1)}=(4,1)-(-11,-4)=(15,5)\quad\text{对 }\mathcal A\text{ 而言计算上均匀}$$

（因为 $\sigma_{2j}$ 由 DDH 保证不可区分于随机 ⇒ $\text{PRG}(\sigma_{2j})$ 均匀 ⇒ 对角余量均匀）

**而且修正后系统里没有公钥 $b_2$ 可供相减** ⇒ 第 7.1 节那类攻击根本不存在。

$$\Rightarrow\ \mathcal A\ \text{无法还原}\ m_2\quad\checkmark$$

### 5.3 共谋界：$\kappa\le N-1$

$\mathcal A$ 控制 C1+C2（$\kappa=2=N-1$）时，仍缺：

$$s_{(2,3)}=(9,-2),\qquad s_{(1,3)}=(-3,7)\qquad\text{（只有 C3 持有）}$$

⇒ **SAS-FL 抗 $\kappa\le N-1$ 共谋**。唯一未覆盖的是全员共谋，而那时聚合结果本就是协议输出。

> 对比 P9 CDKS-LSS Theorem 7：只保证"服务器 + $<t$ 个参与方"，且 $t\le N$。SAS-FL 在共谋维度**更强**。
>
> **但这是有代价的**（诚实声明）：P9 的 LSS 层是**信息论**安全，SAS-FL 依赖 DDH+PRG 的**计算**安全。见 5.5。

### 5.4 G1 补充：成对掩码隐藏 $K_j$

服务器看到 $D_1=K_1+P_1=(132,133)$，其中 $K_1=(87,120)$、$P_1=(45,13)$。$P_1$ 是 PRG 输出 ⇒ 计算上均匀 ⇒ **$D_1$ 不泄露 $K_1$**。

**关键性质**：$\sum_jP_j=0$ ⇒ $M$ 不含任何掩码残留 ⇒ **掩码不占噪声预算**。

### 5.5 成对掩码 vs noise flooding（一个明确的取舍）

| | 成对掩码 $P_j$ | noise flooding $e_j^*$ |
|---|---|---|
| 安全强度 | **计算**安全（DDH + PRG） | **统计**安全 |
| 噪声预算 | **不占用**（$\sum P_j=0$ 精确抵消） | 占用：$\text{Var}(\phi)\ge2^{2\lambda}\cdot\text{Var}(K_j)$ |
| 对 $q$ 的要求 | 无额外要求 | $\log q\gtrsim2\lambda+\log N+\log\sigma$ |
| 抗量子 | 否（DDH） | 是 |

修正版用掩码即可，因此**原报告的"局限 1"（flooding 迫使模数变大）可以撤销**。但这是取舍不是免费午餐：若坚持统计安全或抗量子，仍需 flooding。

### 5.6 跨轮隐私：$v^r$ 必须每轮新鲜

$$c_{i,0}^{r}-c_{i,0}^{r'}=-(u^{r}-u^{r'})s_i+(m_i^{r}-m_i^{r'})+\text{噪声}$$

$u^r$ 每轮变 ⇒ 敌手须解 RLWE 才能分离 $m_i$。**若 $u$ 固定，差分直接暴露 $m_i^r-m_i^{r'}$**（差分攻击）。所以 PRPG 的轮计数器不能省。

### 5.7 G2/G3 可验证性

SAS-FL 本身提供**参与集可验证性的基础**（服务器必须广播 $S$、$c_0^{(S)}$、$\{D_j\}$、$M^{(S)}$，任何客户端可本地重算 $c_0^{(S)}+\sum_jD_j$ 并比对）。完整的抗拜占庭验证层在 **5.B VRSA-FL**。

## 7. ★ 构造例子时发现的两个缺陷与修正

> 这一节是本文档最重要的部分。两处都是我**为了把数字算通才发现**的，原报告 §5.A 里是错的。

### 7.1 缺陷一（致命）：创新点 1 的"公开信标 + 公钥加密"破坏 CPA 安全

**原报告的加密式**（§5.A.5 步骤 2）：

$$c_{i,0}^{r}=v^{r}\cdot b_i+m_i^{r}+e_{i,0}^{r}$$

**攻击**：公钥 $b_i$ 是**公开**的，$v^r$ 被设计成**公开信标**。于是任何窃听者（包括云服务器）做一次减法：

$$c_{i,0}^{r}-v^{r}\cdot b_i=m_i^{r}+e_{i,0}^{r}$$

玩具数值验证（PART 2，全部逐比特相符）：

| | $c_{i,0}$ | $-\ v^1b_i$ | 攻击者得到 | 真值 $m_i+e_{i,0}$ | 还原的 $m_i$ |
|---|---|---|---|---|---|
| C1 | $(151,-236)$ | | $(61,-40)$ | $(61,-40)$ ✓ | $(60,-40)$ = 真值 |
| C2 | $(-45,5)$ | | $(30,151)$ | $(30,151)$ ✓ | $(30,150)$ = 真值 |
| C3 | $(28,-98)$ | | $(-21,10)$ | $(-21,10)$ ✓ | $(-20,10)$ = 真值 |

**三个客户端的明文更新全部被直接还原。方案在隐私上完全失效。**

**为什么会错**：标准 CKKS 的安全性**依赖 $v$ 是秘密随机数**：

$$c_0=vb+\Delta m+e_0,\qquad c_1=va+e_1$$

服务器想算 $vb$，必须先从 $c_1$ 里解出 $v$ ⇒ 这是 RLWE 难题 ⇒ 安全。**把 $v$ 改成公开信标，$vb$ 就人人可算，CPA 安全性当场崩塌。**

**为什么 ESAFL（P5）没这个问题**：ESAFL 的密文是

$$c_i^{t}=a_t\cdot s_i+\tilde p\,e_i^{t}+m_i^{t}$$

它**根本没有公钥 $b_i$**，直接用秘密 $s_i$ 加密。$a_t$ 公开也无妨，因为 $s_i$ 秘密。

**原报告的错误在哪一步**：创新点 1 写"机制取自 P5 ESAFL 的 Eq.6，但用于多密钥 CKKS 而非单密钥聚合体"。**恰恰是这个移植搬错了**——多密钥 CKKS 有公开 $b_i$，ESAFL 没有。把"公开信标"移植到"有公钥的体制"上，就漏了。

**修正**：取消公钥，改用秘密密钥直接加密（与 ESAFL 同构，但 $s_i$ 各自独立、不共享解密密钥）：

$$\boxed{\;c_{i,0}^{r}=-\,u^{r}\cdot s_i+m_i^{r}+e_{i,0}^{r},\qquad u^{r}=v^{r}a\ \text{公开}\;}$$

系统中**不存在公钥**，$s_i$ 永不公开 ⇒ 无人能算 $u^rs_i$ ⇒ 安全性回到 RLWE。

**顺带的好处**：$us^{(S)}$ 项由 $D_j$ 精确抵消，不再经 $b_i=-as_i+e_i$ 抵消，所以密钥噪声 $e_i$ **不进入** $M$：

| | 原设计噪声 | 修正后噪声 |
|---|---|---|
| $M$ 中的噪声项 | $v\sum e_i+\sum e_{i,0}$ | $\sum e_{i,0}$ |

少一项 ⇒ 噪声预算更宽松。玩具例子里体现为：噪声从 $\|(6,15)\|_\infty=15$ 降到 $\|(0,1)\|_\infty=1$，解码误差从 $(0.1,0.25)$ 降到 $(0,0.0167)$。

### 7.2 缺陷二：创新点 4 的"Shamir 自掩码层抗第二阶段掉线"不成立

**原报告的主张**（创新点 4）：叠加 SecAgg 的自掩码层

$$D_j^{(S)}=u^ra\bar s_j^{(S)}+\underbrace{\text{PRG}(b_j)}_{\text{Shamir}(t,N)\text{分片}}+\underbrace{\text{成对零和掩码}}_{\sum_j=0}+e_j^*$$

则"第二阶段只需 $t$ 个客户端在线"。

**证伪**（PART 5a，玩具数值）：设 $D_j=K_j+Z_j+P_j$，C3 未上传 $D_3$，幸存者 $\{C_1,C_2\}$ 上传了 $D_1,D_2$。

Shamir 重构 $Z_3=(-11,14)$ 本身没问题。服务器按原报告步骤 5 计算：

$$M_w=c_0^{(S)}+\sum_{j\in\{1,2\}}D_j-\underbrace{(Z_1+Z_2)}_{\text{幸存者自掩码}}-\underbrace{(P_1+P_2)}_{\text{残余成对掩码}}=(70,386)$$

与全员在线的基线 $M_{\text{full}}=(70,121)$ 相比：

$$M_w-M_{\text{full}}=(0,265),\qquad -K_3=-u^1\bar s_3^{(S)}=(0,265)$$

$$\boxed{\;M_w-M_{\text{full}}=-K_3\quad\text{✔ 精确确认}\;}$$

**所有掩码（$Z$ 与 $P$）都被正确处理之后，差值恰好是 $-K_3$。**

**原因**：$K_3=u^1\bar s_3^{(S)}$ 含 $s_{(3,3)}$，**只有 C3 持有**。Shamir 分片的是 $Z_3$（自掩码），**不是 $s_{(3,3)}$** ⇒ 重构 $Z_3$ 对补出 $K_3$ 毫无帮助。而 $\|K_3\|_\infty=265\approx q$ 量级，与 CDKS-LSS 的污染同级。

**为什么 SecAgg 可以、这里不行**（这是关键的概念差别）：

| | SecAgg（P1） | SAS-FL 第二阶段 |
|---|---|---|
| 掉线者 $v$ 缺的是什么 | 输入 $x_v$ | 核心项 $K_v=u\bar s_v^{(S)}$ |
| 缺了会怎样 | **正好**——$x_v$ 本就该被排除，$\sum_{u\in U_3}x_u$ 是正确的部分和 | **污染**——$c_0^{(S)}$ 已固定含 $v$ 的密文，$K_v$ 缺失 ⇒ $-us_v$ 项无法抵消 |
| 掩码的作用 | 抵消掩码，使部分和干净 | 抵消掩码，但**补不出 $K_v$** |

**二者不同构。原报告说"与 P1 SecAgg 的抗掉线机制完全同构"是错的。**

**正解**：子集重选（§4.2）。$S''=S\setminus\{v\}$，服务器本地 $c_0^{(S'')}=c_0^{(S)}-c_{v,0}$，幸存者重算 $D_j^{(S'')}$ 并重传。**原报告步骤 5 里"重广播 $S_2\subsetneq S_1$ 回到步骤 4"的直觉是对的**，只是它同时还保留了这个错误的掩码层，两者并存造成了自相矛盾。

### 7.3 附带消除：种子复用隐患

若真按创新点 4 实现，掉线恢复需要重构掉线者 C3 的**本轮 DH 私钥 $x_3$**（用于重算成对掩码）。而如果长期密钥份额与每轮掩码**共用同一个 $\sigma_{ij}$**（原报告创新点 3 与创新点 4 的写法确实是共用的），那么交出 $x_3$ ⇒ 服务器可重算所有 $\sigma_{3j}$ ⇒ 得到整行 $s_{(3,\cdot)}$：

$$\sum_j s_{(3,j)}=(1,3)=s_3\quad\text{✘ C3 的长期私钥泄露}$$

进而 $m_3\approx c_{3,0}+u^1s_3$ 可还原，且是**长期**破坏（$s_3$ 泄露 ⇒ C3 全部历史轮次可解密，无前向安全）。

**采用子集重选后，永不需要恢复任何掉线者的种子或私钥 ⇒ 该隐患被根除，不是缓解。**

> 这说明创新点 4 不仅主张错误，还额外引入了一个严重漏洞。**删除它反而更安全、更简单。**

### 8.2 不受影响的核心贡献

修正**不动摇** 5.A 的三个主要卖点：

1. **P2P 归零**（$\mu_i$ 对 $s_i$ 线性 ⇒ setup 期一次性加性预共享）—— 这是效率优势的来源，完全不受影响
2. **子集可选聚合**（份额按 $(i,j)$ 索引，任意 $S$ 可事后精确聚合）—— 不受影响，且修正后**更干净**（噪声项少一项）
3. **原子性缺口被代数排除**（$c_0^{(S)}$ 与 $\bar s_j^{(S)}$ 严格同集合）—— 不受影响

通信量对照（$N=20$）也**完全不变**：上行 2 个环元素 = 1.30 MB，P2P = 0，改善 $10.5\times$。

### 8.3 修正后新出现的局限（诚实声明）

1. **第二阶段需全员在线，否则付出 $O(N)$ 重传代价**。原报告声称"$\ge t$ 即可"是错的。实测掉线率 15–18%（§4.2）意味着重选会被频繁触发。缓解：把两阶段合并为一次上传（客户端在上传 $c_{i,0}$ 时**同时**上传对**当前预期 $S$** 的 $D_j$），但这要求 $S$ 可预测——是后续工作。
2. **无公钥 ⇒ 无法做密文域乘法**。$b_i$ 取消后，体制退化为纯加性 HE（与 ESAFL 同级）。原报告的"乘法深度 0"本就成立，所以这不是退步，但**堵死了未来在同一体制上加乘法的路**。若需乘法，须回到标准多密钥 CKKS 并接受 $c_{i,1}$ 上传。
3. **DDH 依赖**。成对种子与成对掩码都依赖 DDH ⇒ **不抗量子**。原报告的 flooding 是统计安全（抗量子），删掉它损失了这一点。若目标是后量子安全，须保留 flooding 并把成对种子换成基于格的 NIKE。
